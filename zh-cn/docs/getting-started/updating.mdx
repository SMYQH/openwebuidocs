# 更新 Open WebUI {#updating-open-webui}

**保持最新，同时不丢失你的数据。**

你的数据（聊天、用户、设置、上传文件）存放在 Docker 卷或本地数据库中，而不在容器内部。更新 Open WebUI，本质上就是把容器镜像替换成更新版本；数据会保持原样。

---

## 选择更新策略 {#choose-your-update-strategy}

在执行任何命令前，先决定你想如何跟踪版本发布。最佳方案取决于你如何使用 Open WebUI。

| 场景 | 推荐做法 |
|---|---|
| **个人 / homelab** | 使用 `:main` 标签，需要最新版本时手动拉取 |
| **共享 / 团队实例** | 固定特定版本（例如 `:vX.Y.Z`），并使用 [Diun](#diun) 接收更新通知 |
| **生产 / 关键系统** | 固定版本，升级前查看[发布说明](https://github.com/open-webui/open-webui/releases)，先在预发布环境测试 |
| **测试下一个发布版** | 在一个拥有自己卷的第二个实例上运行 `:dev` 预发布镜像，与你生产环境并行 |

无论你处于哪一行，都很值得在 `:dev` 上运行一个第二实例：它只需一个标签、一个卷和一个端口。它能让你在新版本到达用户之前就看到它，能告诉你你的插件和配置是否仍然可用，而它发现的问题也能在发布前得到修复，而不是发布后。

### `:main` 与固定版本 {#main-vs-pinned-versions}

`:main` 标签始终指向**最新构建**。它使用方便，但也可能在没有预告的情况下包含破坏性变更。

如果你更重视稳定性，请固定到具体的发行标签：

```
ghcr.io/open-webui/open-webui:vX.Y.Z
ghcr.io/open-webui/open-webui:vX.Y.Z-cuda
ghcr.io/open-webui/open-webui:vX.Y.Z-ollama
```

`-ollama` 镜像在构建镜像时安装 Ollama。内置的 Ollama 只在你拉取更新的 Open WebUI 镜像时才会变化，而固定的 `vX.Y.Z-ollama` 标签会保留构建时使用的 Ollama 版本。若要按自己的节奏更新 Ollama，请按 [Ollama 的 Docker 指南](https://docs.ollama.com/docker)把它作为独立容器运行。

你可以在 [GitHub releases 页面](https://github.com/open-webui/open-webui/releases) 查看所有可用标签。

## 更新前准备 {#before-you-update}

1. **备份数据**（见下方 [备份与恢复](#backup--restore)）。尤其在遇到包含数据库迁移的版本时更要如此，因为回滚通常不容易。
2. **查看 [发布说明](https://github.com/open-webui/open-webui/releases)**，确认是否有破坏性变更。
3. 更新后**清理浏览器缓存**（`Ctrl+F5` / `Cmd+Shift+R`），避免旧前端资源残留。

:::info 早期版本中的智能体聊天
在本次更新之前开始的智能体聊天中，发送第一条新消息时会开启新的智能体会话。智能体会以文本形式收到此前的聊天内容。
:::

:::info Tether 取代 Direct Connections
用户设置中的 Direct Connections、个人工具服务器和个人终端已移除。在 Tether 应用中添加的连接会将 URL 和密钥保存在你的电脑上。参见[自带模型与工具](/ecosystem/tether#bring-your-own-models-and-tools)。共享连接由管理员在 **Settings > Admin** 下添加。
:::

:::info 图像设置迁移到图像连接
引擎、模型、API URL、密钥、ComfyUI 工作流及 AUTOMATIC1111 的图像环境变量（如 `IMAGE_GENERATION_ENGINE`、`IMAGES_OPENAI_API_*`、`COMFYUI_*` 和 `IMAGE_EDIT_*` 等）仅在首次启动时读取。此次启动会将现有图像生成和编辑设置及这些变量迁移成名为 OpenAI、Gemini、ComfyUI 或 AUTOMATIC1111 的图像连接。独立的编辑后端会带有 ` (edit)` 后缀，迁移后的连接向所有用户开放。此后不再读取这些变量。若设置 `ENABLE_PERSISTENT_CONFIG=false`，则每次启动都会重新迁移。在 **Settings > Images**（管理员区域）管理连接。参见[图像生成和编辑](/features/chat-conversations/image-generation-and-editing)。`ENABLE_IMAGE_GENERATION`、`ENABLE_IMAGE_EDIT` 和 `ENABLE_IMAGE_PROMPT_GENERATION` 仍然有效。
:::

:::info v0.12.1 为 SCIM 用户添加登录记录
这个版本会运行一次数据库迁移，为每个缺少登录记录的账号补上一条——实际上就是通过 [SCIM](/features/authentication-access/auth/scim#integration-with-sso) 创建的账号。它只会改动数据。请先备份。新增的记录不包含可用的密码，因此这些用户仍然通过 SSO 登录。
:::

:::warning 正在运行多个副本？
请在同一时间更新每个实例。对于会改变数据库 schema 的发布版，不支持滚动更新：迁移会一次性把整个数据库向前推进，而仍在旧版本上的实例会继续按旧结构查询。请停止所有副本，让其中一个实例完成迁移，再把其余实例以新版本启动。

在除一个实例之外的所有实例上设置 `ENABLE_DB_MIGRATIONS=false` 只是决定**哪个**实例运行迁移，并不会让混合版本的集群变安全。完整流程参见[更新与迁移](/troubleshooting/multi-replica#updates-and-migrations)，周边配置参见[扩展指南](/getting-started/advanced-topics/scaling)。
:::

## 手动更新 {#manual-update}

<Tabs groupId="setup-method">
  <TabItem value="docker-run" label="Docker 容器" default>

```bash
# 1. Stop and remove the container (data in the volume is preserved)
docker rm -f open-webui

# 2. Pull the latest image (or replace :main with a pinned version)
docker pull ghcr.io/open-webui/open-webui:main

# 3. Recreate the container
docker run -d -p 3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  -e WEBUI_SECRET_KEY="your-secret-key" \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main
```

如需 NVIDIA GPU 支持，请在 `docker run` 命令中加入 `--gpus all`，并使用 `:cuda` 标签。请在第 2 步和第 3 步拉取与你正在运行的相同标签：由 `:cuda`、`:ollama` 或某个版本标签启动的容器，在拉取 `:main` 之后仍会启动旧版本。

  </TabItem>
  <TabItem value="docker-compose" label="Docker Compose">

```bash
docker compose pull
docker compose up -d
```

请确认你的 `docker-compose.yml` 包含 `WEBUI_SECRET_KEY`：

```yaml title="docker-compose.yml"
services:
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    ports:
      - "3000:8080"
    volumes:
      - open-webui:/app/backend/data
    extra_hosts:
      - host.docker.internal:host-gateway
    environment:
      - WEBUI_SECRET_KEY=your-secret-key
    restart: unless-stopped

volumes:
  open-webui:
```

  </TabItem>
  <TabItem value="python" label="Python（pip 安装）">

```bash
pip install -U open-webui
```

`-U` 标志会升级到最新版本。然后重启服务：

```bash
open-webui serve
```

  </TabItem>
</Tabs>

:::warning 设置 WEBUI_SECRET_KEY，避免每次更新都被登出
如果没有持久化的 `WEBUI_SECRET_KEY`，容器每次重建都会生成新密钥，导致所有会话失效。可通过 `openssl rand -hex 32` 生成，并在后续更新中持续复用。详情见[环境变量参考](/reference/env-configuration)。
:::

### 验证更新 {#verify-the-update}

更新后，请确认一切工作正常：

1. **在日志里检查版本：**
   ```bash
   docker logs open-webui 2>&1 | head -20
   ```
2. **打开界面：** 访问 [http://localhost:3000](http://localhost:3000)，应看到登录页。
3. **如果界面显示异常，** 清理浏览器缓存（`Ctrl+F5` / `Cmd+Shift+R`）。
4. **如果日志里看到迁移错误，** 请查看[发布说明](https://github.com/open-webui/open-webui/releases)中的已知问题，以及[连接错误](/troubleshooting/connection-error) 故障排查页面。
5. **如果更新后没有任何变化，** 请检查卷挂载在哪里。应把它挂载到 `/app/backend/data`，绝不要挂到 `/app/backend`。镜像把应用程序代码放在 `/app/backend`，因此挂到那里的卷或绑定挂载会覆盖新代码，容器运行的仍是挂载所包含的代码。要修复类似 `./backend:/app/backend` 的绑定挂载，请改成 `./backend/data:/app/backend/data`。如果你从未设置 `WEBUI_SECRET_KEY`，请先把 `./backend/.webui_secret_key` 中的值复制到该变量：生成的密钥保存在 `/app/backend/.webui_secret_key`，位于数据目录之外，因此移动之后 Open WebUI 会生成新的密钥，所有人都会被登出。

## 回滚 {#rolling-back}

如果更新引发问题，你可以通过固定旧版本标签回退到之前的版本。

<Tabs groupId="setup-method">
  <TabItem value="docker-run" label="Docker 容器" default>

```bash
docker rm -f open-webui
docker pull ghcr.io/open-webui/open-webui:v0.8.3
docker run -d -p 3000:8080 -v open-webui:/app/backend/data \
  --add-host=host.docker.internal:host-gateway \
  -e WEBUI_SECRET_KEY="your-secret-key" \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:v0.8.3
```

  </TabItem>
  <TabItem value="docker-compose" label="Docker Compose">

将 `docker-compose.yml` 中的镜像标签改为：

```yaml
image: ghcr.io/open-webui/open-webui:v0.8.3
```

然后执行：

```bash
docker compose pull
docker compose up -d
```

  </TabItem>
  <TabItem value="python" label="Python（pip 安装）">

```bash
pip install open-webui==0.8.3
open-webui serve
```

  </TabItem>
</Tabs>

:::caution 数据库迁移不可逆
如果你更新到的版本执行了数据库迁移，仅回滚容器**并不会**撤销迁移。旧版本可能无法兼容新数据库结构。在这种情况下，你需要恢复**更新前**创建的备份。针对数据库级恢复，请参见 [数据库迁移](/troubleshooting/manual-database-migration)。
:::

## 持续接收更新通知 {#stay-notified-about-updates}

与其手动反复检查，不如使用工具来监控新版本。下面按“最安全”到“最省心”的顺序列出几种选择。

:::tip 推荐
- **生产 / 关键系统：** Diun（只通知）+ 手动更新
- **托管环境：** WUD（可视化面板 + 手动触发）
- **Homelab / 个人使用：** Watchtower（全自动）
:::

| 功能 | Diun | WUD | Watchtower |
|---------|:---:|:---:|:---:|
| **自动更新容器** | ❌ | ❌（通过 UI 手动触发） | ✅ |
| **Web 界面** | ❌ | ✅ | ❌ |
| **通知** | ✅ | ✅ | ✅ |
| **Docker 29+** | ✅ | ✅ | ✅（fork 版本） |
| **资源占用** | 很低 | 中等 | 低 |

### Diun {#diun}

只负责通知。它会在有更新可用时提醒你（邮件、Slack、Discord、Telegram 等），但不会触碰你的容器。何时更新、如何更新，都由你决定。

```yaml title="docker-compose.yml"
services:
  diun:
    image: crazymax/diun:latest
    container_name: diun
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./data:/data
    environment:
      - TZ=America/New_York
      - LOG_LEVEL=info
      - DIUN_WATCH_WORKERS=10
      - DIUN_WATCH_SCHEDULE=0 */6 * * *  # Every 6 hours
      - DIUN_PROVIDERS_DOCKER=true
      - DIUN_NOTIF_MAIL_HOST=smtp.gmail.com
      - DIUN_NOTIF_MAIL_PORT=587
      - DIUN_NOTIF_MAIL_USERNAME=your-email@gmail.com
      - DIUN_NOTIF_MAIL_PASSWORD=your-app-password
      - DIUN_NOTIF_MAIL_FROM=your-email@gmail.com
      - DIUN_NOTIF_MAIL_TO=your-email@gmail.com
    restart: unless-stopped
```

完整配置与通知选项请查看 [Diun 文档](https://crazymax.dev/diun/)。

### What's Up Docker (WUD) {#whats-up-docker-wud}

用于监控容器更新并手动触发升级的 Web UI。安装方式见 [WUD 文档](https://getwud.github.io/wud/)。

### Watchtower {#watchtower}

全自动方案。它会拉取新镜像并自动重建容器，无需人工干预。

:::warning
原始的 `containrrr/watchtower` 已**不再维护**，且在 Docker 29+ 下会失效。请改用 [nicholas-fedor/watchtower](https://watchtower.nickfedor.com/) fork。
:::

:::warning
如果新版本包含破坏性变更或数据库迁移，自动更新可能直接破坏你的部署。生产环境启用自动更新前，请务必先查看发布说明，并始终做好备份。
:::

**一次性更新：**
```bash
docker run --rm \
  -v /var/run/docker.sock:/var/run/docker.sock \
  nickfedor/watchtower --run-once open-webui
```

**持续运行（每 6 小时检查一次）：**
```bash
docker run -d --name watchtower --restart unless-stopped \
  -v /var/run/docker.sock:/var/run/docker.sock \
  nickfedor/watchtower --interval 21600 open-webui
```

将 `WATCHTOWER_CLEANUP=true` 设为开启即可自动移除旧镜像。更多调度、通知和仅监控模式配置见 [Watchtower 文档](https://watchtower.nickfedor.com/)。

## 备份与恢复 {#backup--restore}

所有数据都保存在 `open-webui` Docker 卷中，包括：
- **数据库**：聊天、用户、设置、管理员配置
- **已上传文件**：文档、图片、知识库内容
- **生成内容**：图片生成结果、导出数据

### 备份 {#backup}

```bash
docker run --rm -v open-webui:/data -v $(pwd):/backup \
  alpine tar czf /backup/openwebui-$(date +%Y%m%d).tar.gz /data
```

请在**每次更新前**备份，并根据 Open WebUI 的使用频率，每天或每周定期备份。

### 恢复 {#restore}

:::caution
恢复命令会在解压前**删除卷中的所有内容**。请确认你恢复的是正确的备份文件。
:::

```bash
docker stop open-webui
docker run --rm -v open-webui:/data -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/openwebui-YYYYMMDD.tar.gz -C /"
docker start open-webui
```

请将 `YYYYMMDD` 替换为实际备份文件日期。

数据库级恢复请参见 [数据库迁移](/troubleshooting/manual-database-migration)。

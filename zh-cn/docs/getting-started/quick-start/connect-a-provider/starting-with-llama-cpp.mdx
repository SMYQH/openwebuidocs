## 概览 {#overview}

Open WebUI 可以简单灵活地连接并管理本地 Llama.cpp 服务器，以运行高效的量化语言模型。无论你是自行编译 Llama.cpp，还是使用预编译二进制，本指南都会带你完成以下内容：

- 配置 Llama.cpp 服务器
- 在本地加载大模型
- 与 Open WebUI 集成，获得顺滑界面体验

开始吧！

---

## 第 1 步：安装 Llama.cpp {#step-1-install-llamacpp}

要用 Llama.cpp 运行模型，首先需要在本地安装 Llama.cpp 服务器。

你可以：

- 📦 [下载预编译二进制](https://github.com/ggerganov/llama.cpp/releases)
- 🛠️ 或按照[官方构建说明](https://github.com/ggerganov/llama.cpp/blob/master/docs/build.md)从源码编译

安装后，请确认 `llama-server` 已加入系统路径，或记下其实际位置。

---

## 第 2 步：下载受支持的模型 {#step-2-download-a-supported-model}

你可以用 Llama.cpp 加载并运行多种 GGUF 格式的量化 LLM。其中一个很有代表性的例子，是由 UnslothAI 优化的 DeepSeek-R1 1.58-bit 模型。下载方式如下：

1. 打开 [Hugging Face 上的 Unsloth DeepSeek-R1 仓库](https://huggingface.co/unsloth/DeepSeek-R1-GGUF)
2. 下载 1.58-bit 量化版本——大约 131GB。

你也可以使用 Python 以编程方式下载：

```python

# pip install huggingface_hub hf_transfer

from huggingface_hub import snapshot_download

snapshot_download(
    repo_id = "unsloth/DeepSeek-R1-GGUF",
    local_dir = "DeepSeek-R1-GGUF",
    allow_patterns = ["*UD-IQ1_S*"],  # Download only 1.58-bit variant
)
```

这会把模型文件下载到类似下面的目录：
```
DeepSeek-R1-GGUF/
└── DeepSeek-R1-UD-IQ1_S/
    ├── DeepSeek-R1-UD-IQ1_S-00001-of-00003.gguf
    ├── DeepSeek-R1-UD-IQ1_S-00002-of-00003.gguf
    └── DeepSeek-R1-UD-IQ1_S-00003-of-00003.gguf
```

📍 请记下第一个 GGUF 文件的完整路径——第 3 步会用到。

---

## 第 3 步：使用 Llama.cpp 提供模型服务 {#step-3-serve-the-model-with-llamacpp}

使用 `llama-server` 启动模型服务。进入你的 llama.cpp 目录（例如 build/bin）后运行：

```bash
./llama-server \
  --model /your/full/path/to/DeepSeek-R1-UD-IQ1_S-00001-of-00003.gguf \
  --port 10000 \
  --ctx-size 1024 \
  --n-gpu-layers 40
```

🛠️ 可根据你的机器调整参数：

- --model：`.gguf` 模型文件路径
- --port：10000（或任意其他可用端口）
- --ctx-size：上下文的 token 数上限（内存允许时可调大）
- --n-gpu-layers：卸载到 GPU 的层数，用于提升性能

服务启动后，会在以下地址暴露一个本地**兼容 OpenAI 的 API**（聊天补全）：

```
http://127.0.0.1:10000
```

:::tip
Open WebUI 也支持实现了 [Open Responses](/getting-started/quick-start/connect-a-provider/starting-with-open-responses) 规范的提供商。
:::

## 第 4 步：把 Llama.cpp 连接到 Open WebUI {#step-4-connect-llamacpp-to-open-webui}

要在 Open WebUI 中直接控制并调用本地运行的模型：

1. 在浏览器中打开 Open WebUI
2. 进入 **Settings → Connections → OpenAI**（管理员区域）。
3. 点击 ➕ **Add Connection**。
4. 填写以下内容：
   - **URL**：`http://127.0.0.1:10000/v1`
     （如果 WebUI 运行在 Docker 中，请使用 `http://host.docker.internal:10000/v1`。**注意末尾一定要有 `/v1`！**）
   - **Auth**：无需密钥的服务器选 **None**。选择 **Bearer** 且密钥留空时，Open WebUI 不会发送 `Authorization` 请求头，与 **None** 相同
   - **Provider**：展开 **Advanced**，从 **Provider** 下拉列表中选择 `llama.cpp`。这样就能在模型选择器中看到加载状态指示，管理员也能使用 **Eject** 按钮及[在 Open WebUI 中管理本地模型](/getting-started/quick-start/connect-a-provider/starting-with-openai-compatible#managing-local-models-from-open-webui)中介绍的管理面板。详见下方[卸载已加载的模型](#unloading-loaded-models)。设置之后，**Continue Response** 还会发送用于继续上一次回复的 llama.cpp 字段，参见[服务商设置](/getting-started/quick-start/connect-a-provider/starting-with-openai-compatible#the-provider-setting)。如果不需要这些功能，请保留 `Default`。

💡 保存后，Open WebUI 就会开始把你的本地 Llama.cpp 服务器作为后端使用！

:::tip 连接超时配置

如果 Llama.cpp 服务器初始化较慢，或你看到了超时报错，可以提高模型列表获取超时：

```bash
# Increase timeout for slower model loading (default is 10 seconds)
AIOHTTP_CLIENT_TIMEOUT_MODEL_LIST=30
```

如果你保存了一个不可达 URL，导致界面卡住，请查看 [模型列表加载问题](/troubleshooting/connection-error#model-list-loading-issues-slow-ui--unreachable-endpoints) 故障排查页面。

:::

## 卸载已加载的模型 {#unloading-loaded-models}

当模型被你的 `llama-server` 实例加载到内存后，Open WebUI 会在模型选择器中为其加上一个绿色的 "Loaded" 指示符。管理员还会在该行看到一个 **Eject** 按钮——它会在不重启服务器的前提下卸载模型，方法是调用 `POST /api/models/unload`，进而访问 llama.cpp 在该 OpenAI 兼容连接根 URL 上的 `POST /models/unload` 端点。

要使上述功能正常工作，**Settings → Connections → OpenAI**（管理员区域）中对应的连接必须把 **Provider** 设为 `llama.cpp`（Open WebUI 用这个提示来选取正确的卸载机制）。如果连接仍保留默认的 OpenAI 兼容提供商类型，管理员尝试卸载模型时会返回错误。

同一个 **Provider** 设置还会在 **Settings > Models > ⋯ > Manage**（管理员区域）下为管理员提供一个管理面板，其中列出了服务器上的模型，并可以下载、加载、卸载和删除它们。参见[在 Open WebUI 中管理本地模型](/getting-started/quick-start/connect-a-provider/starting-with-openai-compatible#managing-local-models-from-open-webui)。

# 在 Open WebUI 中使用 Hermes Agent {#use-hermes-agent-in-open-webui}

如果你希望 Hermes 在聊天中选定的项目文件夹里工作，请通过 **Open Terminal** 使用它。如果你已经在运行带自己工作区的 Hermes 网关，可以[连接网关 API](#connect-the-hermes-gateway)。

## 通过 Open Terminal 运行 Hermes {#run-hermes-through-open-terminal}

1. 以运行终端的用户身份安装 Hermes。在该环境中运行 `hermes model` 配置模型提供商，然后启动 `hermes` 并发送一条测试提示。[Hermes Agent 快速开始](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)
2. 按 [Open Terminal 快速开始](/getting-started/quick-start/connect-an-agent#quick-start-with-open-terminal)连接工作区。在一个新的已保存聊天中，选择 **Terminal**，并用 **Choose working directory** 选定你的项目。
3. 选择以 `hermes/` 开头的模型。Open Terminal 会为你启动 `hermes acp`。让它读取项目中的一个文件，并把它的回复与 **Files** 中的文件对照。

## 连接 Hermes 网关 {#connect-the-hermes-gateway}

**把 Open WebUI 作为 Nous Research 自主 AI Agent 的聊天前端。**

[Hermes Agent](https://github.com/NousResearch/hermes-agent) 是 **Nous Research** 开发的自主 AI Agent，内置终端访问、文件操作、网页搜索、记忆和可扩展技能。它会暴露一个**兼容 OpenAI 的 API 服务**，因此接入 Open WebUI 只需几分钟。

当你通过 Open WebUI 发送消息时，Hermes Agent 会接收消息，决定是否调用工具，执行相关操作，并将最终回复流式返回。你还会实时看到内联进度提示（例如 `ls -la`、`searching...`）。

:::info 你需要准备
- 本机已安装 **Hermes Agent**（见其[快速开始指南](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)）
- 正在运行的 **Open WebUI**（Docker、pip 或桌面应用均可）
- 大约 **10 分钟** 完成本次配置
:::

---

### 第 1 步：安装 Hermes Agent {#step-1-install-hermes-agent}

如果你还没有安装 Hermes Agent，请先按照[官方快速开始](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)完成安装。安装后先验证：

```bash
hermes --version
```

---

### 第 2 步：启用 API 服务 {#step-2-enable-the-api-server}

把以下内容加入 Hermes Agent 的环境变量文件：

```bash title="~/.hermes/.env"
API_SERVER_ENABLED=true
API_SERVER_KEY=your-secret-key
```

请将 `your-secret-key` 替换为任意强随机字符串。它就是稍后你要在 Open WebUI 中填写的 API 密钥。

:::tip 可选配置
你也可以自定义端口和监听地址：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `API_SERVER_PORT` | `8642` | API 服务监听端口 |
| `API_SERVER_HOST` | `127.0.0.1` | 绑定地址（默认仅本机可访问） |
:::

---

### 第 3 步：启动 Gateway {#step-3-start-the-gateway}

```bash
hermes gateway
```

你应该看到类似如下输出，表示 API 服务已启动：

```
[API Server] API server listening on http://127.0.0.1:8642
```

:::warning 保持它持续运行
网关必须持续运行，Open WebUI 才能与智能体通信。长期部署时，可以通过终端复用器（`tmux` 或 `screen`）运行网关，也可以将它配置为系统服务。
:::

---

### 第 4 步：在 Open WebUI 中添加连接 {#step-4-add-the-connection-in-open-webui}

1. 在浏览器中打开 Open WebUI。
2. 进入 **Settings > Connections**（管理员区域），找到 **Manage OpenAI API Connections** 列表。
3. 点击 ➕ **添加连接**。
4. 填写以下内容：

| 设置项 | 值 |
|---|---|
| **URL** | `http://localhost:8642/v1` |
| **API 密钥** | 第 2 步中设置的 `API_SERVER_KEY` |

5. 点击 ✅ 勾选按钮进行验证，然后点击 **保存**。

:::tip 如果 Open WebUI 运行在 Docker 中？
把 `localhost` 替换为 `host.docker.internal`：

```
http://host.docker.internal:8642/v1
```
:::

---

### 第 5 步：开始聊天！ {#step-5-start-chatting}

现在，`hermes-agent` 模型应已出现在模型下拉列表中。选中它即可开始聊天。通过 Open WebUI 界面，你可以使用智能体的全部工具，包括终端、文件操作、网页搜索、记忆和技能。

流式输出默认开启。工具执行时你会看到简短的内联提示，随后再出现 Agent 的最终回复。

---

## Docker Compose 配置 {#docker-compose-setup}

如果你想要更稳定的长期部署，可以直接运行一个已预配置好连接 Hermes Agent 的 Open WebUI：

```yaml title="docker-compose.yml"
services:
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    ports:
      - "3000:8080"
    volumes:
      - open-webui:/app/backend/data
    environment:
      - OPENAI_API_BASE_URL=http://host.docker.internal:8642/v1
      - OPENAI_API_KEY=your-secret-key
    extra_hosts:
      - "host.docker.internal:host-gateway"
    restart: always

volumes:
  open-webui:
```

```bash
docker compose up -d
```

然后打开 [http://localhost:3000](http://localhost:3000)，创建你的管理员账户。

:::note
环境变量只会在 Open WebUI **首次启动**时生效。之后，连接设置会存储在其内部数据库中。若之后要修改，请使用管理界面，或删除 Docker 卷后重新开始。
:::

## 故障排查 {#troubleshooting}

### 下拉框中没有模型 {#no-models-appear-in-the-dropdown}

- 确认 URL 包含 `/v1`：`http://localhost:8642/v1`（而不只是 `:8642`）
- 检查 gateway 是否在运行：`curl http://localhost:8642/health` → `{"status": "ok"}`
- 检查模型列表：`curl http://localhost:8642/v1/models` → 应返回 `hermes-agent`

### 连接测试通过，但模型仍未加载 {#connection-test-passes-but-no-models-load}

Open WebUI 的连接测试会带上你的密钥请求 `GET <URL>/models`，因此缺少 `/v1` 后缀的 URL 通常会让测试本身就失败。如果测试通过但模型仍未加载，说明 `/models` 的响应不是带有 `data` 列表的 JSON（也不是一个裸列表），或者该连接已被关闭。如果你填写了 Model ID，则只会列出这些 ID，并且不会查询 `/models`。

### 出现 “无效的 API 密钥” 错误 {#invalid-api-key-errors}

请确认 Open WebUI 中填写的 **API 密钥** 与 `~/.hermes/.env` 中的 `API_SERVER_KEY` 完全一致。

### 响应耗时较长 {#response-takes-a-long-time}

Hermes Agent 可能在回复前执行了多个工具调用。对于复杂查询，这很正常——因为 Agent 的确在代表你完成真实工作。

### Linux Docker（无 Docker Desktop） {#linux-docker-no-docker-desktop}

在不带 Docker Desktop 的 Linux 上，`host.docker.internal` 默认不会解析：

```bash
# Option 1: Add host mapping
docker run --add-host=host.docker.internal:host-gateway ...

# Option 2: Use host networking
docker run --network=host -e OPENAI_API_BASE_URL=http://localhost:8642/v1 ...

# Option 3: Use Docker bridge IP
docker run -e OPENAI_API_BASE_URL=http://172.17.0.1:8642/v1 ...
```

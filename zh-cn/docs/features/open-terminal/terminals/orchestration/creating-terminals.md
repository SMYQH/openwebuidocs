# 创建机器 {#creating-machines}

**机器**是准备好的工作区，AI 可以在其中运行命令并处理文件。你可以直接从聊天创建机器，为它命名并决定谁可以使用。每台机器会启动一个或多个**实例**，即运行命令的容器。

当 AI 需要在真实计算机上运行代码、编辑文件或构建项目，并且每个人或聊天都需要干净、独立的工作环境时，可使用机器。一台机器可以通过共享用户组服务整个团队，也可以为每个用户、聊天或模型提供单独的实例，让文件保持隔离。只需配置一次镜像、资源、起始目录和设置脚本，每个实例就能以相同方式启动。

管理员添加 Terminals 服务器连接，并向用户授予**写入**权限。拥有**写入**权限的用户可创建和管理机器。其他用户可使用共享给自己的机器。

## 连接访问权限 {#connection-access}

按照[连接到 Open WebUI](/features/open-terminal/setup/connecting)和[身份验证](/features/open-terminal/terminals#authentication)中的说明，在管理区域的**设置 > 集成**中添加连接。连接表单包含名称、ID、URL、API 密钥、认证、**验证连接**、聊天上传、**访问权限**和**高级**选项。机器可以在聊天中创建，管理员也可在该列表的连接行中点击 **+** 来创建（参见[创建机器](#create-a-machine)）。

连接的 **Access** 有两种权限：

| 权限 | 用户可以执行的操作 |
| :--- | :--- |
| **读取** | 查看和使用共享给自己的机器 |
| **写入** | 在此服务器上创建和管理机器，并查看其所有机器 |

## 创建机器 {#create-a-machine}

1. 打开消息输入框中的机器菜单（云图标）。拥有**写入**权限时，即使还没有机器也会显示此菜单。
2. 在**机器**下点击**新建机器**。
3. 填写对话框并点击 **Create**。

管理员也可在管理区域的**设置 > 集成**中创建。点击 Terminals 连接旁的 **+** 会打开同一个对话框，连接下方会列出其机器，每台机器都带有用于打开设置的齿轮图标。这适用于为他人设置机器的情况，例如之后要公开的机器。

| 字段 | 用途 |
| :--- | :--- |
| **名称** | 机器菜单中显示的名称 |
| **服务器** | 运行机器的 Terminals 连接。只有创建机器且有多个 Terminals 连接可用时才显示 |
| **Separate instances** | 开关。开启后，通过旁边的下拉菜单选择 **User**、**Chat** 或 **Model**，初始值为 **User**。关闭时，所有拥有访问权限的人共用一个实例。参见[实例范围](#machine-scope)。存在实例时此设置会锁定，须删除所有实例才能更改 |
| **Start directory** | 位于 **Advanced** 下，指定命令开始运行的文件夹。该文件夹须位于主目录内，否则命令会在主目录中启动。保存为 `OPEN_TERMINAL_START_DIR` |
| **Setup script** | 位于 **Advanced** 下。每次启动实例时，系统都会在启动目录中运行此 Shell 脚本，运行完毕后实例才可用。重启时只保留主目录，因此脚本应能安全地重复运行。保存为 `OPEN_TERMINAL_SETUP_SCRIPT`。**System info** 会显示进度和失败信息，包括退出码及日志的末尾内容 |
| **Advanced** | 包含 **Start directory**、**Setup script**、**Image**、**CPU**、**Memory**、**Storage**、**Network** 和 **Environment variables**。留空时使用服务器默认值。填写的值会按服务器上限核验 |

新机器默认为私有。创建后，从机器菜单打开**机器设置**，点击对话框顶部的**私有**按钮打开**访问权限**，在那里向指定用户及用户组共享机器。管理员还可以将机器设为公开，向所有用户共享。共享只授予使用权限。

:::warning 写入权限可访问他人的实例
拥有 Terminals 连接 **Write** 权限的用户可以打开该连接上任意运行中实例的 **System info**，并完全访问其实例文件。仅将 **Write** 权限授予你信任的用户，因为他们能够访问每个人的工作区。
:::

原始值与保留键见[环境变量](/features/open-terminal/terminals/orchestration/environment-variables)，**Image** 字段见[自定义镜像](/features/open-terminal/terminals/orchestration/custom-images)。

有权访问机器的人可以在机器上运行命令。关闭**独立实例**时，所有有访问权限的人共用一个实例。选择**模型**时，使用同一个模型的人共享一个实例。他们可以看到该实例的文件，因此只向获准查看这些文件的人共享。

## 实例范围 {#machine-scope}

| Separate instances | 结果 |
| :--- | :--- |
| 关闭 | 所有使用该机器的人共享一个实例 |
| 开启，**User** | 每个用户拥有独立实例 |
| 开启，**Chat** | 每个已保存的聊天拥有独立实例和文件 |
| 开启，**Model** | 每个模型拥有独立实例 |

- **聊天**作用域的机器需要已保存的聊天。发送第一条消息后，即可在已保存的聊天中使用。
- **模型**作用域的机器需要模型访问权限。
- 可以在以**允许回复**方式共享的聊天中回复的人，会使用该聊天自身的机器。
- 向频道发帖的自动化不能使用**聊天**作用域的机器。

**Chat** 和 **User** 会增加同时运行的实例数。可请管理员设置空闲超时，以清理已不再使用的聊天实例。参见[空闲清理、最长运行时间和计划重置](/features/open-terminal/terminals/orchestration#idle-cleanup-lifetime-and-scheduled-resets)。

## 管理实例 {#manage-machines}

对话框中的**实例**列表按名称显示机器的所有实例及其运行或停止状态。打开某一行的**更多选项**菜单即可操作。运行中的实例提供**重启**、**停止**、**系统信息**和**查看文件**，已停止的实例提供**启动**。每个实例都可**删除实例**。操作执行过程中，该行会显示进度指示器及当前状态（**正在重启...**、**正在停止...**、**正在启动...**或**正在删除...**）。**删除机器**会移除机器及其所有实例和文件。

## 机器菜单 {#machine-menu}

菜单中每台机器都有**更多**菜单。实例运行时提供**重启**和**停止**，停止时提供**启动**。运行时还会列出**系统信息**和**查看文件**。**机器设置**始终可用。**查看文件**会打开该机器的[文件浏览器](/features/open-terminal/file-browser)，无需在聊天中选择它。**系统信息**显示 CPU、内存、磁盘及网络使用情况、运行时长和主要进程，打开时每 5 秒刷新一次。

## 聊天 {#chats}

每个聊天都会保存其机器和工作目录，并在重新打开时恢复。保存时未选择机器的聊天在打开时也不会选择机器。

**在管理面板中监控使用情况、评估模型质量，并与用户沟通。**

Open WebUI 为管理员提供了完整的运营工具包。跟踪团队使用的模型及其费用。通过盲测评估找到最适合工作负载的模型。向所有用户推送可定制的横幅公告。配置 Webhook 以在用户注册或长时间任务完成时收到通知。

## Task Models（任务模型） {#task-models}

聊天标题、标签、追问建议、自动补全、搜索查询改写和上下文压缩摘要，都会在后台单独调用模型。默认使用当前聊天的模型，因此旗舰模型也可能被频繁调用来生成寥寥数词的标题。

**适合用来：** 把这类工作挪到一个小而快的模型上，限制这些请求允许消耗的额度，并关掉你的实例不需要的那部分。

[**了解 Task Models →**](/features/administration/task-models)

---

## Analytics（分析） {#analytics}

从全局视角了解实例的使用情况。分析仪表板展示消息量、Token 消耗、模型热度及用户活动，可按时间段和用户组进行筛选。

**适用场景：** 容量规划、费用估算、识别热门模型、跟踪推广趋势以及按部门统计用量。

[**了解 Analytics →**](/features/administration/analytics)

---

## Evaluation（评估） {#evaluation}

不确定哪个模型最适合您的团队？评估系统允许用户在日常对话中通过点赞/踩对模型回复评分。评分结果会汇入基于 ELO 的排行榜，已评分的对话将生成快照，用于未来的模型微调。

**两种评估模式：**
- **竞技场模式**：随机选择模型进行盲测对比，消除偏见
- **普通交互**：在日常使用中对回复评分，然后通过切换模型进行比较

[**了解 Evaluation →**](/features/administration/evaluation)

## Banners（横幅） {#banners}

向所有已登录用户推送高可见度消息。将横幅用于维护窗口、故障告警、政策提醒和功能公告。可通过管理面板或 `WEBUI_BANNERS` 环境变量（适用于 GitOps 工作流）进行配置。

| 类型 | 颜色 | 最适合 |
|------|-------|----------|
| `info` | 蓝色 | 一般公告 |
| `success` | 绿色 | 故障已解决、变更完成 |
| `warning` | 黄色 | 计划维护、局部降级 |
| `error` | 红色 | 正在发生的故障、服务中断 |

[**了解 Banners →**](/features/administration/banners)

## Default Interface Settings（默认界面设置） {#default-interface-settings}

你可以决定每个人 **设置 > 界面** 页面的初始值，而不是让每个账户都停留在出厂默认值。可在管理面板中设置，或用 `DEFAULT_INTERFACE_SETTINGS` 环境变量以适配 GitOps 工作流。

**适合用来：** 让团队第一天就拥有一致的界面，关掉某个默认开启但碍眼的选项，或者推行一套团队风格同时仍允许个人自行调整。没有被改动的选项会继续跟随你的默认值，因此之后的变更会传达到所有没有覆盖过它的用户。

[**了解 Default Interface Settings →**](/features/administration/interface-defaults)

## Webhook 通知 {#webhooks}

三种 Webhook 集成类型让您的外部服务保持同步：

| Webhook | 用途 |
|---------|---------|
| **事件 Webhooks** | 把事件目录中的任意事件（包括注册事件）推送到 Slack、Discord 或你自己的端点 |
| **用户 Webhook** | 长时间运行的对话响应就绪时通知对应用户 |
| **频道 Webhooks** | 允许外部服务（CI/CD、监控、脚本）向 Open WebUI 频道发送消息 |

[**了解 Webhooks →**](/features/administration/webhooks)

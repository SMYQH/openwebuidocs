# 将搜索结果保存到知识库 📚 {#save-search-results-to-knowledge}

**Add Web Sources to Knowledge Action** 可将网页搜索结果的 URL 一键保存到知识库。该功能会自动抓取、清洗并上传网页内容，帮助你积累研究资料。

## 功能特性 {#features}

- **一键保存**：快速把聊天消息中选中的来源添加到任意知识库
- **URL 选择**：可从编号列表中挑选要保存的特定 URL
- **批量处理**：单次操作可处理多个 URL
- **重复检测**：自动跳过目标知识库中已存在的 URL
- **可配置默认值**：可设置默认知识库并跳过确认弹窗，加快保存流程

## 设置 {#setup}

“Add Web Sources to Knowledge” 功能以 **Function Action** 的形式实现。使用方法如下：

1.  **下载该 Action**：访问 Open WebUI Community Hub，并下载 [Add Web Sources to Knowledge Action](https://openwebui.com/posts/65d97417-d079-4720-b2cc-a63dd59b7e3e)
2.  **启用该 Action**：
    *   前往**管理面板 > 函数**
    *   导入它，或使用提供的代码创建新函数
    *   为所有模型或指定模型启用该 Action

## 如何使用 {#how-to-use}

:::warning 原生模式只列出已抓取的页面
在原生（agentic）工具调用中，搜索命中项并不算来源，因此该操作能提供的网页条目只有模型通过 `fetch_url` 打开过的页面。如果模型仅依据摘要（snippet）作答，就没有任何内容可供保存。旧版工具调用行为不变，仍会列出所有已检索到的搜索结果。参见 [Agentic Search](/features/chat-conversations/web-search/agentic-search)。
:::

1.  **触发网页搜索**：提出一个会触发网页搜索的问题（例如使用 DDGS、Google PSE 等）
2.  **点击 Action 按钮**：模型返回引用后，点击消息工具栏中**带 + 号的文件夹**图标
3.  **选择来源**：会弹出一个对话框。输入你想保存的来源编号（例如 `1,3,5`、`1-3` 或 `all`）
4.  **选择知识库**：选择要保存内容的目标知识库
5.  **完成**：系统会使用你配置好的 **Web Loader** 抓取内容，并将其加入知识库

## 配置（Valves） {#configuration-valves}

你可以在函数设置中通过 **Valves** 自定义该 Action 的行为。

### 管理员设置（全局默认） {#admin-settings-global-defaults}

| 设置项 | 默认值 | 说明 |
|---------|---------|-------------|
| `max_urls_per_action` | `10` | 单次操作最多处理的 URL 数量 |
| `enable_duplicate_check` | `True` | 添加前检查知识库中是否已有该 URL |
| `default_knowledge_base` | `""` | 系统级默认知识库的名称或 ID |
| `skip_confirmation` | `False` | 跳过确认弹窗，直接使用默认知识库 |
| `file_name_prefix` | `""` | 生成文件名的前缀（例如 `web_`） |

### 用户设置（个人覆盖） {#user-settings-personal-overrides}

用户也可以在自己的设置中覆盖全局默认值：
- **默认知识库（Default Knowledge Base）**：设置一个偏好的 KB，避免每次手动选择
- **跳过确认（Skip Confirmation）**：启用后可实现即时一键保存（要求已设置默认 KB）
- **文件名前缀（File Name Prefix）**：自定义保存来源时的文件名前缀

:::tip 高级用法
在你的 User Valves 中设置 **默认知识库（Default Knowledge Base）**，并启用 **跳过确认（Skip Confirmation）**，即可实现真正的一键式即时保存网页来源！
:::

## 故障排查 {#troubleshooting}

- **内容质量**：保存内容的质量取决于**网页加载引擎**设置（管理面板中的设置 > 文档）。对于大量使用 JavaScript 的网站，可考虑使用 **Firecrawl** 或 **Playwright**
- **未检测到 URL**：该操作会读取附加到消息上的来源。如果检测不到 URL，请确认网页搜索已启用并返回了结果。在原生模式下，还要确认模型确实用 `fetch_url` 打开过页面，因为搜索命中项本身不算来源

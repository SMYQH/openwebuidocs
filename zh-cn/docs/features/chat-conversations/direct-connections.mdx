该功能当前仍处于**实验阶段**，未来版本中可能会发生变化，甚至被移除。
:::

**直接连接**让用户的 Open WebUI 客户端可以直接连接到兼容 OpenAI 的 API 端点，无需通过 Open WebUI 后端即可发送推理请求。

## 概览 {#overview}

在标准部署中，Open WebUI 充当代理：浏览器把提示词发送给 Open WebUI 后端，再由后端转发给 LLM 提供商（如 Ollama、OpenAI 等）。

而使用 **直接连接** 后，浏览器会直接与 API 提供商通信。

服务器仍会运行该轮对话的其余部分，包括聊天标题和标签等后台步骤，而这些步骤需要读取实例的模型列表。它们读取的是同一份一致的副本，因此在基于 Redis 的多副本部署中，即使在请求过程中刷新了该列表也不会再导致消息失败，模型列表很长也不会再拖慢这一轮对话（详见[说明](/troubleshooting/multi-replica#3-model-not-found-or-configuration-mismatch)）。

## 优势 {#benefits}

*   **隐私与控制**：用户可以使用个人 API 密钥。密钥保存在浏览器本地存储中，不必存到 Open WebUI 服务器上。
*   **更低延迟**：不再经过 Open WebUI 后端转发，可能加快响应速度。
*   **降低服务器负载**：由各用户的浏览器处理网络流量并管理连接，不再由 Open WebUI 服务器承担。

## 前提条件 {#prerequisites}

1.  **管理员启用**：管理员必须全局开启该功能。
    *   在管理界面的**设置 > 连接 > 直接连接**中，将开关设为**开启**。
    *   或设置环境变量：`ENABLE_DIRECT_CONNECTIONS=true`。
2.  **CORS 配置**：由于请求由浏览器发起，API 提供商必须配置**跨源资源共享 (CORS)**，允许来自你的 Open WebUI 域名的请求。
    *   *注意：许多限制严格的提供商（如 OpenAI 官方服务）可能会因 CORS 策略拒绝浏览器直连请求。此功能通常更适合限制较少的提供商或内部 API 网关。*

:::warning 安全建议：限制提供商密钥的权限
直接连接应使用权限最小的提供商凭证。

如果提供商支持限制密钥权限，日常使用时请优先选择仅能发起推理请求的密钥。不要用管理密钥或主密钥处理日常用户请求。
:::

## 用户配置 {#user-configuration}

管理员启用该功能后，用户就可以配置自己的直连：

1.  前往**用户设置 > 连接**。
2.  点击 **+（添加连接）**。
3.  输入**基础 URL**（例如 `https://api.groq.com/openai/v1`）以及你的 **API 密钥**。
4.  点击**保存**。

来自该直连的模型现在就会出现在你的模型列表中。它们通常与后端提供的模型看起来没有区别，但实际请求将直接从你的设备流向对应提供商。

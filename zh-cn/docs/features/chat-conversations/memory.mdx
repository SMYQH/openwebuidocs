:::info 依赖模型的质量
记忆的存储和回忆效果在很大程度上依赖于所使用的模型。Frontier 级模型可以良好地管理记忆；小型本地模型可能在存储或检索信息时表现不一致。
:::

Open WebUI 内置了一套完善的记忆系统，使模型能够跨不同对话记住事实、偏好和上下文。
启用**原生工具调用**时，模型会主动管理这些记忆，将其用作长期记忆。

## 工作原理 {#how-it-works}

记忆系统会存储关于你的若干信息片段（例如"我偏好用 Python 处理后端任务"或"我住在维也纳"）。这些记忆有两种使用方式：

### 1. 手动管理（设置中） {#1-manual-management-settings}

用户可以通过以下位置手动新增、编辑或删除记忆：
**设置 > 个性化 > 记忆**

只有在 **Memory** 开关开启时才会列出**已保存的记忆**。关闭开关会隐藏该列表，也不再把记忆加入你的聊天，但不会删除任何内容；重新打开后，同样的记忆会回来。

**Add Memory** 会要求选择**类型**。**User** 记忆是关于你的事实、偏好或指令，它们在每次回复时都会全部提供给模型，上限为 [`MEMORIES_USER_CHAR_LIMIT`](/reference/env-configuration#memories_user_char_limit) 预算。**Context** 记忆只在与当前聊天相关时才会提供：Open WebUI 用你最近七条消息检索你的记忆，并加入最相近的匹配项，上限为 [`MEMORIES_CONTEXT_CHAR_LIMIT`](/reference/env-configuration#memories_context_char_limit) 预算。记忆按字母顺序列出，有路径时路径排在最前，超出预算的文本会被直接截断且没有提示。**User** 记忆过多时，排在末尾的那些永远无法传给模型。

该检索还会应用 **Settings > Documents**（管理员区域）中的**相关性阈值**，或 [`RAG_RELEVANCE_THRESHOLD`](/reference/env-configuration#rag_relevance_threshold)。当它大于 `0` 时，与你的消息向量相似度低于该值的 **Context** 记忆会从检索结果中掉出，既不报错也没有提示。记忆不会经过重排序器处理，而且即使 **Hybrid Search** 关闭、该字段被隐藏，阈值依然生效，因此为重排序器分数调好的数值可能让所有 **Context** 记忆都无法匹配。若 **Context** 记忆不再传给模型，请降低阈值或将其设为 `0`。**User** 记忆和按文本匹配的 `search_memories` 工具不受影响。

列表上方 **Actions** 菜单中的 **Clear memory** 会删除你账号上的全部记忆，包括被搜索框隐藏的记忆。在 **Clear Memory** 对话框（`Are you sure you want to clear all memories? This action cannot be undone.`）中确认后，Open WebUI 会从数据库中删除这些记忆并清除其搜索索引，随后显示 `Memory cleared successfully`。没有撤销，也没有回收站。若只想删除部分记忆，请改为在列表中逐条删除。

### 2. 原生记忆工具（Agentic 模式） {#2-native-memory-tools-agentic-mode}

当你使用启用了 **原生函数调用（Agentic 模式）** 的模型时，高质量模型可以通过内置工具自主管理你的记忆。关于管理员如何配置和管理这些系统级工具的详细说明，请参阅 [**中央工具调用指南**](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)。

:::tip 最低模型档位
自主记忆管理需要模型能够判断哪些事实值得保存、何时召回它们。这并不要求 frontier 级模型：**GPT-5.6 Luna**、**Gemini 3.5 Flash-Lite**、**MiniMax M3**，或者本地运行的 **Qwen 3.6 27B**、**Muse Glimmer 30B** 是最低要求。只有非常小的模型在记忆选择上会吃力。该列表不会随每次模型发布而更新；任何较新且工具调用可靠的模型都可以。
:::

每条记忆都带有一个**类型**和一个可选的**路径**（见下方的[记忆类型与路径](#memory-types--paths)）。模型通过以下工具管理记忆：

-   **`add_memory`**：保存新的事实、偏好或指令，标记为 `user` 或 `context` 类型，可选地指定 `path`。
-   **`update_memory`**：在一次调用中应用批量更改（添加/替换/移动/移除）。
-   **`replace_memory_content`**：使用 `id` 更新或修正特定的已有记忆。
-   **`delete_memory`**：使用 `id` 移除不再相关或正确的记忆。
-   **`search_memories`**：按内容、路径、类型或精确 `id` 搜索或浏览记忆库。结果包含每条片段的唯一 `id`（默认返回 5 条）。
-   **`list_memories`**：检索用户的所有已存储记忆，包括内容和时间戳。
-   **`list_memory_paths`**：列出已保存的记忆路径（分组），以便模型在写入前找到相关记忆的存放位置。
-   **`read_memory_path`**：读取指定路径下存储的记忆，包括附近的父路径和子路径。

## 记忆类型与路径 {#memory-types--paths}

每条记忆都有一个**类型**和一个可选的**路径**：

- **类型** — `user` 类型的记忆是**关于你**的事实、偏好或指令（例如"偏好用 Python 处理后端"）；`context` 类型的记忆是值得在聊天之间携带的其他持久化上下文。两者在注入提示词时分别计算预算（见[后台审查与限制](#background-review--limits)）。
- **路径** — 一个可选的稳定"地址"，用于**对相关记忆进行分组**（例如 `work/projects`），使模型可以通过 `list_memory_paths` / `read_memory_path` 以层级结构组织和浏览它们，而不是一个扁平的列表。

这些由记忆工具自动设置，你无需手动分配。

## 新记忆系统的优势 {#benefits-of-the-memory-system}

-   **主动学习**：你无需手动输入偏好。模型可以在后台调用 `add_memory`，例如说：*"我会记住你在 UI 项目里偏好深色模式"*
-   **上下文检索**：如果对话突然转回几个月前提到的话题，模型可以通过 `search_memories` 去"搜索大脑"，找回相关细节
-   **动态修正**：如果模型记错了内容，它可以使用 `replace_memory_content` 修正该事实，而不是创建一条重复记忆
-   **清理能力**：模型可以通过 `delete_memory` 清除过期或无关事实，保持记忆库整洁
-   **完全可见**：借助 `list_memories`，模型可以查看它所掌握的全部内容，并识别空缺或矛盾之处
-   **用户控制**：尽管模型可以主动添加记忆，但用户始终保有完全控制权。模型添加的每条记忆都可以在个性化设置中审查并删除

## 启用记忆工具 {#enabling-memory-tools}

1.  **管理员启用**：确保管理员已经[全局启用](#administrative-controls)记忆功能，并确认你拥有所需权限
2.  **原生模式（Agentic 模式）**：在模型的高级参数中启用**原生函数调用**（**设置 > 模型 > 编辑**（管理员区域）该模型 **> 高级参数**）
3.  **按模型开关**：确保在 **设置 > 模型 > 编辑**（管理员区域）（自己的模型则用 **工作区 > 模型**）中，模型的 **记忆** 能力与 **内置工具** 下的 **记忆** 分类均已启用（两者默认均为开启）。模型还需要开启 **内置工具**

[自动化](/features/chat-conversations/chat-features/automations)也会在相同条件下获得记忆工具——只要记忆对其所有者用户开启。这依赖用户在 **设置 > 个性化** 中的 **记忆** 开关。如果用户从未设置过该开关，则由默认界面设置决定，而在连默认界面设置也没有的情况下，则由实例级的 **记忆** 设置决定。

:::warning 出现空回复而非记忆操作
记忆以原生工具调用的方式运行，因此它只能在流式输出遵循 OpenAI schema 的连接上工作。在流式工具调用中省略 `index` 字段的端点上（其中包括 Google 的 OpenAI 兼容层），该调用会被丢弃，该轮请求返回一条空的 assistant 消息，且日志中不会留下任何记录。由于是否调用 `list_memories` 或 `add_memory` 由模型自行决定，这表现为偶发性的空回复，而不是明显的记忆故障。参见[模型使用工具时出现空回复](/troubleshooting/connection-error#blank-replies-when-the-model-uses-a-tool)。
:::

:::info 中央工具文档
有关所有内置 agentic 工具（包括记忆、网络搜索和知识库）的完整说明及配置方法，请参阅 [**原生/Agentic 模式工具指南**](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)。
:::

## 管理控制 {#administrative-controls}

管理员对记忆功能拥有完全的控制权，包括在全局禁用它，或将其限制为特定的用户组。

### 全局开关 {#global-toggle}

记忆功能可以对整个实例开启或关闭。关闭后，所有用户都会看不到"个性化"标签，相关记忆 API 端点也会被禁用。已存储的记忆将不再注入模型上下文，模型也不会收到记忆工具。
- **管理 UI**：设置 > 通用 > 功能 > **记忆**（管理员区域）
- **环境变量**：[`ENABLE_MEMORIES`](/reference/env-configuration#enable_memories)（默认：`True`）

### 细粒度权限 {#granular-permissions}

管理员还可以通过权限界面，按角色或用户组控制记忆访问。
- **管理 UI**：管理面板 > 用户 > 权限 > 功能 > **记忆**
- **环境变量**：[`USER_PERMISSIONS_FEATURES_MEMORIES`](/reference/env-configuration#user_permissions_features_memories)（默认：`True`）

收回该权限会切断记忆抵达模型的所有路径。受影响的用户将失去**个性化**标签页，记忆 API 端点会向其返回 `403`，模型不再获得记忆工具，其已存储的记忆也不再被加入模型上下文。最后一项检查会在每次聊天请求时于服务端执行，因此仍在请求记忆的请求（比如之前就开着的个人 **记忆** 开关，或者发送 `features: {"memory": true}` 的 API 客户端）也不会让记忆重新出现。管理员不受该权限检查的限制。

### 后台审查与限制 {#background-review--limits}

- **后台审查** — 当启用了 [`ENABLE_MEMORY_BACKGROUND_REVIEW`](/reference/env-configuration#enable_memory_background_review)（默认**关闭**），Open WebUI 会定期使用该对话自身的模型回顾最近的对话内容，并每 [`MEMORIES_REVIEW_INTERVAL_TURNS`](/reference/env-configuration#memories_review_interval_turns) 轮（默认 `10`）添加、替换、移动或删除两种类型的记忆（其中也包括 `user` 类型），而不只是依赖显式的工具调用。
- **注入预算** — [`MEMORIES_CONTEXT_CHAR_LIMIT`](/reference/env-configuration#memories_context_char_limit) 和 [`MEMORIES_USER_CHAR_LIMIT`](/reference/env-configuration#memories_user_char_limit)（均默认 `2000`）限制注入到提示词中的 `context` 和 `user` 类型记忆的最大字符数。

### 记忆系统上下文 {#memory-system-context}

默认情况下，Open WebUI 会将用户的已存储记忆注入到模型的上下文，使模型能够感知到它们。使用原生函数调用时，这些记忆会在每次回复时以隐藏的 `recall_memories` 工具结果形式出现在用户消息之后；否则它们会被追加到用户消息上。记忆召回还需要模型具备 **Memory** 能力。此注入可以独立于记忆工具单独关闭：关闭后，模型仍然可以按需添加、更新和删除记忆，但记住的信息不再自动添加到提示词中。
- **管理 UI**：设置 > 通用 > 功能 > **记忆系统上下文**（管理员区域）（在记忆功能启用时显示）
- **环境变量**：[`ENABLE_MEMORY_SYSTEM_CONTEXT`](/reference/env-configuration#enable_memory_system_context)（默认：`True`）

## 隐私与安全 {#privacy--security}

记忆会本地存储在你的 Open WebUI 数据库中，并且仅作用于你的用户账号。默认情况下，它们不会与其他用户共享；你也可以随时清空自己的整个记忆库。

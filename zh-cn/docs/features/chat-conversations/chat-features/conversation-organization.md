# 文件夹与项目 {#folders--projects}

Open WebUI 提供了强大的基于文件夹的组织功能，可将简单的对话容器变成功能完备的**项目工作区**。文件夹不仅让你可以对相关对话进行分组，还可以定义适用于其中所有对话的特定上下文、系统提示词和知识库。

## 启用文件夹 {#enabling-folders}

文件夹默认启用。管理员可通过以下方式控制该功能：

- **管理面板**：文件夹功能与其他功能一起进行全局控制
- **环境变量**：[`ENABLE_FOLDERS`](/reference/env-configuration#enable_folders) - 设为 `True`（默认）启用，设为 `False` 禁用

## 核心功能 {#core-features}

### 创建文件夹 {#creating-folders}

创建一个新文件夹来组织你的对话：

1. 点击**侧边栏**中文件夹标题旁的 **+ 按钮**。
2. 选择 **"新建文件夹"**
3. 输入文件夹名称
4. 点击 **保存**

### 将对话移动到文件夹中 {#moving-conversations-into-folders}

你可以把现有聊天整理到文件夹中：

- **拖拽**：在侧边栏中将任意对话拖入某个文件夹
- **对话菜单**：在侧边栏中悬停某个对话，点击出现的三点菜单，然后选择**移动**并选定目标文件夹。只要至少存在一个文件夹，该菜单项就会出现。

如果有权限将聊天放入某个文件夹，拖动聊天经过该文件夹时，它会高亮显示，方便你在松手前确认放置位置。你自己的文件夹始终可接收聊天。[与你共享的文件夹](#sharing-folders)仅在你拥有写入权限时接收聊天。如果只有读取权限，则不会高亮。

### 嵌套文件夹 {#nested-folders}

文件夹可以嵌套在其他文件夹中，形成层级结构：

- **从菜单创建子文件夹**：右键（或点击三点菜单 ⋯）任意文件夹，选择 **"创建文件夹"**，即可直接在其中创建子文件夹
- **拖拽**：把一个文件夹拖到另一个文件夹上，即可把它变成子文件夹
- **重新排序**：将文件夹拖到另一文件夹的正上方或正下方，即可放在与它相同的层级。顺序会随设置保存，因此在各设备上一致。尚未排序的文件夹会在末尾按名称排列。共享文件夹仍按名称排序。
- **导出**：文件夹上的同一个三点菜单还有**导出**，用于下载该文件夹中的聊天。它需要[允许聊天导出](/features/authentication-access/rbac/permissions#3-chat-permissions)权限。菜单中没有移动项；文件夹只能通过拖放来更换父级。
- 文件夹可展开或折叠，以显示 / 隐藏其内容
- 同一父文件夹下，子文件夹名称必须唯一；若输入重复名称，系统会自动追加编号（例如 "Notes 1"）

子文件夹中的聊天使用该子文件夹的**系统提示词**和**知识库**设置。例如，如果父文件夹附加了手册，还需要把手册附加到子文件夹，才能让其中的聊天自动使用该手册。

### 未读徽标 {#unread-badge}

文件夹会在侧边栏的名称旁显示其中未读或等待你批准工具调用的聊天数量。

- 该计数包含文件夹及其所有子文件夹中的聊天，因此折叠父文件夹后，仍能看到其中有多少聊天未读或等待批准。
- 自上次打开以来发生变化的聊天计为未读。已归档的聊天不计入，仍在生成回复的聊天要等生成结束才计入。因等待工具调用批准而暂停的聊天会立即计入一次。
- 打开聊天会立即把它从计数中清除，并且在你打开的每个窗口中都生效：服务器会即时重新计算你的文件夹计数并推送到你的其它会话，而不是等到下次重新加载。
- 未读状态只与你自己的阅读情况有关。共享的文件夹不带徽标，属于他人的聊天无论最近是否被改动过，对你都不会显示为未读。
- 为聊天自动生成的标题不会让它重新变成未读。

文件夹页面会标注每个聊天的状态：圆点表示未读，加载动画表示仍在流式生成回复，黄色圆点表示等待批准。页面会实时更新。开始或结束生成的聊天会就地更新，移入该文件夹的聊天会直接插入，无需整页重新加载。断线恢复后，页面会重新加载。从该页面打开聊天会立即清除其圆点，无需等聊天加载完成。按活动排序、分组和筛选的方法见[文件夹页面](#the-folder-page)。

#### 标记为已读和未读 {#marking-read-and-unread}

- **将聊天标记为未读**：在侧边栏中打开某个聊天的三点菜单，选择**标记为未读**。该聊天会重新显示圆点，与其他未读聊天一起上移，文件夹计数也会增加。浏览对话后，可以用这个选项提醒自己稍后返回。
- **将文件夹标记为已读**：打开文件夹的三点菜单，选择**全部标记为已读**。如果你拥有该文件夹，此操作会清除其中及其所有下级文件夹内的未读状态。如果文件夹是别人共享给你的，只会清除该文件夹中你自己的聊天的未读状态。归档聊天不受影响。
- **全部标为已读**：侧边栏的**聊天**区段标题有自己的菜单，其中的**全部标为已读**会将你拥有的所有未读聊天标为已读，无论它们是否位于文件夹中，并一次性清零所有文件夹徽标。同样，已归档的聊天不受影响。

### 在文件夹中开始聊天 {#starting-a-chat-in-a-folder}

当你点击侧边栏中的某个文件夹时，它会成为你的**当前工作区**：

1. 在侧边栏点击任意文件夹将其选中
2. 聊天界面会显示该文件夹当前处于激活状态
3. 此后你新建的任何聊天都会自动创建在该文件夹中
4. 新聊天会**继承文件夹的设置**（默认模型、机器、工作目录、系统提示词和知识库）。

文件夹的三点菜单中还有**新建聊天**，其作用与打开该文件夹相同。

侧边栏中的每个文件夹都是指向其独立页面的链接，因此中键点击或 Ctrl/Cmd 点击会在新标签页中打开该文件夹。

文件夹会为你保留自己的标签页，再次打开时，会恢复留在其中的聊天、文件和终端。新聊天页面的**继续**区域列出有未完工作或仍留有打开标签页的文件夹。未完工作包括正在运行或等待你批准的聊天，你可以从中断处继续。

把聊天移动到某个文件夹需要对该文件夹有**写入权限**。也就是说，该文件夹属于你本人，或者它（直接或通过上层文件夹）以写入权限共享给你。对共享文件夹只有只读权限时，你可以打开它并阅读其中的聊天，但在那里发送新聊天的第一条消息会被拒绝，而不是悄悄把聊天移动进该文件夹。

这项检查在聊天被赋予文件夹的三个地方都相同：通过 API 创建聊天、把已有聊天移动到某个文件夹，以及发送一个在其中创建的聊天的第一条消息。指定一个不存在的文件夹，与指定一个你没有写入权限的文件夹一样会被拒绝。

## 文件夹页面 {#the-folder-page}

点击侧边栏中的文件夹，页面会像小型项目跟踪器一样显示其中的所有聊天。它适合收集较多对话的文件夹，例如研究项目、请求队列或周报，让你看清哪些已完成、哪些在等待，以及哪些需要处理。共享给你的文件夹页面用法相同，可修改的内容取决于你的访问权限。

### 列表和看板 {#list-and-board}

打开**显示选项**（搜索和筛选旁的滑块图标），选择**布局**。

- **列表**每行显示一个聊天。**分组**可按**状态**、**优先级**、**标签**或**活动**划分为可折叠的组，也可以选择**无**来保留单个列表。空分组保持隐藏，直到开启**显示空分组**。
- **看板**将每个聊天显示为卡片。**列**可选择按**状态**、**优先级**、**标签**或**活动**分列。**行**可按其余一种属性添加横向泳道。使用状态分列时，它就像一张任务看板。

**排序**可按**更新时间**、**标题**或**优先级**进行升序或降序排列。布局、分组、列、行和排序由浏览器保存，而筛选条件在每次访问时都会清空。

**活动**反映聊天当前进展：**未读**（自上次打开后有变化）、**正在生成**、**等待批准**（因等待工具批准而暂停）和**已读**。列表行和卡片用圆点或加载动画标记前三种状态，便于发现需要关注的聊天。

### 搜索和筛选 {#searching-and-filtering}

点击搜索图标或按 `/` 键，可以打开搜索框，匹配聊天标题和消息文本。点击筛选图标或按 `f` 键会打开菜单，支持按**状态**、**优先级**、**标签**、**用户**、**活动**和**更新时间**（**今天**、**最近 7 天**或**最近 30 天**）筛选。状态、优先级、标签和用户都支持多选。标签列表包含**无标签**，用于筛选未加标签的聊天。

列表和看板中的聊天与侧边栏中的聊天使用同样的三点菜单，可重命名、移动、克隆、共享、归档、删除和标记为未读。别人发起的聊天只有**重命名**。在以只读方式共享给你的文件夹中，你没有发起的聊天没有菜单。

### 状态 {#statuses}

状态描述聊天的进展，例如**进行中**或**已完成**。文件夹初始没有自定义状态，未分配状态的聊天显示为**无状态**。可在**编辑状态…**中添加所需状态。在该文件夹添加自己的状态之前，系统会建议**待规划**、**待办**、**进行中**、**等待中**和**已完成**。

点击聊天开头的状态图标可选择状态，也可在按状态分组的看板上把卡片拖到另一列或泳道。聊天所有者始终可以设置其状态。在共享文件夹中，有权编辑该文件夹的人可以设置其中每个聊天的状态。已分配状态的聊天会在旁边显示累计处于该状态的时间，例如 **3d**。此前处于同一状态的时间也会计入。

有权编辑该文件夹的人可在状态菜单底部选择**编辑状态…**，或在状态看板末尾选择**添加状态**。在**状态**对话框中，可更改名称（最多 40 个字符，在文件夹内唯一）、图标（内置形状或**使用表情符号…**）和颜色，也可拖动调整顺序，以及新增或删除状态。处于已删除状态的聊天会回到**无状态**。

还可以通过聊天上的优先级图标设置优先级（**紧急**、**高**、**中**或**低**），所需权限与设置状态相同。

### 标签 {#tags}

标签按主题标记聊天，可用于上述分组、看板和筛选。聊天所有者可添加标签，在共享文件夹中，有权编辑该文件夹的人也可以添加。将鼠标悬停在聊天所在行，点击**标签**按钮或现有标签。对于自己的聊天，也可使用顶栏聊天菜单中的**标签**子菜单。这些入口打开同一个选择器，输入名称查找标签，勾选或取消勾选以添加或移除。选择**创建“名称”**可新建标签。点击已勾选标签旁的彩色圆点可选择颜色，颜色在所有使用该标签的地方生效。文件夹编辑者对他人聊天新增、移除或改色的标签属于该聊天所有者，也会出现在所有者自己的标签列表中。无编辑权限的用户只能看到标签。

### 笔记 {#notes}

除聊天外，文件夹也能存放[笔记](/features/notes)，如项目简报或会议纪要。选择文件夹页面顶部切换控件中的**笔记**，即可列出文件夹内所有人的笔记。可以通过以下两种方式添加。

- 点击文件夹页首切换控件右侧的 **+**，或在侧边栏文件夹的 **⋯** 菜单中选择**新建笔记**。
- 从笔记列表将笔记拖到侧边栏文件夹上，或通过笔记的 **⋯** 菜单中的**移动**选择文件夹。选择**移动 > 无文件夹**可将笔记移出。

添加笔记需要文件夹的写入权限。如果删除文件夹时勾选**删除此文件夹中的所有内容**，也会删除所有者在其中的笔记。其他人的笔记会移出文件夹，并继续归原作者所有。

### 自动化 {#automations}

页首可在**聊天**、**笔记**、**自动化**和**知识库**之间切换。**笔记**仅向具有笔记功能的用户显示。**自动化**仅向具有[自动化](/features/chat-conversations/chat-features/automations)功能的用户显示，其中列出文件夹内的自动化，并提供**新建自动化**按钮。各用户能执行的操作详见自动化页的[文件夹](/features/chat-conversations/chat-features/automations#folders)一节。

### 从标签页重命名 {#renaming-from-the-tab}

双击顶部的文件夹标签页可重命名文件夹。此操作需要文件夹编辑权限。

## 文件夹设置（项目配置） {#folder-settings-project-configuration}

文件夹可以被配置为完整的项目工作区，拥有独立的 AI 行为和上下文。要编辑文件夹设置：

1. 将鼠标悬停在侧边栏中的某个文件夹上
2. 点击**三点菜单**（⋯）
3. 选择 **"编辑"** 打开文件夹设置弹窗

在桌面端，将指针停留在侧边栏中某个文件夹的名称上，会显示该文件夹的预览：其中的对话数量、默认模型以及已附加的知识条目数量；如果该文件夹是与您共享的，还会显示所有者的姓名。拥有写权限时，预览中还会出现 **Edit Folder** 按钮，可打开相同的设置。

![共享的 Product Launch 文件夹的悬停预览：5 个对话，由 Alex Chen 共享，默认模型为 Team Assistant，两个知识条目，以及 Edit Folder 按钮](/images/features/chat/folder-hover-preview.webp)

### 文件夹名称 {#folder-name}

你可以修改文件夹名称，使其更准确地反映用途或项目内容。

### 描述 {#description}

添加一段简短说明，介绍该文件夹的用途。它会显示在文件夹页面的文件夹名称下方，超过两行后被截断。

### 文件夹背景图 {#folder-background-image}

你可以上传背景图来自定义文件夹的视觉外观，从而更直观地区分工作区中的不同项目。

### 默认模型 {#default-model}

选择此文件夹的新聊天使用的模型，也可以保留**使用默认值**来沿用平常的默认模型。在文件夹中的聊天里切换模型不会改变文件夹的默认模型，请在这里修改。

### 默认机器和工作目录 {#default-machine-and-working-directory}

在**高级**下通过**机器**选择文件夹使用的机器。文件夹内的聊天、文件和终端都使用它，并在**工作目录**中启动。留空则使用机器自身的默认目录。如果机器为每个聊天或模型提供独立实例，每个聊天都可以选择其他机器。当你无法使用文件夹的机器时，该文件夹内你自己的聊天会禁用消息输入框。工作目录旁的文件夹按钮可浏览机器上的目录，也可将 [Git 仓库克隆](/features/open-terminal/file-browser#cloning-a-repository)到新目录。选定机器后，**默认模型**也会提供该机器的[智能体](/features/open-terminal/agents)。

### 系统提示词 {#system-prompt}

你可以为文件夹指定专属 **系统提示词**，它会自动应用到该文件夹中的所有对话：

- 该系统提示词会**添加到该文件夹中的每个聊天**，包括之后移入的聊天。它在模型的系统提示词之后、聊天或账户的系统提示词之前发送（[顺序](/features/chat-conversations/chat-features/chat-params#how-system-prompts-combine)）。
- 这可让 AI 针对特定任务或 persona 采取定制行为
- 系统提示词是可选的；即使不设置，文件夹仍可纯粹用于组织

:::info

只有当你拥有设置系统提示词的权限时（由管理员设置控制），系统提示词字段才会显示。

:::

### 附加知识 {#attached-knowledge}

文件夹页面还设有**知识**部分，列出该文件夹中新建聊天所使用的知识。

在文件夹的 **Knowledge** 字段（位于**高级**选项下）附加**知识库、笔记和文件**，使用的选择器与模型编辑器相同（参见[附加知识与笔记](/features/workspace/knowledge#attaching-knowledge-and-notes)）：

- 文件夹中的每个聊天都会使用这些内容，同时[知识工具只能访问已附加的条目](/features/workspace/knowledge#scoped-access-keeps-things-organized)。
- 使用 **Native** 函数调用时，模型会拿到该文件夹的知识列表，并通过 **Knowledge Base** [内置工具](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)读取它们，无论 **Preload files** 是开是关。使用 **Legacy** 函数调用时，则会在 **Preload files** 开启的情况下通过 RAG（Retrieval Augmented Generation）检索并注入。
- 附加知识是可选的。不附加文件也可以用文件夹整理聊天。
- **把文件夹附加到另一个聊天。** 文件夹会列在 `#` 菜单中，你也可以从侧边栏把它拖进消息输入框。这会附加该文件夹所链接的文件与知识库，且仅在 **Preload files** 开启时生效。关闭 Preload files 时，请直接用 `#` 附加该文件夹的知识库和文件，或者在文件夹内部发起聊天。

**谁的访问权限决定哪些内容能够附加。** 附加时，你和**文件夹所有者**都必须有访问权限。随后，文件夹中的每个聊天都遵循所有者的访问权限。

- 向文件夹附加某个文件、知识库或笔记，要求附加者本人和所有者都能读取它。因此，某个共享文件夹的写入权限持有者，无法把其所有者本人打不开的文档（包括他们自己的私有文档）附加进去，也无法附加他们自己打不开的文档。同样的检查也适用于在共享文件夹内创建的子文件夹——它归属于父文件夹的所有者。
- 文件夹中的每个聊天在使用这些附件之前，都会依据所有者当前的访问权限重新检查一遍。如果所有者在附加之后失去了某个知识库的访问权限，该知识库就不再用于该文件夹的聊天。
- 不是文件、知识库或笔记的条目，或者没有携带 ID 的条目，都会被忽略。

## 共享文件夹 {#sharing-folders}

把一个文件夹连同其中的对话共享给特定的用户或用户组，让团队可以基于同一批对话协同工作。

共享文件夹需要 **Folders Sharing** 权限，该权限默认关闭。管理员可以在 **Admin Panel > Users > Groups** 下开启，或者通过 [`USER_PERMISSIONS_FOLDERS_ALLOW_SHARING`](/reference/env-configuration#user_permissions_folders_allow_sharing) 开启。

1. 从侧边栏或文件夹页面打开文件夹的**三点菜单**（⋯），选择**共享**，即可打开该文件夹的 **Access** 对话框。管理员和拥有 **Folders Sharing** 权限的文件夹所有者可以看到此入口。**Edit Folder** 对话框顶部的 **Access** 按钮也会打开同一个对话框。
2. 添加要共享给的用户或用户组。每一项初始都是**写入**，可按需在**访问列表**的对应行切换为**读取**：
   - **Read**：他们可以打开该文件夹并阅读其中的对话。他们不能在其中发起对话，也不能把对话移入其中；在侧边栏把对话拖到它上面时，也不会出现可放置目标。
   - **Write**：他们还可以重命名文件夹、在其中发起对话、把自己的对话移入其中，并在其中创建子文件夹。当他们在侧边栏把对话拖到它上面时，它会高亮并接收该对话。
3. 选择 **Sharing mode**。你可在授予任何人访问权限之前设置好共享方式，方便之后添加成员：
   - **Clone only**（默认）：共享对象可以阅读文件夹中的对话，也可以克隆其中一段对话后自行继续。
   - **允许回复**：拥有文件夹**写入**权限的用户可以向直接位于其中的聊天发送消息。这些聊天的行为与[允许回复的共享聊天](/features/chat-conversations/chat-features/chatshare#allowing-replies)相同。只有**读取**权限的用户可以阅读和克隆聊天，和**仅克隆**模式一样。子文件夹中的聊天采用该子文件夹的共享模式，在子文件夹自己的**访问权限**对话框中设置。设置之前，它们以只读方式打开。

每一项更改都会在你做出后立即生效。


只有文件夹的所有者或管理员才能更改文件夹的共享对象和共享模式。拥有写入权限的人不会在 **Edit Folder** 对话框中看到 **Access** 按钮。

**Add Access** 选择器只列出尚未与该文件夹共享的人员和用户组，因此你无法把同一个人添加两次，列表也会随着你的操作不断变短。若要在 **Read** 和 **Write** 之间切换某人，或完全移除他，请改用 **Access List** 中他所在的那一行。

共享文件夹会出现在接收方的侧边栏中。有几条规则需要了解：

- **子文件夹会继承共享。** 在某个文件夹上授予的访问权限会向下传递到其中嵌套的一切。当某人在子文件夹上继承到 **Write**、同时又有直接授予的 **Read** 时，以 **Write** 为准。共享模式按文件夹分别生效，因此在子文件夹的对话中回复，需要该子文件夹自身开启 **Allow replies**。
- **别人的聊天以对方的名义打开。** 在设为**仅克隆**的文件夹中，这些聊天只读。如果已开启**允许回复**，且你拥有该文件夹的**写入**权限，则打开聊天时会显示消息输入框，可以向其中写入。聊天中和**概览**标签页的消息节点上，每条消息都会显示发送者的姓名和头像。
- **文件夹的所有者可以整理别人的对话。** 在你拥有的文件夹中，你可以重命名别人发起的对话（仅标题），并把它们移动到同一共享树中的其他文件夹。
- **共同编辑并重新生成。** 开启**允许回复**后，拥有**写入**权限的人可以编辑任意提示词并创建新分支，也可以重新生成任意回复，和[允许回复的共享聊天](/features/chat-conversations/chat-features/chatshare#allowing-replies)相同。
- **每个聊天都会显示参与者。** 对于共享文件夹，侧边栏及文件夹页面中的每个聊天都会显示发过消息的人的头像，聊天所有者排在第一位。最多显示三个头像，之后显示计数，例如 **+2**。点击计数可查看所有人，将指针悬停在头像上或点击头像可打开用户资料卡。
- **共享文件夹中的对话可以作为上下文附加。** 把其中一个从侧边栏拖进另一个聊天的消息输入框，模型就会收到那段对话的消息，与你自己拥有的对话一样。只要对该文件夹有读权限即可——无论它是直接授予的，还是从上层文件夹继承而来的。
- **归档对话会把对话移出该文件夹。** 那些只能通过该文件夹看到它的人将失去访问权限。
- **只有所有者或管理员才能删除共享的根文件夹。** 拥有写入权限的人可以添加和编辑对话与子文件夹。
- **写入权限也适用于文件夹页面。** 拥有写入权限的人可以设置文件夹中每个聊天的状态和优先级，以及修改文件夹的状态选项。拥有读取权限的人可以查看这些状态。参见[文件夹页面](#the-folder-page)。
- **自动化可向共享文件夹发布聊天。** 有写入权限的人可在其中创建或暂停自动化。见自动化页面的[文件夹](/features/chat-conversations/chat-features/automations#folders)一节。
- **克隆聊天以自行继续。** 在设为**仅克隆**的文件夹中，或只有**读取**权限时，可使用**克隆聊天**或**分叉聊天**在自己的聊天中继续。参见[克隆或分叉共享聊天](/features/chat-conversations/chat-features/chatshare#cloning-or-forking-a-shared-chat)。
- **文件夹不能公开共享**，管理员也不能。共享始终只针对特定的用户或用户组。

## 示例用例 {#example-use-case}

:::tip **创建一个 “Python Expert” 项目**

假设你正在进行一个 Python 开发项目：

1. **创建一个文件夹**，命名为 "Python Expert"
2. **编辑该文件夹**，并设置系统提示词：
   ```
   You are an expert Python developer. You provide clean, efficient, and well-documented code. When asked for code, prioritize clarity and adherence to PEP 8 standards.
   ```

3. **附加知识**：在文件夹的 **Knowledge** 字段中添加你项目的技术规格 PDF 或库文档
4. **点击该文件夹**，将其设为当前激活工作区
5. **开始聊天** —— 每个新对话都会自动具备：
   - Python 专家角色
   - 访问项目文档的能力
   - 自动归档到该文件夹中

:::

## 标签（补充性组织方式） {#tags-complementary-organization}

除文件夹外，**标签**也提供了一种灵活的对话标记方式：

- **添加标签**：根据内容或用途，为对话添加关键词标签
- **按标签搜索**：在搜索窗口中输入 `tag:<name>` 可列出带该标签的对话，输入 `tag:none` 则列出不带标签的对话。参见[筛选结果](/features/chat-conversations/chat-features/history-search#filtering-results)。
- **灵活组织**：标签可随时添加或移除，且不会影响文件夹结构
- **颜色和文件夹视图**：标签可以设置颜色，文件夹页面可按标签对聊天分组、筛选和布局。见[文件夹页面中的标签](#tags)。
- **自动标签**：任务模型可以替你为对话打标签。你可以在 **设置 > 界面** 中通过 **Chat Tags Auto-Generation** 为自己关闭这一功能。只有当管理员开启了 **Tags Generation** 时，该开关才会显示。

:::tip **按主题打标签**

如果你经常讨论“marketing”或“development”等主题，可以用这些词给对话打标签。这样当你搜索某个标签时，无论这些对话位于哪个文件夹，都能被快速找到。

:::

# 自动化 {#automations}

自动化可以定期自动运行提示词。默认情况下，每次运行都会创建一个聊天，并走常规聊天补全流程，因此模型默认值、工具、过滤器和其他流程行为仍然适用。

运行与你的聊天使用相同的方式使用[记忆](/features/chat-conversations/memory)。当你的记忆已开启时，一次运行会获得记忆工具；开启 **Memory System Context** 后，你已存储的记忆也会进入其上下文，所用的模型、权限与管理员设置与聊天完全一致。记忆是否开启取决于你在 **Settings > Personalization** 中的 **记忆** 开关；如果你从未设置过它，则由[默认界面设置](/features/administration/interface-defaults)决定，而在连默认界面设置也没有的情况下，则取决于实例是否启用了 Memories。

管理员可通过 [`ENABLE_AUTOMATIONS`](/reference/env-configuration#enable_automations) 环境变量，或 **Settings > General**（管理员区域） 中的开关，在全局启用或禁用自动化。禁用后，自动化 worker 会停止处理任务，API 端点会返回 `403`，侧边栏入口也会隐藏。

## 你可以自动化什么 {#what-you-can-automate}

- 按计划执行提示词（每小时、每天、每周、每月或自定义 RRULE）
- 使用 [webhook](#webhooks) URL 从其他服务启动运行，并可传入文本
- 与用户和用户组[共享](#sharing)自动化，让他们跟进运行情况
- 点击**立即运行**手动触发运行
- 在不删除的情况下暂停 / 恢复自动化任务
- 查看每个自动化任务的执行历史
- 可以选择将计划生成的聊天归入你有权编辑的[文件夹](/features/chat-conversations/chat-features/conversation-organization#the-folder-page)，包括共享文件夹，让团队在同一处查看每次运行的结果
- 为运行指定机器和工作目录，并从该机器运行[智能体](/features/open-terminal/agents)

## 访问控制 {#access-control}

对于非管理员用户，Automations 受权限控制。

- **管理员**：始终拥有自动化访问权限
- **用户**：需要具备 **Features > Automations** 权限

每次运行均使用创建者的账户，因此由创建者决定自动化执行的操作。管理员可以打开所有自动化。其他用户可以通过[共享](#sharing)或共享[文件夹](#folders)访问自动化，未共享给他们的自动化仍不可见。**功能 > 自动化**权限决定用户能否使用自动化。

管理员无法在界面中暂停或删除其他用户的自动化。要停止某个用户的自动化，把其角色设为 **Pending**，或移除其 **Features > Automations** 权限。此后每次运行都会以失败结束，并提示 `Owner no longer permitted to run automations`，而调度仍会继续推进，因此角色或权限恢复后运行会重新开始。

权限分类请参阅 [RBAC Permissions](/features/authentication-access/rbac/permissions#4-features-permissions)。

若要授予用户访问权限：

1. 打开 **Admin Panel > Users > Groups**
2. 编辑 **Default permissions** 或某个具体用户组
3. 启用 **Features > Automations**

你也可以通过 [`USER_PERMISSIONS_FEATURES_AUTOMATIONS`](/reference/env-configuration#user_permissions_features_automations) 设置默认值。

:::tip 快速访问
在 User Menu 中按住 **Shift** 可显示固定 / 取消固定按钮。将 Automations 固定后，会在侧边栏栏位中显示快捷图标，便于一键进入。
:::

## 管理员限制 {#admin-limits}

管理员可以通过环境变量为非管理员用户设置全局自动化用量限制。**自动化数量和运行间隔限制不适用于管理员。**

| 设置 | 效果 | 环境变量 |
| --- | --- | --- |
| **最大自动化数量** | 限制用户可创建的自动化数量 | [`AUTOMATION_MAX_COUNT`](/reference/env-configuration#automation_max_count) |
| **最小重复间隔** | 拒绝执行频率高于设定间隔（秒）的计划 | [`AUTOMATION_MIN_INTERVAL`](/reference/env-configuration#automation_min_interval) |
| **最大并发运行数** | 限制每个服务器进程可同时执行的自动化运行数。超出的运行会等待空位。修改后需要重启 | [`AUTOMATION_MAX_CONCURRENT`](/reference/env-configuration#automation_max_concurrent) |

- **Max count** 仅在创建时检查；若后续下调限制，不会删除现有自动化任务。
- **Min interval** 会在创建和更新时都进行检查；一次性自动化（`COUNT=1`）不受此限制。
- 三项默认均为空（无限制）。设为正整数即可启用限制。最大并发运行数也适用于管理员。

## 创建一个自动化任务 {#create-an-automation}

1. 打开 **User Menu > Automations**
2. 点击 **New Automation**
3. 设置：
   - **Title**
   - **Instructions**（提示词）
   - **Model**
   - **计划**，或选择**无**，让自动化仅在点击**立即运行**或调用其 [webhook](#webhooks) 时运行
4. （可选）为自动化生成的聊天选择 **Folder**。选择器仅列出你自己的文件夹。要向共享文件夹发布聊天，请从该文件夹页面创建自动化（见[文件夹](#folders)）
5. 点击 **Create**

创建后，Open WebUI 会自动打开该自动化任务的专属编辑页：`/automations/{id}`。

### 运行使用的模型设置 {#model-settings-used-by-a-run}

对于由 Ollama 或 OpenAI 兼容连接提供的模型，运行会使用模型的**系统提示词**和**高级参数**。在**指令**中输入你希望模型执行的任务。自动化编辑器没有**模型控件**选择器。运行会使用模型的[默认选项](/features/workspace/models#model-controls)，点击**立即运行**时也是如此。

模型的**默认功能**可为运行启用 Web 搜索、图像生成或视频生成，前提是对应的能力和实例设置都已启用。**默认功能**中的**代码解释器**开关仅适用于交互式聊天。

### 聊天标题 {#chat-titles}

当运行创建聊天时，初始标题是自动化保存的**标题**。像 `{{CURRENT_DATE}}` 这样的提示词变量在**指令**中会展开，在**标题**中会以原文显示。

### 为运行指定机器 {#giving-a-run-a-machine}

自动化编辑器提供**机器**列表。选定机器后，会显示**工作目录**字段。运行会使用该机器并从该目录启动。字段留空时，从机器的默认目录启动。至少有一台机器可供你使用时才会显示列表，在此选择的机器会覆盖模型配置的机器。

如果编辑器中未指定机器，运行会使用模型配置的机器。要配置它，请在**工作区 > 模型**中编辑模型，从**默认机器**字段中进行选择。至少有一台机器可用，且模型的**终端**能力已开启时，才会显示此列表。该能力默认开启。

:::info 自动化中的终端限制
机器的用法以及频道自动化的限制，见[创建机器](/features/open-terminal/terminals/orchestration/creating-terminals#machine-scope)。
:::

### 运行智能体 {#running-a-coding-agent}

选定机器后，**模型**列表还会显示该机器报告的智能体，名称格式为 `<agent>/<model>`。更换机器或目录会重新加载列表，**创建**和**保存**会等待列表加载。智能体自动化必须指定机器才能保存，其结果始终发送到聊天。每次运行前，Open WebUI 都会检查机器和智能体是否仍然可用，任一不可用都会导致运行失败。

## 编辑与管理 {#edit-and-manage}

在 Automations 列表中点击某个任务，即可进入其专属编辑页。

页面本身就是编辑器。顶部是名称和指令，其下方的**属性**列表包含**状态**、**计划**、**模型**、**目标**、**机器**和**下次运行**。点击任意值即可就地修改。一旦设置与已保存的自动化有差异，页首就会出现**保存**按钮。**状态**开关会立即暂停或恢复自动化，无需点击**保存**。

页眉还提供**立即运行**、**复制链接**及**更多**菜单，其中包含**复制**和**删除**。点击**复制**会打开新建自动化表单，预填相同设置并在名称后加上“(Copy)”。点击**创建**才会保存。

属性下方的**活动**按时间从新到旧列出运行记录，标注**已运行**或**失败**及其时间。点击某条运行记录即可打开对应聊天。滚动时会逐步加载更多记录。

**目标**菜单中的**每次运行都创建新聊天**开关（对于频道为**每次运行都创建新线程**）默认开启。关闭后，每次运行都会接续同一个聊天或频道线程，因此可以读取之前的运行内容。

对于频道，**在线程中回复**开关（默认开启）决定模型在哪里回复。开启后，每次运行会将提示词发布为频道消息，并在线程中回复该消息。关闭后，每次运行会将提示词和答案都作为普通的顶层频道消息发布，不创建线程。

### 快速删除 {#quick-delete}

在自动化列表打开时按住 **Shift**，每个自动化的菜单按钮和开关都会变成删除按钮。点击它会立即删除该自动化，不会再询问。松开 **Shift** 后菜单和开关会恢复。从菜单中删除仍然需要你确认。当用 `Tab` 键到达的按钮或链接处于焦点状态时，按住 **Shift** 不会把菜单按钮和开关变成删除按钮，因此 `Shift+Tab` 仍会照常在列表中向后移动。

## 导出与导入 {#export-and-import}

自动化列表页头有一个分裂式 **创建** 按钮。其下拉菜单中包含 **导入 JSON** 和 **导出 JSON**，用于在实例或账户之间迁移自动化。

**导出 JSON** 会将你拥有的每个自动化下载为 `automations-export-<timestamp>.json`，无论搜索框或状态过滤器如何设置。每个条目都保留其名称、计划和其他设置、文件夹归属以及启用状态。ID、时间戳和运行历史不会写入文件，因此导出是定义的副本，而不是运行历史的备份。

**导入 JSON** 接受一个 `.json` 文件，其中可以是一个自动化数组，也可以是一个带有 `automations` 键的对象。其他格式会被当作无效 JSON 格式拒绝。

导入会做什么、不会做什么：

- 每个条目都会变成一个**全新**的自动化。导入时不会与你已有的自动化做匹配，因此把同一个文件导入两次会留下重复项。
- 除非文件把 `is_active` 设为 `false`，条目默认以**启用**状态创建。因此导入可能立刻在目标实例上启动计划运行；如果这不是你想要的，请先禁用它们。
- 只有当你自己的账户中存在相同 ID 的文件夹时才会保留文件夹，否则该字段会被丢弃，导入的自动化不带文件夹。
- 每个条目都走正常的创建流程，因此计划校验和[管理员限制](#admin-limits)依然生效。一旦某个条目被拒绝（例如无效的 `RRULE` 或触发 [`AUTOMATION_MAX_COUNT`](/reference/env-configuration#automation_max_count)），导入的其余部分就会中止；在此之前已创建的条目会保留。

## 文件夹 {#folders}

自动化可以将聊天发布到文件夹，让定期报告或摘要与同主题的其他工作集中在一起。文件夹的未读徽标会显示尚未阅读的运行次数。在编辑器的**目标位置**中设置此项。选择**新聊天**会将聊天留在未分组列表中，选择**文件夹**会列出你自己的文件夹，选择**频道**则会发布到频道中（参见[频道](#channels)）。

文件夹页面集中展示其中的自动化。通过页首的切换控件选择**自动化**即可打开，仅对拥有自动化权限的用户可见。**自动化**区域列出文件夹内的自动化及其计划、上次运行日期（或**已暂停**、**尚未运行**）和开关。**新建自动化**按钮会创建在此文件夹中启动的自动化。自动化生成的聊天在文件夹列表和看板中带有小钟图标。

- 自动化可向创建者有权编辑的任何文件夹发布聊天，包括共享文件夹。请从共享文件夹页面创建自动化。**目标位置**选择器仅列出你自己的文件夹。
- 所有拥有文件夹访问权限的人都能在列表中查看该自动化并阅读其运行结果，包括只有读取权限的人。能编辑文件夹的人还可以运行、暂停自动化，修改其名称和计划。其他设置及删除权限仍归创建者。
- 只要创建者仍有权编辑该文件夹，运行结果就会继续出现在该文件夹中。如果失去该权限，下次运行将清除文件夹设置，并在文件夹之外创建聊天，自动化仍会继续运行。
- 文件夹是聊天的归档位置。该文件夹的系统提示词和附加知识同样适用于这些聊天。
- 清除文件夹只是一项普通编辑。以后创建的聊天会回到未分组列表，已创建的聊天留在原处。
- 删除文件夹不会删除以其为目标位置的自动化。自动化会清除文件夹设置并继续运行。
- 导入的自动化只有在你的账户中存在相同 ID 的文件夹时才保留其文件夹，否则导入时不带文件夹。

## 自动化 Webhook {#webhooks}

Webhook 为自动化提供一个 URL。调用它就会启动运行，因此 CI 任务、监控告警或 Git 托管平台无须等待计划即可触发自动化。一个自动化可以使用计划、Webhook 或两者兼用。如果两者都没有，只会在点击**立即运行**时运行。

要添加 Webhook，请打开自动化，开启 **Webhook** 并点击**保存**。保存后会显示 URL。**重新生成**会创建新 URL 并使旧 URL 失效。URL 泄露时可使用此功能。只有创建者能查看 URL 和重新生成它。

- **本次运行使用的文本。** 在指令中放入 `{{name}}` 形式的占位符，例如 `Summarize this alert: {{message}}`。URL 查询参数或 JSON 正文中同名的字段会填入占位符。正文也可以包含 `variables` 对象，GitHub 或 Gitea 等服务发送的正文可直接读取。占位符可像其他[提示词](/features/workspace/prompts)一样指定默认值和类型。如果缺少必填值、类型不匹配或正文不是 JSON 对象，则返回 `400`，且不会开始运行。
- **允许 GET。** 默认支持 `POST`。对只能打开链接的服务，可开启**允许 GET**以接受 `GET`。关闭时，`GET` 调用会收到 `405`。
- **限制。** 正文超过 64 KB 时返回 `413`。每项自动化每分钟可接收 30 次调用，超出后返回 `429`。已暂停的自动化返回 `409`。调用成功返回 `202`。

:::warning 任何拥有 URL 的人都能启动自动化
URL 本身就是凭据，只应共享给确实需要它的服务。调用不需要登录，持有 URL 的人可以用创建者的账户启动运行，并决定提示词包含哪些文本。只有在自动化的指令可以安全地处理不受信任的文本时，才应创建 Webhook。
:::

管理员可以在**管理设置 > 常规**中使用**自动化 Webhook**，或用 [`ENABLE_AUTOMATION_WEBHOOKS`](/reference/env-configuration#enable_automation_webhooks) 控制 Webhook（默认开启）。关闭后，已有地址会失效。创建 Webhook 需要管理员权限或**功能 > 自动化**权限。如果创建者失去该权限，Webhook 会失效。

## 共享 {#sharing}

可以将自动化共享给指定用户和用户组，让团队成员跟进同一份报告，无需每人各建一项。使用自动化页首的**共享**并选择用户和用户组，操作与其他[共享项目](/features/authentication-access/rbac/permissions#2-sharing-permissions)相同。非管理员用户需要**共享自动化**权限才能共享。

- **读取**允许打开自动化、查看计划，以及阅读运行所创建的聊天。自动化列表的**与我共享**选项卡显示直接与你共享的自动化。
- **写入**还允许运行和暂停自动化，以及更改名称和计划。
- 只有创建者能修改指令、模型、目标和 Webhook，因为运行始终使用创建者的账户。创建者和管理员可以共享和删除自动化。

共享文件夹中的自动化遵循文件夹的访问权限（参见[文件夹](#folders)）。

## 频道 {#channels}

当**目标位置**设为**频道**时，运行会把内容发布到某个[频道](/features/channels)，而不是创建聊天。该列表会显示你的频道，不含私信。

- 保存需要标准频道的写入权限，或群组频道的成员身份。非管理员用户还需要**频道**权限。
- 每次运行都会把指令以你的身份发布为频道中的一条消息。模型的回复会进入该消息下的线程；当管理员的 **Model Response Mode** 设为 **Channel** 时，回复会进入时间线。
- 模型只会收到指令，不会收到频道中更早的消息。
- 在**活动**中点击某条运行记录会打开该频道。
- 智能体自动化需要以聊天为目标。如果选择**频道**并保存，系统会拒绝并显示 `Agent automations require a chat destination.`。如果机器来自模板，则显示 `This machine requires a chat destination.`。仅限聊天使用的模板机器也会显示后一条消息。
- 当实例关闭频道功能时，运行会以 `Channel not found` 失败；当创建者失去**频道**权限时，会以 `Owner no longer permitted to use channels` 失败。

## 调度 {#scheduling}

支持的计划模式包括：

- **一次**
- **每小时**
- **每天**
- **每周**
- **每月**
- **自定义**（`RRULE`）

**每天**、**每周**和**每月**会在你的账户所保存时区中的指定时间运行。登录或在已登录状态下重新加载应用时，Open WebUI 会从浏览器读取时区。如果服务器没有此账户的有效时区，就使用服务器自己的本地时区。

如果计划的时间不对，请检查设备时区，然后重新加载 Open WebUI 以同步时区。修改自动化并点击**保存**，即可用更新后的时区重新计算下次运行时间。

自定义计划支持标准 RRULE 语法。无效或已耗尽的规则会被拒绝。

要每天运行两次，请选择**计划 > 自定义**，并输入 `RRULE:FREQ=DAILY;BYHOUR=8,16;BYMINUTE=0`，即可在计划时区的 08:00 和 16:00 运行。

在 Open WebUI 0.13.4 中，重新打开此计划时可能显示**每天**，并且只显示第一个时间。保持**计划**不动并保存对其他字段的编辑，会保留已存的规则。如果修改**每天**中的时间，保存后会将原规则替换为每天只运行一次的计划。要更改包含多个时间的规则，请选择**自定义**并重新输入完整规则，再点击**保存**。

关于自定义规则如何被解析，有几点需要注意：

- **间隔短于一天的规则会按时钟对齐。** 没有 `DTSTART` 的 `SECONDLY`、`MINUTELY` 或 `HOURLY` 规则以时钟为锚点，因此“每 5 分钟”指的是 `:00`、`:05`、`:10`，而不是从你保存的那一刻起算的五分钟。
- **`DTSTART` 在仍然有意义的地方会被采纳。** 给出起始时间后，计划会从那里开始计数，并保留你指定的运行节奏。如果该起点早到按字面执行需要推算超过 100,000 次运行才能到达当前时间，规则会退回到时钟对齐，而不是卡住。
- **`INTERVAL` 必须是正整数。** 零或负值会被拒绝，而不是悄悄按 1 处理。
- **每个计划只允许一条规则。** 多条 `RRULE` 会被拒绝，也完全不支持 `EXRULE`；请把排除条件写进规则本身。
- 属性名不区分大小写，因此 `freq=daily` 与 `FREQ=DAILY` 行为一致。

## 说明 {#notes}

- 自动化任务在后台 worker loop 中按轮询间隔执行。
- 每次执行都会记录状态（`success` 或 `error`）以及可选的错误详情。在聊天中回复的运行在回复完成后记为 `success`；回复失败或被取消则记为 `error`，同时运行会保留 **View chat** 链接，方便你打开对应聊天。
- 若想在运行失败时收到通知，把[通知目标](/features/chat-conversations/chat-features/notifications#events)订阅到 `automation.run_failed`。
- 删除自动化任务时，也会同时删除其运行历史。

## 在对话中管理自动化 {#managing-automations-from-chat}

在使用 **原生函数调用模式** 且模型能力足够时，也可以直接在对话中通过内置工具创建和管理自动化。这样你只需说出诸如 *“每天早上 9 点安排一份摘要报告”* 之类的话，模型就会为你创建该自动化。

### 可用工具 {#available-tools}

| 工具 | 作用 |
| --- | --- |
| `create_automation` | 使用名称、提示词和 RRULE 计划创建一个新的定时自动化，并可选择为其聊天指定文件夹。使用当前对话模型。 |
| `update_automation` | 更新现有自动化的名称、提示词、计划、模型或文件夹 |
| `list_automations` | 列出你的定时自动化，包含状态、文件夹、计划和下次运行 |
| `toggle_automation` | 暂停或恢复某个定时自动化 |
| `delete_automation` | 删除定时自动化及其全部运行历史 |

### 使用要求 {#requirements}

若想在聊天中使用自动化工具，需要满足以下条件：

1. 该模型必须启用 **Native Function Calling**
2. 该模型必须启用 **Builtin Tools** 能力
3. 模型的 Builtin Tools 设置中必须启用 **Automations** 分类（默认开启）
4. 全局必须启用 **`ENABLE_AUTOMATIONS`**（默认开启）
5. 当前用户必须具备 **Features > Automations** 权限（管理员始终通过）

这些工具接受的 folder 参数是一个文件夹 ID，并会与你拥有的文件夹进行校验：不属于你的文件夹或已不存在的文件夹会返回错误，而不会被应用。

- 在 `update_automation` 中，省略该参数或传入空字符串会保留自动化当前的文件夹；传入 `null` 则清除它。`model_id` 同理：空值会被忽略，而不会清空自动化的模型。
- 在 `list_automations` 中，省略该参数或传入空字符串会跨所有文件夹列出。

有关所有 builtin tools 的完整说明，请参阅 [Builtin Tools reference](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)。

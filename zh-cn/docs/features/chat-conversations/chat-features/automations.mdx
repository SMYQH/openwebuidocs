# 自动化 {#automations}

Automations 允许你按周期自动执行提示词。每次执行都会创建一个聊天，并走完整的聊天完成流程，因此模型默认值、工具、过滤器以及其他 Pipeline 行为仍然全部生效。

管理员可通过 [`ENABLE_AUTOMATIONS`](/reference/env-configuration#enable_automations) 环境变量，或 **Admin Panel > Settings > General** 中的开关，在全局启用或禁用自动化。禁用后，自动化 worker 会停止处理任务，API endpoint 会返回 `403`，侧边栏入口也会隐藏。

## 你可以自动化什么 {#what-you-can-automate}

- 按计划执行提示词（每小时、每天、每周、每月或自定义 RRULE）
- 通过 **立即运行** 手动触发一次执行
- 在不删除的情况下暂停 / 恢复自动化任务
- 查看每个自动化任务的执行历史
- 可选地为任务附加 terminal server 和工作目录，以便执行需要终端上下文的任务

## 访问控制 {#access-control}

对于非管理员用户，Automations 受权限控制。

- **Admins**：始终拥有自动化访问权限
- **Users**：需要具备 **Features > Automations** 权限

权限分类请参阅 [RBAC Permissions](/features/authentication-access/rbac/permissions#4-features-permissions)。

若要授予用户访问权限：

1. 打开 **Admin Panel > Users > Groups**
2. 编辑 **Default permissions** 或某个具体用户组
3. 启用 **Features > Automations**

你也可以通过 [`USER_PERMISSIONS_FEATURES_AUTOMATIONS`](/reference/env-configuration#user_permissions_features_automations) 设置默认值。

:::tip 快速访问
在 User Menu 中按住 **Shift** 可显示固定 / 取消固定按钮。将 Automations 固定后，会在侧边栏栏位中显示快捷图标，便于一键进入。
:::

### 快速删除

在自动化列表打开时按住 **Shift**，每个自动化的菜单按钮和开关都会变成删除按钮。点击它会立即删除该自动化，不会再询问。松开 **Shift** 后菜单和开关会恢复。从菜单中删除仍然需要你确认。

## 管理员限制 {#admin-limits}

管理员可以为非管理员用户设置全局自动化使用限制。这些限制通过环境变量配置。**管理员不会受到这些限制。**

| 设置 | 效果 | 环境变量 |
| --- | --- | --- |
| **最大自动化数量** | 限制用户可创建的自动化数量 | [`AUTOMATION_MAX_COUNT`](/reference/env-configuration#automation_max_count) |
| **最小重复间隔** | 拒绝执行频率高于设定间隔（秒）的计划 | [`AUTOMATION_MIN_INTERVAL`](/reference/env-configuration#automation_min_interval) |

- **Max count** 仅在创建时检查；若后续下调限制，不会删除现有自动化任务
- **Min interval** 会在创建和更新时都进行检查；一次性自动化（`COUNT=1`）不受此限制
- 两者默认都为空（即不限制）；如需强制执行，请设置为正整数

## 创建一个自动化任务 {#create-an-automation}

1. 打开 **User Menu > Automations**
2. 点击 **New Automation**
3. 设置：
   - **Title**
   - **Instructions**（提示词）
   - **Model**
   - **Schedule**
4. （可选）选择 **Terminal** server 和 **Working Directory**
5. 点击 **Create**

创建后，Open WebUI 会自动打开该自动化任务的专属编辑页：`/automations/{id}`。

### 运行编码智能体 {#giving-a-run-a-terminal}

选定终端后，**模型**列表还会提供该终端报告的编码智能体，名称格式为 `<智能体>/<模型>`。更换终端或文件夹会重新加载该列表，**创建**和**保存**会等待加载完成。智能体自动化需要先有终端才能保存。它的结果始终会进入某个聊天。每次运行前，Open WebUI 都会检查终端和智能体是否仍然可用，任意一个消失都会导致运行失败。

### 运行编码智能体 {#running-a-coding-agent}

选定终端后，**模型** 列表还会提供该终端报告的编码智能体，名称形如 `<agent>/<model>`。更改终端或文件夹会重新加载该列表，而 **创建** 和 **保存** 会等待其加载完成。智能体自动化需要先有终端才能保存。其结果始终会进入某个对话。每次运行前，Open WebUI 都会检查终端和智能体是否仍然可用，若其中之一已消失则运行失败。

## 编辑与管理 {#edit-and-manage}

在 Automations 列表中点击某个任务，即可进入其专属编辑页。

在编辑页中，你可以：

- 更新标题、说明、模型、计划和 terminal 设置
- 保存变更
- 通过 **立即运行** 立即执行
- 暂停 / 恢复自动化状态
- 删除自动化任务
- 查看执行日志并打开对应运行聊天

编辑页中的执行日志采用无限滚动分页，因此即使运行历史很长，也会按需逐步加载。

### 文件夹 {#quick-delete}

自动化可以被指定一个文件夹，此后它创建的每个聊天都会归档到该文件夹中，而不是散落在聊天列表里。这可以把周期性的报告或摘要放到一边，也让你通过文件夹的未读徽标看到还有多少次运行尚未阅读。

- 只能选择你自己的文件夹。与你共享的文件夹属于他人，不会出现在选项中；强行填写一个文件夹名也会像填写未知文件夹一样被拒绝。
- 文件夹是归档目的地，而不是项目上下文：聊天会被放入该文件夹，而文件夹的系统提示词和附加知识库对它照常生效，就像对该文件夹中的任何其它聊天一样。
- 自动化列表可以通过 API 和聊天工具按文件夹筛选；列表页面本身不会标注或按文件夹过滤。不带文件夹或带空文件夹请求该列表时，会返回你拥有的全部自动化，无论它们各自归档在哪个文件夹。
- 清除文件夹属于一次普通编辑。自动化会继续运行，它创建的聊天会回到未分组列表；已经创建的聊天仍留在原处。
- 删除文件夹不会删除指向它的自动化。它们会失去该文件夹并继续运行。两次运行之间文件夹消失时也是同样情况：运行会发现这一点，清除该设置，并在任何文件夹之外创建其聊天，而不是失败。
- 导入的自动化只有在你的账户中存在相同 ID 的文件夹时才保留其文件夹，否则导入时不带文件夹。

## 调度方式 {#export-and-import}

支持的计划模式包括：

- **一次**
- **每小时**
- **每天**
- **每周**
- **每月**
- **自定义**（`RRULE`）

自定义计划支持标准 RRULE 语法。无效或已耗尽的规则会被拒绝。

## 说明 {#folders}

- 自动化任务在后台 worker loop 中按轮询间隔执行
- 每次执行都会记录状态（`success` 或 `error`）以及可选错误详情
- 删除自动化任务时，也会同时删除其运行历史

## 在聊天中管理 Automations {#scheduling}

当你使用支持 **Native Function Calling Mode** 的模型时，也可以通过内置工具，直接在聊天里创建和管理自动化任务。比如你可以直接说：*"Schedule a daily summary report at 9am"*，模型就会替你创建相应自动化任务。

## 在对话中管理自动化 {#managing-automations-from-chat}

在使用 **原生函数调用模式** 且模型能力足够时，也可以直接在对话中通过内置工具创建和管理自动化。这样你只需说出诸如“每天早上 9 点安排一份摘要报告”之类的话，模型就会为你创建该自动化。

### 可用工具 {#available-tools}

| 工具 | 作用 |
| --- | --- |
| `create_automation` | 使用名称、提示词和 RRULE 计划创建一个新的自动化任务；使用当前聊天模型 |
| `update_automation` | 更新现有自动化任务的名称、提示词、计划或模型 |
| `list_automations` | 列出你当前的自动化任务，包括状态、计划和下次运行时间 |
| `toggle_automation` | 暂停或恢复某个自动化任务 |
| `delete_automation` | 删除自动化任务及其全部运行历史 |

### 使用要求 {#requirements}

若想在聊天中使用自动化工具，需要满足以下条件：

1. 该模型必须启用 **Native Function Calling**
2. 该模型必须启用 **Builtin Tools** 能力
3. 模型的 Builtin Tools 设置中必须启用 **Automations** 分类（默认开启）
4. 全局必须启用 **`ENABLE_AUTOMATIONS`**（默认开启）
5. 当前用户必须具备 **Features > Automations** 权限（管理员始终通过）

有关所有 builtin tools 的完整说明，请参阅 [Builtin Tools reference](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)。

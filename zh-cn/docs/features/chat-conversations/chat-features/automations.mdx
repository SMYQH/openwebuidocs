# 自动化 {#automations}

Automations 允许你按周期自动执行提示词。每次执行都会创建一个聊天，并走完整的聊天完成流程，因此模型默认值、工具、过滤器以及其他 Pipeline 行为仍然全部生效。

运行与你的聊天使用相同的方式使用[记忆](/features/chat-conversations/memory)。当你的记忆已开启时，一次运行会获得记忆工具；开启 **Memory System Context** 后，你已存储的记忆也会进入其上下文，所用的模型、权限与管理员设置与聊天完全一致。记忆是否开启取决于你在 **Settings > Personalization** 中的 **记忆** 开关；如果你从未设置过它，则由[默认界面设置](/features/administration/interface-defaults)决定，而在连默认界面设置也没有的情况下，则取决于实例是否启用了 Memories。

管理员可通过 [`ENABLE_AUTOMATIONS`](/reference/env-configuration#enable_automations) 环境变量，或 **Settings > General**（管理员区域） 中的开关，在全局启用或禁用自动化。禁用后，自动化 worker 会停止处理任务，API 端点会返回 `403`，侧边栏入口也会隐藏。

## 你可以自动化什么 {#what-you-can-automate}

- 按计划执行提示词（每小时、每天、每周、每月或自定义 RRULE）
- 通过 **立即运行** 手动触发一次执行
- 在不删除的情况下暂停 / 恢复自动化任务
- 查看每个自动化任务的执行历史
- 可以选择将计划生成的聊天归入你有权编辑的[文件夹](/features/chat-conversations/chat-features/conversation-organization#the-folder-page)，包括共享文件夹，让团队在同一处查看每次运行的结果
- 为运行指定终端和工作目录，并从该终端运行[编程智能体](/features/open-terminal/coding-agents)

## 访问控制 {#access-control}

对于非管理员用户，Automations 受权限控制。

- **管理员**：始终拥有自动化访问权限
- **用户**：需要具备 **Features > Automations** 权限

只有创建者可以打开、编辑或删除自动化，管理员也不例外。其他请求会按该自动化不存在处理。向文件夹发布内容的自动化有一项例外：有权编辑该文件夹的人也能暂停或运行它，并查看运行历史（见[文件夹](#folders)）。**Features > Automations** 权限决定用户能否拥有自动化。

权限分类请参阅 [RBAC Permissions](/features/authentication-access/rbac/permissions#4-features-permissions)。

若要授予用户访问权限：

1. 打开 **Admin Panel > Users > Groups**
2. 编辑 **Default permissions** 或某个具体用户组
3. 启用 **Features > Automations**

你也可以通过 [`USER_PERMISSIONS_FEATURES_AUTOMATIONS`](/reference/env-configuration#user_permissions_features_automations) 设置默认值。

:::tip 快速访问
在 User Menu 中按住 **Shift** 可显示固定 / 取消固定按钮。将 Automations 固定后，会在侧边栏栏位中显示快捷图标，便于一键进入。
:::

## 管理员限制 {#admin-limits}

管理员可以为非管理员用户设置全局自动化使用限制。这些限制通过环境变量配置。**管理员不会受到这些限制。**

| 设置 | 效果 | 环境变量 |
| --- | --- | --- |
| **最大自动化数量** | 限制用户可创建的自动化数量 | [`AUTOMATION_MAX_COUNT`](/reference/env-configuration#automation_max_count) |
| **最小重复间隔** | 拒绝执行频率高于设定间隔（秒）的计划 | [`AUTOMATION_MIN_INTERVAL`](/reference/env-configuration#automation_min_interval) |

- **Max count** 仅在创建时检查；若后续下调限制，不会删除现有自动化任务。
- **Min interval** 会在创建和更新时都进行检查；一次性自动化（`COUNT=1`）不受此限制。
- 两者默认都为空（即不限制）；如需强制执行，请设置为正整数。

## 创建一个自动化任务 {#create-an-automation}

1. 打开 **User Menu > Automations**
2. 点击 **New Automation**
3. 设置：
   - **Title**
   - **Instructions**（提示词）
   - **Model**
   - **Schedule**
4. （可选）为自动化生成的聊天选择 **Folder**。选择器仅列出你自己的文件夹。要向共享文件夹发布聊天，请从该文件夹页面创建自动化（见[文件夹](#folders)）
5. 点击 **Create**

创建后，Open WebUI 会自动打开该自动化任务的专属编辑页：`/automations/{id}`。

### 为运行指定终端 {#giving-a-run-a-terminal}

自动化编辑器中有一个 **Terminal** 列表，选定一个终端后还会出现 **Working Directory** 字段。运行时使用的就是这个终端，并从该文件夹开始；字段留空时则从终端的默认文件夹开始。当至少有一个终端对你可用时该列表才会出现，在这里选定的终端会取代模型上配置的终端。

如果编辑器中没有指定终端，运行会使用模型上配置的终端。你可以在 **Workspace > Models** 中设置它：编辑模型并从 **Default terminal** 字段中选择终端。当至少有一个终端对你可用且模型的 **Terminal** 能力处于开启状态（默认开启）时，该列表才会出现。

:::info 自动化中的终端限制
有关终端及频道自动化的限制，见[创建终端](/features/open-terminal/terminals/orchestration/creating-terminals#machine-scope)。
:::

### 运行编程智能体 {#running-a-coding-agent}

选定终端后，**模型**列表还会提供该终端报告的编程智能体，名称格式为 `<agent>/<model>`。更换终端或文件夹会重新加载该列表，**创建**和**保存**会等待加载完成。智能体自动化需要先有终端才能保存。它的结果始终会进入某个聊天。每次运行前，Open WebUI 都会检查终端和智能体是否仍然可用，任意一个消失都会导致运行失败。

## 编辑与管理 {#edit-and-manage}

在 Automations 列表中点击某个任务，即可进入其专属编辑页。

该页面本身就是编辑器。顶部是名称和指令，下方的**属性**列表包含**状态**、**计划**、**模型**、**目标位置**、**终端**和**下次运行**。点击任意值即可就地修改。当内容与已保存的自动化不同时，页眉会显示**保存**按钮。**状态**开关无需点击**保存**即可立即暂停或恢复自动化。

页眉还提供**立即运行**、**复制链接**及**更多**菜单，其中包含**复制**和**删除**。点击**复制**会打开新建自动化表单，预填相同设置并在名称后加上“(Copy)”。点击**创建**才会保存。

属性下方的**活动**按时间从新到旧列出运行记录，标注**已运行**或**失败**及其时间。点击一次运行即可打开对应聊天。滚动时会逐步加载更多记录。

### 快速删除 {#quick-delete}

在自动化列表打开时按住 **Shift**，每个自动化的菜单按钮和开关都会变成删除按钮。点击它会立即删除该自动化，不会再询问。松开 **Shift** 后菜单和开关会恢复。从菜单中删除仍然需要你确认。

## 导出与导入 {#export-and-import}

自动化列表页头有一个分裂式 **创建** 按钮。其下拉菜单中包含 **导入 JSON** 和 **导出 JSON**，用于在实例或账户之间迁移自动化。

**导出 JSON** 会将你拥有的每个自动化下载为 `automations-export-<timestamp>.json`，无论搜索框或状态过滤器如何设置。每个条目都保留其名称、计划和其他设置、文件夹归属以及启用状态。ID、时间戳和运行历史不会写入文件，因此导出是定义的副本，而不是运行历史的备份。

**导入 JSON** 接受一个 `.json` 文件，其中可以是一个自动化数组，也可以是一个带有 `automations` 键的对象。其他格式会被当作无效 JSON 格式拒绝。

导入会做什么、不会做什么：

- 每个条目都会变成一个**全新**的自动化。导入时不会与你已有的自动化做匹配，因此把同一个文件导入两次会留下重复项。
- 除非文件把 `is_active` 设为 `false`，条目默认以**启用**状态创建。因此导入可能立刻在目标实例上启动计划运行；如果这不是你想要的，请先禁用它们。
- 只有当你自己的账户中存在相同 ID 的文件夹时才会保留文件夹，否则该字段会被丢弃，导入的自动化不带文件夹。
- 每个条目都走正常的创建流程，因此计划校验和[管理员限制](#admin-limits)依然生效。一旦某个条目被拒绝（例如无效的 `RRULE` 或触发 [`AUTOMATION_MAX_COUNT`](/reference/env-configuration#automation_max_count)），导入的其余部分就会中止；在此之前已创建的条目会保留。

## 文件夹 {#folders}

自动化可以将聊天发布到文件夹，让定期报告或摘要与同主题的其他工作集中在一起。文件夹的未读徽标会显示尚未阅读的运行次数。在编辑器的**目标位置**中设置此项。选择**新聊天**会将聊天留在未分组列表中，选择**文件夹**会列出你自己的文件夹。

文件夹页面也是管理该文件夹内自动化的入口。拥有自动化权限的用户可在页眉切换**聊天**和**自动化**。**自动化**区会列出该文件夹的自动化及其计划、最近运行日期（或**已暂停**或**尚未运行**）和启停开关。点击**新建自动化**即可创建在此文件夹中启动的自动化。自动化创建的聊天在文件夹列表和看板中带有小钟图标。

- 自动化可向创建者有权编辑的任何文件夹发布聊天，包括共享文件夹。请从共享文件夹页面创建自动化。**目标位置**选择器仅列出你自己的文件夹。
- 只有创建者能编辑自动化并打开其页面。有权编辑该文件夹的用户可通过开关暂停它。拥有该文件夹访问权限的用户都能在列表中看到它，包括仅有读取权限的用户。
- 只要创建者仍有权编辑该文件夹，运行结果就会继续出现在该文件夹中。如果失去该权限，下次运行将清除文件夹设置，并在文件夹之外创建聊天，自动化仍会继续运行。
- 文件夹是聊天的归档位置。该文件夹的系统提示词和附加知识同样适用于这些聊天。
- 清除文件夹只是一项普通编辑。以后创建的聊天会回到未分组列表，已创建的聊天留在原处。
- 删除文件夹不会删除以其为目标位置的自动化。自动化会清除文件夹设置并继续运行。
- 导入的自动化只有在你的账户中存在相同 ID 的文件夹时才保留其文件夹，否则导入时不带文件夹。

## 调度 {#scheduling}

支持的计划模式包括：

- **一次**
- **每小时**
- **每天**
- **每周**
- **每月**
- **自定义**（`RRULE`）

**每天**、**每周**和**每月**会按你挑选的准确分钟，在你自己的时区运行。

自定义计划支持标准 RRULE 语法。无效或已耗尽的规则会被拒绝。

关于自定义规则如何被解析，有几点需要注意：

- **按日以下的规则会对齐到整点。** 没有 `DTSTART` 的 `SECONDLY`、`MINUTELY` 或 `HOURLY` 规则以时钟为锚点，因此“每 5 分钟”指的是 `:00`、`:05`、`:10`，而不是从你保存的那一刻起算的五分钟。
- **`DTSTART` 在仍然有意义的地方会被采纳。** 给出起始时间后，计划会从那里开始计数，并保留你想要的相位。如果该起点早到按字面执行需要跨越超过 100,000 次发生才能到达当前时间，规则会退回到时钟对齐，而不是卡住。
- **`INTERVAL` 必须是正整数。** 零或负值会被拒绝，而不是悄悄按 1 处理。
- **每个计划只允许一条规则。** 多条 `RRULE` 会被拒绝，也完全不支持 `EXRULE`；请把排除条件写进规则本身。
- 属性名不区分大小写，因此 `freq=daily` 与 `FREQ=DAILY` 行为一致。

## 说明 {#notes}

- 自动化任务在后台 worker loop 中按轮询间隔执行。
- 每次执行都会记录状态（`success` 或 `error`）以及可选的错误详情。在聊天中回复的运行在回复完成后记为 `success`；回复失败或被取消则记为 `error`，同时运行会保留 **View chat** 链接，方便你打开对应聊天。
- 若想在运行失败时收到通知，把[通知目标](/features/chat-conversations/chat-features/notifications#events)订阅到 `automation.run_failed`。
- 删除自动化任务时，也会同时删除其运行历史。

## 在对话中管理自动化 {#managing-automations-from-chat}

在使用 **原生函数调用模式** 且模型能力足够时，也可以直接在对话中通过内置工具创建和管理自动化。这样你只需说出诸如 *“每天早上 9 点安排一份摘要报告”* 之类的话，模型就会为你创建该自动化。

### 可用工具 {#available-tools}

| 工具 | 作用 |
| --- | --- |
| `create_automation` | 使用名称、提示词和 RRULE 计划创建一个新的定时自动化，并可选择为其聊天指定文件夹。使用当前对话模型。 |
| `update_automation` | 更新现有自动化的名称、提示词、计划、模型或文件夹 |
| `list_automations` | 列出你的定时自动化，包含状态、文件夹、计划和下次运行 |
| `toggle_automation` | 暂停或恢复某个定时自动化 |
| `delete_automation` | 删除定时自动化及其全部运行历史 |

### 使用要求 {#requirements}

若想在聊天中使用自动化工具，需要满足以下条件：

1. 该模型必须启用 **Native Function Calling**
2. 该模型必须启用 **Builtin Tools** 能力
3. 模型的 Builtin Tools 设置中必须启用 **Automations** 分类（默认开启）
4. 全局必须启用 **`ENABLE_AUTOMATIONS`**（默认开启）
5. 当前用户必须具备 **Features > Automations** 权限（管理员始终通过）

这些工具接受的 folder 参数是一个文件夹 ID，并会与你拥有的文件夹进行校验：不属于你的文件夹或已不存在的文件夹会返回错误，而不会被应用。

- 在 `update_automation` 中，省略该参数或传入空字符串会保留自动化当前的文件夹；传入 `null` 则清除它。`model_id` 同理：空值会被忽略，而不会清空自动化的模型。
- 在 `list_automations` 中，省略该参数或传入空字符串会跨所有文件夹列出。

有关所有 builtin tools 的完整说明，请参阅 [Builtin Tools reference](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)。

# 多模型聊天 {#multi-model-chats}

Open WebUI 允许你在单个聊天界面中**同时与多个模型交互**。这一强大功能让你可以并排比较回答、交叉验证事实，并结合不同 LLM 的独特优势。

## 概览 {#overview}

在多模型聊天中，你的提示词会同时发送给两个或更多已选模型。它们的回复会以并列列布局显示（或在小屏幕上堆叠显示），让你能够立刻看到不同 AI 架构面对同一问题时的处理方式。

## 如何使用 {#how-to-use}

1.  **启用对比模式**：在模型选择器中，点击搜索框旁边的 <img src="/images/features/chat/multi-model-compare.svg" alt="" width="20" height="20" /> **Compare** 按钮。
2.  **选择模型**：启用对比模式后，选择希望同时对话并进行比较的模型。
    *   *示例组合*：选择 **GPT-5.6 Sol**（负责推理）、**Gemini 3.6 Flash**（擅长创意写作）和 **Claude Sonnet 5**（综合表现强）。
3.  **发送提示词**：像平常一样输入你的问题。
4.  **查看结果**：观察所有模型在聊天窗口中同时生成回复。

在对比模式下，所有已选模型的默认工具与技能会被合并使用。只有当每个已选模型都具备某个过滤器时，该默认过滤器才会启用。**Web Search**、**Image Generation** 和 **Code Interpreter** 只有在每个已选模型都具备相应能力、且已在 [Default Features](/features/workspace/models#capabilities-and-bindings) 中开启时才会默认启用。重新生成回复时，使用的是当前为其所在列选中的模型。

## 使用场景 {#usage-scenarios}

*   **模型比较 / 基准测试**：测试哪个模型更擅长写 Python 代码，或哪个模型在小众主题上幻觉更少
*   **事实校验**：对多个模型进行“交叉盘问”。如果两个模型说 X，而另一个说 Y，你就可以进一步调查
*   **多元视角**：针对同一个问题，从一个模型获得“创意型”回答，从另一个模型获得“技术型”回答

## 权限 {#permissions}

管理员可按角色或用户组控制对多模型聊天的访问权限。

*   **位置**：Admin Panel > Users > Groups > **Default permissions** > **Permissions** > **Allow Multiple Models in Chat**。要设置某个用户组专属的值，请编辑该用户组并打开其 **Permissions** 选项卡。
*   **环境变量**：`USER_PERMISSIONS_CHAT_MULTIPLE_MODELS`（默认：`True`）

如果关闭，用户将看不到模型选择器中的 **Compare** 按钮，也无法发起多模型会话。此时新聊天会以单个模型开始，即它原本会打开的模型列表中的第一个。打开已有的多模型聊天时，也只会以其中的第一个模型继续。管理员始终不受此限制。

## 合并回复（Mixture of Agents） {#merging-responses-mixture-of-agents}

当你获得多个模型的回复后，Open WebUI 还提供一个更高级的能力：将它们**合并**为一个更优答案。这实现了 **Mixture of Agents（MOA）** 工作流。

### 什么是合并？ {#what-is-merging}

合并会把所有当前激活模型的输出，加上你的原始提示词，一并发送给一个“合成模型（Synthesizer Model）”。这个合成模型会阅读所有草稿答案，并将它们融合为一个最终的、经过打磨的回复。

### 如何合并 {#how-to-merge}

1.  启动一个**多模型聊天**，并获取多个模型的回复。
2.  点击回复下方右侧的分支状图标，其悬浮提示为 **Merge Responses**。它只在聊天的最后一轮出现，且需要所有模型都已完成生成。管理员可以在 **Settings > Interface**（管理员区域） 的 **Visible controls** 中为非管理员隐藏它。
3.  Open WebUI 会在各个单独的回复下方添加一个**合并回复**，汇总之前各个输出的最佳部分。

合并后的答案会与聊天一同保存，因此您返回该对话时它仍然存在。对于重新打开的对话，合并行为与刚刚生成的对话完全相同，因此您可以把一次对比放置几天，随时回来再合并。

### 合并的优势 {#advantages-of-merging}

*   **更高准确性**：研究表明，聚合多个模型的输出，往往优于任何一个单独模型的结果
*   **兼得优势**：例如，你可以同时获得模型 A 的代码准确性和模型 B 的解释清晰度
*   **减少幻觉**：综合模型可以过滤掉单个回复中的不一致内容

### 配置 {#configuration}

这里没有任何需要配置的内容，但在您四处寻找之前知道这一点是有价值的：

*   **模型**：合并会在对比中已有的某个模型上运行，即您按下 **Merge** 时正在查看其回复的那个模型。它不使用任务模型，因此 **Settings > Interface**（管理员区域） 下的设置对它不起作用。
*   **提示模板**：合并会使用一个内置提示，告诉模型如何综合这些答案。没有对应的管理字段或环境变量。

:::info 实验性功能
合并 / MOA 是一个高级能力。结果的好坏取决于执行综合的模型，因此请用您最强模型的回复来执行合并，而不是用较小的模型。
:::

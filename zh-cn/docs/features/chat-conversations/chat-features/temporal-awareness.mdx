# 时间感知（日期与时间） {#temporal-awareness-date--time}

要让 AI 真正有帮助，它必须理解“时间”这一概念。Open WebUI 会向模型提供当前日期、时间和时区，从而使其能够给出更符合上下文的回答（例如“我今天的日程是什么？”或“总结一下我昨天的会议”）。

## 系统级时间感知 {#system-level-awareness}

日期和时间本身不会自动传到模型那里。只有当系统提示词、模型文件或提示词中包含下列占位符时，Open WebUI 才会在请求发送前把它们填入：

- **`CURRENT_DATE`**：以 YYYY-MM-DD 格式注入。
- **`CURRENT_TIME`**：对于来自界面的聊天，按浏览器本地 24 小时制以 `HH:MM:SS` 表示。未携带浏览器变量的请求（API 调用、自动化、定时器）会得到服务器本地时间，格式为 `hh:MM:SS AM/PM`。
- **`CURRENT_DATETIME`**：日期与时间合在一起。`CURRENT_TIMEZONE` 和 `USER_LANGUAGE` 只由浏览器填充，因此对 API 调用方、自动化和定时器来说会保持字面量。
- **`CURRENT_WEEKDAY`**：（例如 Monday、Tuesday）。

这些变量也可以在 [**提示词**](/features/workspace/prompts) 或 [**模型文件**](/features/workspace/models) 中通过 `{{CURRENT_DATE}}` 语法手动使用。

## 原生时间工具（Agentic） {#native-temporal-tools-agentic}

当你使用启用了 **原生函数调用** 的模型时（参见 [**集中式工具调用指南**](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)），模型就能更细粒度地执行时间查询与时间计算。

### 可用时间工具： {#available-time-tools}
- **`get_current_timestamp`**：模型可获取精确的当前 Unix 时间戳（UTC）和 ISO 日期字符串。
- **`calculate_timestamp`**：从当前时间减去指定的天数、周数、月数或年数（例如“3 天前的日期”）。它无法计算“下周五”等未来日期。模型需要根据 `get_current_timestamp` 的结果自行推算；如果用户资料中有时区，该工具也会返回用户的本地时间和时区。

### 为什么时间要用原生工具调用？ {#why-use-native-tool-calling-for-time}
静态变量只能告诉模型“现在是什么时间”，而原生工具能让模型**对时间进行推理**。

如果你问：*"查找我上周二写的笔记"*，没有工具的模型可能会猜错具体日期；而有工具的模型会：
1.  使用 `calculate_timestamp` **计算**出“上周二”的准确日期
2.  再通过 `search_notes` 用该具体日期作为过滤条件去**搜索**你的笔记

这种精确性对于依赖历史搜索、任务调度或时序数据分析的 agentic 工作流至关重要。

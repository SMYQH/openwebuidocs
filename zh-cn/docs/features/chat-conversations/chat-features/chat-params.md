在 Open WebUI 中，**系统提示词** 和 **高级参数** 共有三层设置粒度：按聊天、按模型、按账号。这个分层体系既保证了灵活性，也保留了结构化管理和控制能力。

## 系统提示词与高级参数层级图 {#system-prompt-and-advanced-parameters-hierarchy-chart}

| **层级** | **定义** | **修改权限** | **覆盖能力** |
| --- | --- | --- | --- |
| **按聊天** | 针对某个具体聊天实例设置的系统提示词和高级参数 | 用户可修改，但不能覆盖模型的系统提示词 | 在这里设置的高级参数即为实际发送的值，取代按账号和按模型的值 |
| **按账号** | 针对某个用户账号设置的默认系统提示词和高级参数 | 用户可设置，但系统提示词可能被模型级设置覆盖 | 在这里设置的高级参数取代按模型的值，并让位于按聊天的值 |
| **按模型** | 针对某个模型设置的默认系统提示词和高级参数 | 管理员可设置，用户不可修改 | 系统提示词优先。高级参数适用于所有未自行设置它们的聊天 |

### 1. 按聊天设置 {#1-per-chat-basis}

- **说明**：按聊天设置是指针对某个具体聊天实例配置的系统提示词和高级参数。这些设置只对当前对话生效，不会影响后续新聊天。
- **如何设置**：打开 **模型控制** 菜单（消息输入框旁边的旋钮图标）并展开 **Controls**。其中包含该聊天的文件、valves、系统提示词和高级参数；管理员以及拥有 **允许聊天控制** [权限](/features/authentication-access/rbac/permissions#3-chat-permissions)的用户都能看到它。
- **覆盖能力**：如果管理员已在模型级（**#3**）设置了 **系统提示词**，用户将不能在聊天级覆盖它。这可确保一致性并遵守模型级配置。在这里设置的 **高级参数** 即是该聊天实际发送的值，即使模型自带同名参数也是如此。

### 2. 按账号设置 {#2-per-account-basis}

- **说明**：按账号设置是指为某个用户账号配置默认系统提示词和高级参数。当更低层级没有定义相关设置时，这些用户级设置可作为回退值使用。
- **如何设置**：用户可在 Open WebUI 的 **设置** 菜单中的 **常规** 部分为自己的账号设置系统提示词和高级参数。
- **覆盖能力**：用户可以为自己的账号设置系统提示词，但也要注意：如果管理员已经针对正在使用的特定模型，在模型级设置了 **系统提示词**，这些账号级设置仍然可能被覆盖。在这里设置的 **高级参数** 会取代模型自身的同名参数，而聊天 **Controls** 中设置的值又会取代它。

### 3. 按模型设置 {#3-per-model-basis}

- **说明**：按模型设置是指为某个模型配置默认系统提示词和高级参数。这些设置会应用于所有使用该模型的聊天实例。
- **如何设置**：管理员可在 Open WebUI 的 **工作区** 中的 **模型** 部分，为某个模型设置默认系统提示词和高级参数。
- **覆盖能力**：**用户** 账号不能在模型级（**#3**）修改 **系统提示词** 或特定 **高级参数**。这一限制可防止用户不恰当地更改默认设置。
- **系统提示词保持：** 当管理员在 **工作区** 中手动为模型设置 **系统提示词** 后，**用户** 账号便无法再在 **常规** 设置或聊天的 **Controls** 中按账号覆盖或调整它。这可确保一致性并遵守模型级配置。
- **参数优先级：** 管理员在模型上设置的 **高级参数** 适用于所有未自行设置同一参数的聊天。**用户** 账号在 **常规** 设置或聊天的 **Controls** 中设置它时，发送的是自己的值，且按聊天的值优先于按账号的值。在上述各层级都没有人设置过的参数，会回落到 [全局模型默认值](/features/workspace/models#global-model-defaults-admin)中的实例级值。上下文长度也包括在内：在聊天 **Controls** 中设置的 `num_ctx` 即为实际发送的值，即使模型自带 `num_ctx` 也一样。**流式聊天响应** 是例外：模型上设置的值优先，其次是聊天的，最后是账号的。
- **模型控制：** 当模型拥有[模型控制](/features/workspace/models#model-controls)时，在那里选定的选项（或该控制的默认选项）位于所有层级之上：它的参数会取代聊天 **Controls**、**常规** 设置、模型或全局模型默认值中设置的同名参数。该选择按模型保存在账号上，因此会跨该模型的所有聊天沿用。

:::note `top_k` 只接受整数

`top_k` 用于统计候选 token，因此它只接受 0 到 1000 之间的整数。它的滑块和数字输入框都以 1 为步长；输入小数、负数或任何其他非整数时，不会被接受，而是保留先前的值。无论该参数是在按聊天、按账号还是按模型层级编辑，这一点都成立。

:::

## **最大化灵活性的系统提示词优化建议** {#optimize-system-prompt-settings-for-maximum-flexibility}

:::tip

**额外建议**  
**以下建议同时适用于管理员和普通用户。若想最大化系统提示词的灵活性，可考虑如下方式：**

- 将你的主要系统提示词（**例如赋予 LLM 一个明确人格**）放在 **常规** 设置中的 **系统提示词** 字段。这会在账号级生效，让它在所有 LLM 上都可作为基础系统提示词，而无需在 **工作区** 的模型设置里逐个调整。

- 对于次级系统提示词（**例如让 LLM 执行某个具体任务**），你可以根据需要将其放在 **模型控制 > Controls** 下的 **系统提示词** 字段（按聊天），或对于管理员放到 **工作区** 的 **模型** 部分（按模型）。这样账号级系统提示词就能与 **Controls** 提供的聊天级提示词，或 **模型** 提供的模型级提示词叠加工作。

- 作为管理员，建议你通过 **模型** 部分按模型设置 LLM 参数，以获得最佳灵活性。对于这些次级系统提示词，请尽量采用既能提高灵活性、又能减少跨账号 / 跨聊天重复调整的设置方式。管理员和所有用户都应清楚了解：**Controls** 与 **模型** 中的系统提示词最终会按怎样的优先顺序应用到 **LLM**。

:::

## Chat Variables

Chat Variables 把模型的系统提示词变成了一张简短的表单。管理员在系统提示词中写入占位符，Open WebUI 会要求打开该模型聊天的人填写它们。答案保存在该聊天上，并在其中每一条消息中复用。

在模型的系统提示词中声明一个变量：

```txt
{{chat.variables.key_name}}
```

这样会生成一个单行文本字段。若要在竖线之后加上定义以获得带类型的字段：

```txt
{{chat.variables.project_name | text:placeholder="Which project?":required}}
{{chat.variables.tone | select:options=["Formal","Casual"]:default="Formal"}}
```

其语法和可用的字段类型与[提示词输入变量](/features/workspace/prompts#available-input-types)所用的完全相同。键名必须是小写蛇形命名：以字母开头，之后是字母、数字或下划线。

:::danger 必须带上 `chat.variables.` 前缀

只有带有完整 `chat.variables.` 前缀的占位符才会声明一个聊天变量。裸露的 `{{project_name | text:required}}` 是[提示词输入变量](/features/workspace/prompts#custom-input-variables)语法，它在提示词内容中有效，在系统提示词中则毫无作用。

在系统提示词中写一个不带前缀的占位符，根本不会声明任何变量：聊天输入框旁不会出现控件，表单永远不会打开，而占位符本身会作为字面文本发送给模型。没有任何提示，因此模型看起来就像是直接忽略了这个功能。

检查方式是模型编辑器中的 **Detected Variables** 列表。它会随你的输入实时更新，而缺少前缀的占位符永远不会出现在其中。

:::

### 填写这些变量 {#filling-them-in}

当所选模型声明了聊天变量时，聊天输入框旁会出现一个控件，点击它会打开 **Chat Variables** 表单。仅仅选择模型并不会打开它：除非你按下该控件或尝试发送消息，否则什么都不会显示。之后可以随时通过同一个控件修改这些值，修改后发送的消息即按新值生效。

只有在没有任何可发送的内容时，发送消息才会改为打开表单而不是直接发送，也就是说存在以下情况之一：

- 某个 `required` 字段既没有值也没有 `default`；或
- **所有**字段都没有值且都没有 `default`。

否则消息会直接发给模型，任何未填写的变量都会被替换为空字符串。

:::tip 在 `required` 与 `default` 之间选择

这个表单是一个输入闸门而非确认步骤，因此只有在缺少答案就无法合理继续时才会打断你。带有 `default` 的字段本来就有一个值，这正是为什么所有变量都有 `default` 的模型会立即开始聊天。

这也意味着，只要有一个 `default`，就足以阻止表单为其他可选字段弹出。它们仍然可以从聊天输入框旁的控件访问，只是不会被追问。

因此：当答案必须由用户给出时，把字段标记为 `required`；当你愿意让聊天不经询问就开始时，给它一个 `default`。

:::

这些值保存在聊天上，因此重新打开它仍会保留，分叉或克隆自己的聊天时也会一并带过去。别人聊天的副本则以空的聊天变量开始。在临时聊天中，它们随每个请求一起传递，生命周期与聊天本身相同。

单个值最多可有 20,000 个字符，一个聊天的全部变量合计最多 100,000 个字符。

:::warning 修改定义可能让已有聊天变成空白

组装提示词时会依据当前定义校验这些值，只要其中任何一个未通过校验，该提示词中的所有聊天变量都会渲染为空白，而不只是出问题的那一个。因此，从 `select` 中移除某个选项会悄无声息地让存储了被移除值的聊天中的整组变量变空，所以在修改定义后请重新打开受影响的聊天并重新填写表单。

:::

### 一个聊天中使用多个模型 {#several-models-in-one-chat}

选择多个模型时，它们的变量会被合并。完全相同的定义会合并为一个字段，只要其中任一模型将其标记为必填，该字段就是必填的。如果两个所选模型以不同方式定义了同一个键，发送会被阻止，并列出冲突的键以及定义它们的模型，此时请取消选择其中一个，或让两者的定义保持一致。

### 编写时的检查 {#authoring-checks}

模型编辑器会列出它找到的内容，位于 **Detected Variables** 之下，分为 **Chat Variables** 和 **User Variables**。它会对以下情况发出警告：键名不是小写蛇形命名、`select` 没有 `options=[...]`、同一个键以两种不同方式定义，以及给用户变量写了定义——因为用户变量由每位用户各自配置，对其加定义不会产生任何作用。

## User Variables

User Variables 让同一个共享的系统提示词能为每个使用它的人产生不同的结果。管理员在模型的系统提示词中写入占位符，每位用户填写自己的值。

每位用户可在 **设置 > 账户 > User Variables** 下管理自己的值，以键值对列表的形式呈现。在系统提示词中这样引用：

```txt
{{user.variables.key_name}}
```

在请求时，每个占位符都会被替换为该用户针对这个键的值。用户未设置的键会被替换为空字符串，因此提示词中永远不会出现原始占位符。

例如，一个共享模型可以带有 `Address the user as {{user.variables.preferred_name}} and answer in {{user.variables.language}}.`，从而对所有人都有正确表现，而无需管理员为每个人维护一个模型。

### 键和值的规则 {#rules-for-keys-and-values}

- 键名必须是小写蛇形命名：以字母开头，之后是字母、数字或下划线（`preferred_name`、`team2`）。不符合的键名会被拒绝。
- 值是纯文本。单个值最多可有 20,000 个字符，一个用户的全部变量合计最多 100,000 个字符。
- 值按用户保存，且只会被替换进该用户自己的请求中。

这些值属于个人数据，因此应当把它们视为用户提供的文本，而不是存放机密的地方：放进变量的任何内容都会被插入到发送给该聊天所配置模型的提示词中。

### User Variables 还是 Chat Variables？ {#user-variables-or-chat-variables}

两者都写在模型的系统提示词中，也都由用户而非管理员填写。区别在于向谁询问，以及答案能持续多久。

| | Chat Variables | User Variables |
| --- | --- | --- |
| 书写形式 | `{{chat.variables.key}}` | `{{user.variables.key}}` |
| 由谁填写 | 打开该聊天的任何人，通过表单填写 | 每位用户，在 **设置 > 账户** 中一次性填写 |
| 持续时间 | 那一次对话 | 该用户发出的每个请求 |
| 字段类型 | 带类型，在竖线之后定义 | 仅纯文本 |
| 何时询问 | 聊天开始时 | 从不询问，值是事先设置好的 |

竖线之后的定义只对聊天变量生效。把它写在用户变量上不会产生任何作用，模型编辑器也会标出这一点——因为每位用户是在设置中配置自己的值，而不是被提示填写。

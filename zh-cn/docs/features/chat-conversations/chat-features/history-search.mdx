# 历史记录与搜索 {#history--search}

Open WebUI 提供了一套强大的系统，用于管理和浏览你以往的对话。无论你是在查找上个月的某段代码，还是想整理数百条聊天记录，历史记录与搜索功能都能帮助你快速找到所需数据。

## 聊天历史侧边栏 {#chat-history-sidebar}

你的所有对话都会自动保存在 **侧边栏** 中。

![搜索聊天历史](/images/features/chat/history-search.png)

*   **持久化**：聊天会保存到内部数据库（`webui.db`），并可在你的所有设备间访问
*   **组织方式**：聊天会按时间段分组（今天、昨天、最近 7 天等）
*   **悬停预览**：把指针停在某个聊天上会弹出小卡片，显示它最近的消息，不打开也能分辨出各个对话。卡片标题会显示该聊天共有多少轮对话，其中计入你的消息以及当前分支上的回复。若一个聊天中有多个模型的回复，则每一轮只显示你所在分支上的那一条。如果希望侧边栏更安静、正在共享屏幕，或网络较慢导致预览卡顿，可以在 **Settings > Interface > Chat** 中关闭 **Chat Hover Previews**。预览需要指针，因此在触摸屏上不会显示。
*   **未读标记**：有新活动的聊天会在侧边栏显示未读圆点，直到你打开它们。聊天三点菜单中的 **Mark as unread** 可以重新加上圆点；文件夹的菜单以及 **Chats** 区块标题自身的菜单都提供 **Mark all as read**，可以一次性清除某个文件夹或整个聊天列表的未读状态。
*   **重命名**：标题通常由 task model 自动生成，但你也可以点击侧边栏中标题旁的铅笔图标手动重命名任意聊天。聊天打开后，标题旁的菜单中的 **Rename** 同样可以重命名，而输入框旁的 **Generate**（星芒）按钮会根据对话内容重新生成标题。新聊天的标题在你发出第一条消息时就会开始请求生成，此时回复还在生成中，因此中止该回复或回复失败都不会让聊天没有标题。如果标题请求本身失败，例如任务模型无法访问，聊天会保留 **New Chat** 这个名字，后续消息也不会再重试；可以用 **Generate** 为它命名。开启自动标题后，重新生成第一条回复，或编辑并再次发送第一条消息，都会在该回复完成后写入新标题并替换当前标题，包括你手动输入的标题。自动生成的标题不会计入活动，因此仅仅命名不会把聊天重新顶到列表顶部，也不会再次标记为未读。你可以在 **Settings > Interface** 中通过 **Title Auto-Generation** 为自己关闭自动标题。该开关只有在管理员在 **Settings > Interface**（管理员区域） 中开启 **Title Generation** 后才会显示，在隐藏期间你的选择会被保留。
*   **归档**：你可以将聊天 **归档**，把它们从主列表移除而不删除。除非使用 `archived:true` 搜索，否则已归档的对话不会出现在搜索窗口中，但仍可在 **Settings > Archived Chats** 下浏览。管理员可以在 **Settings > Interface**（管理员区域） 的 **Visible controls** 中隐藏 **Archive**，详见 [Archived Chats](/features/chat-conversations/data-controls/archived-chats)。
*   **选择多个聊天**：按住 Shift 点击某个聊天即可开始选择。选择范围会从你上次点击的聊天一直覆盖到你 Shift 点击的那个聊天。此后每个聊天都会显示复选框，普通点击即可勾选或取消。继续 Shift 点击会从同一个起点扩展范围。侧边栏底部的工具条会显示已选中的数量，并提供 **Archive**、**Delete**（一次性处理全部）和 **Clear selection** 按钮。删除前会先要求确认，且只有拥有 [Allow Chat Delete](/features/authentication-access/rbac/permissions#3-chat-permissions) 权限时才会出现删除按钮。`Escape` 也会清除选择。由他人拥有的聊天（例如共享文件夹中别人的聊天）无法被选中。如果批量操作未能处理某些聊天，它们会保持选中状态，方便你重试。
*   **文件夹未读计数**：文件夹会显示其本身及子文件夹中未读或等待批准工具调用的聊天数。参见[文件夹与项目](/features/chat-conversations/chat-features/conversation-organization#unread-badge)。
*   **展开与收起**：侧边栏可以滑入滑出。你的聊天只在打开 Open WebUI 时加载一次，不会每次显示侧边栏都重新加载，因此隐藏后再打开仍然保留你已经滚动到的位置，而不会跳回最新的聊天。

Open WebUI 会按聊天跟踪已读状态，并在你打开对话时更新，这样未读标记就能在不同会话间保持同步。打开聊天会清除它的未读标记，你其他已打开窗口中的文件夹计数也会立即同步。

## 搜索你的历史记录 {#searching-your-history}

搜索窗口可以集中搜索你能打开的所有内容。

1.  点击侧边栏中的 **搜索**，或按 `Cmd+K` / `Ctrl+K`。
2.  输入查询内容。窗口会搜索：
    *   **你自己的聊天**，按标题和消息内容匹配
    *   **与你共享的文件夹中的聊天**，包括其子文件夹
    *   **共享给你的聊天**，包括按名称共享和通过群组共享的。以 **Allow replies** 方式共享的聊天会实时打开；其他共享聊天显示为 **Shared snapshot**，并打开其分享链接。
    *   **频道消息和私信**中你有权限访问的部分
    *   **笔记**中你拥有的或与你共享的部分
3.  点击结果或按 `Enter` 打开。

只有在启用频道并且你拥有 **Channels** 功能权限时，频道消息才会出现。笔记同理，需要启用笔记并拥有 **Notes** 权限。管理员始终拥有这两项权限。除非使用 `archived:true` 搜索，否则已归档的对话不会包含在内。

查询为空时，窗口会列出 **Pinned & recent**：先显示你置顶的聊天和笔记，其余按最近活动时间排序。

### 过滤结果 {#filtering-results}

搜索框旁的按钮用于选择内容类型：**Everything**、**Chats**、**Messages** 或 **Notes**。它旁边的过滤按钮还提供两项过滤：

*   **View**：**All**、**Created by you** 或 **Shared with you**。选择 **Shared with you** 会保留由他人拥有或撰写的条目。
*   **Location**：**Everywhere**、某个文件夹或某个频道。文件夹包含其子文件夹，且只显示聊天；频道只显示该频道中的消息。

生效的过滤会以标签形式显示在搜索框下方。点击某个标签即可移除它，也可以在过滤菜单中使用 **Reset**。

你也可以把[过滤前缀](#filter-prefixes)与搜索词一起输入搜索框。`tag:none` 用于查找没有标签的聊天，标签和文件夹名称中的空格要写成下划线（`folder:client_work`）。任何前缀都会把结果限制为你自己的聊天。输入过程中，窗口会提示可用的前缀和取值，可用方向键加 `Enter` 或 `Tab` 选中。

### 处理搜索结果 {#working-with-results}

每条结果都会显示它的标题、所属位置（文件夹、**Personal chat**、**Shared chat**、频道、**Personal note** 或 **Shared note**），以及匹配消息中的一小段摘录。仅按标题匹配的聊天会显示它的最后一条消息；频道消息则以发送者姓名作为标题。查询中的关键词会在标题和摘录中高亮显示。

*   **聊天**会直接打开到匹配的消息，并切换到包含该消息的分支。
*   **频道消息**会打开频道，并定位到消息所在线程中的匹配消息。
*   **笔记**会打开到匹配的页面，并选中第一处匹配。

按 `Ctrl/Cmd + Enter` 可在结果列表旁显示或隐藏所选结果的预览。宽度不小于 768 像素的屏幕上预览默认展开；一旦手动显示或隐藏，该选择会应用到所有宽度。预览打开时，单击可选中结果，双击则打开结果。

**Actions** 菜单可以通过其按钮打开，也可以在窗口打开时按 `Cmd+K` / `Ctrl+K` 打开，其中包含 **Open result**、**Show preview** 或 **Hide preview**、**Copy link**、以当前查询为提示词开启新对话的 **Start a new conversation**，以及以当前查询为内容新建笔记的 **Create a new note**。

### 查询是如何匹配的 {#how-queries-are-matched}

在搜索窗口中，由多个词组成的查询会找出包含这些词的每一项，顺序不限。词以空格分隔，最多计十二个。每个词既可以来自标题，也可以来自任意一条消息，不同的词也可以来自不同的消息。匹配不区分大小写，并按子串工作。标题与查询完全相同的条目排在最前，其次是标题包含查询的条目，其余按最近活动时间排序。向下滚动时会加载更多结果。

对话输入框 **+** 菜单中的 **参考对话** 选择器以及模型的 `search_chats` 工具使用不同的规则来搜索你自己的对话。由多个词组成的查询会找出包含这些词的每个对话，顺序不限，也不要求它们彼此相邻。每个词可以来自对话标题或其任意一条消息，不同的词也可以来自不同的消息，因此 `docker healthcheck` 同样能找出标题为 “Docker setup” 且回复中提到 healthcheck 的对话。包含你的查询作为完整短语的对话排在最前，其余随后，每组按最近更新时间排序。

匹配不区分大小写并按子串工作，因此 `log` 也会匹配到 “login” 和 “backlog”。查询中的词按英文字母和数字切分，因此 `v0.9.1` 会分别搜索 `v0`、`9` 和 `1`。只有前十二个不同的词计入。如果查询完全使用另一种文字书写（例如中文或俄文），则按一个完整短语进行搜索。

### 过滤前缀 {#filter-prefixes}

在搜索窗口和 **参考对话** 选择器中，你可以单独使用过滤前缀，也可以与查询组合使用来缩小结果范围：

*   `tag:<name>`，具有指定标签的聊天；`tag:none` 表示没有标签的聊天
*   `folder:<name>`，位于指定文件夹中的聊天
*   `pinned:true` 或 `pinned:false`：仅已置顶的聊天，或仅未置顶的聊天
*   `archived:true` 或 `archived:false`：仅已归档的聊天，或仅未归档的聊天
*   `shared:true` 或 `shared:false`：仅带分享链接的聊天，或仅不带分享链接的聊天

最后三个前缀需要在冒号后写 `true` 或 `false`。单独输入 `pinned:`、`archived:` 和 `shared:` 时，这些前缀会从查询中丢弃，不产生任何过滤。在搜索窗口中，`tag:` 和 `folder:` 后面没有内容时同样会被丢弃。

搜索窗口会在你输入时提示可用的前缀。当输入某个前缀的首字母时（例如 `tag:` 的 `t`），搜索框下方会列出该前缀及一段简短说明。选择 `tag:` 会列出你的标签，选择 `folder:` 会列出你的文件夹，`pinned:`、`archived:` 和 `shared:` 则提供 `true` 和 `false`。点击提示项，或用方向键配合 `Enter` 或 `Tab` 选择。`Escape` 会关闭提示列表并保留搜索窗口。

搜索窗口中的过滤只搜索你自己拥有的聊天。笔记、频道消息和共享快照没有标签、文件夹或归档状态，因此在查询包含过滤前缀时会被排除在结果之外。

例如，`folder:work meeting notes` 会在 **work** 文件夹中搜索 “meeting notes”。

## 原生对话搜索（代理模式） {#native-conversation-search-agentic}

当你使用启用了 **Native Function Calling** 的模型时（参见 [**Central Tool Calling Guide**](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)），模型还可以自主搜索你的聊天历史。

### 可用历史工具： {#available-history-tools}
- **`search_chats`**：在聊天标题和消息内容中做文本搜索，匹配规则与 **参考对话** 选择器相同，并跳过模型当前所在的对话。返回匹配的聊天 ID 和摘录。
- **`view_chat`**：按 ID 读取并返回某个聊天的消息历史；当设置了 [`VIEW_CHAT_MAX_CHARS`](/reference/env-configuration#view_chat_max_chars) 时只截取最新的消息。
- **`search_users`**：按姓名或邮箱查找用户，以便模型在回复中提及他们。被提及且有权查看该聊天的用户会收到[收件箱](/features/chat-conversations/chat-features/notifications#inbox)通知，点击可打开聊天中的对应回复。

### 为什么要为搜索使用原生工具调用？ {#why-use-native-tool-calling-for-search}

这让模型能够复用它自己过去完成的工作。你可以直接问：*“我上一次邮件草稿收到的反馈是什么？”* 或 *“帮我找出两周前我写的关于图像处理的 Python 脚本。”*

模型会搜索你的历史、定位正确聊天、读取内容，并直接返回答案或你需要的代码——省去你手动滚动和复制粘贴的麻烦。

## 数据管理 {#data-management}

*   **导出**：你可以将单个聊天或全部历史下载为 **JSON**、**纯文本 (.txt)** 或 **PDF**。导出全部历史时只能使用 JSON。没有 Markdown 导出格式。
*   **导入**：将 JSON 聊天导出文件拖到侧边栏并松开，即可恢复。
*   **删除**：你可以通过侧边栏中的三点菜单或聊天顶部菜单删除单个聊天，也可以在 **Settings > Data Controls** 中使用 **Delete All Chats** 清空全部历史。

删除需要 [Chat Delete 权限](/features/authentication-access/rbac/permissions#3-chat-permissions)。如果管理员撤销了该权限，这些删除入口都不会显示，你也就不会再遇到点击后被拒绝的删除按钮。归档不受影响，管理员始终拥有删除权限。

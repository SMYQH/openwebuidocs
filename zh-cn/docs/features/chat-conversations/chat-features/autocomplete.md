# 自动补全 {#autocomplete}

Open WebUI 提供由 AI 驱动的 **自动补全** 功能，在你输入提示词时实时建议文本补全。它就像对话输入框的“Copilot”，借助你配置的任务模型帮助你更快地写出提示词。

## 工作原理 {#how-it-works}

启用后，Open WebUI 会持续监测你在聊天框中的输入。当你暂停打字时，它会将当前文本发送给一个轻量级 **Task Model**。该模型会预测接下来最可能出现的词句，并以覆盖在输入框上的“幽灵文本”形式显示。

- **接受建议**：按 `Tab` 接受建议。Right Arrow 只会移动光标。
- **拒绝 / 忽略**：继续输入即可覆盖该建议

:::info
**性能建议**

自动补全高度依赖 **任务模型** 的响应速度。我们建议使用体积小、速度快、**非推理型** 的模型，以确保建议可以即时出现。

**推荐模型：**

- **Qwen 3.5**（`qwen3.5:0.8b` 或 `qwen3.5:2b`）
- **GPT-5.6 Luna**（针对低延迟和低成本优化）
- **Gemini 3.5 Flash-Lite**

避免为该功能使用推理模型或较重的 Chain-of-Thought 模型 —— 延迟会让自动补全体验变得迟钝。
:::

## 配置 {#configuration}

自动补全功能采用两层控制：**全局可用性** 与 **用户偏好**。

### 1. 全局配置（管理员） {#1-global-configuration-admin}

管理员可控制服务器上是否开放自动补全功能。

### 1. 配置自动补全（全局） {#1-configuring-autocomplete-global}

**管理面板设置：**
前往 **设置 > 界面 > 任务模型**（管理员区域），切换 **自动补全生成**。

### 2. 用户配置（个人） {#2-user-configuration-personal}

即使全局已启用，单个用户如果觉得干扰，也可以自行关闭。

- 前往 **设置 > 界面**
- 切换 **Prompt Autocompletion**

个人设置使用的标签与管理端不同——管理端显示为 **自动补全生成**。两者控制的是同一个功能。

:::note
如果管理员已在全局关闭自动补全，用户将**无法**在个人设置中重新启用。
:::

## 性能与故障排查 {#performance--troubleshooting}

### 为什么没有出现建议？ {#why-arent-suggestions-appearing}

1. **检查设置**：确认它在管理员和用户两侧设置中都已启用
2. **任务模型**：前往 **设置 > 界面**（管理员区域），确认已选择哪个 **任务模型**。如果一个都没设置，聊天中当前的模型会用来生成建议，因此阻碍生成的原因是聊天里没有选中模型。管理端开关下面还有两个字段：**自动补全生成输入最大长度**（`AUTOCOMPLETE_GENERATION_INPUT_MAX_LENGTH`，默认 `-1` 表示不限制；留空保存会写入该环境变量的值，若该变量未设置则为 `-1`）和 **自动补全生成提示词**。该功能在两侧默认都是关闭的：管理端开关（`ENABLE_AUTOCOMPLETE_GENERATION`，默认 `False`）以及每个用户的 **Prompt Autocompletion** 开关。
3. **延迟**：如果任务模型太大，或运行在较慢硬件上，预测结果可能到得太晚，不具备使用价值；请改用更小的模型
4. **推理模型**：确认你**没有**使用“推理型”模型（如 o1 或 o3），因为它们的内部思考过程会引入过大延迟，破坏实时自动补全体验。如果你只能用这类模型，可以在 **设置 > 界面**（管理员区域） 的 **任务模型参数** 中调低 `reasoning_effort`。该设置被所有后台任务共用，请先阅读 [任务模型](/features/administration/task-models#task-model-parameters)。

### 性能影响 {#performance-impact}

自动补全几乎会在你每次暂停输入时向 LLM 发送一次请求（带防抖）。

- **本地模型**：这可能显著消耗宿主机的 GPU / CPU 资源
- **API 提供商**：这会产生大量 API 调用（虽然通常 token 数很少）。请留意服务商的 **速率限制**（每分钟请求数 RPM、每分钟 token 数 TPM），避免被限流

:::warning
对于运行在有限本地硬件上的多用户实例，我们建议**关闭**自动补全，以优先保障实际聊天生成的资源。
:::

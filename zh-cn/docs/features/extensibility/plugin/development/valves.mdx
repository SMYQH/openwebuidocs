## Valves 配置 {#valves}

Valves 和 UserValves 用来让用户提供动态信息，例如 API key 或某个配置项。它们会在 GUI 菜单中为对应的函数生成一个可填写的字段或一个布尔开关。它们始终是可选的，但**强烈建议**提供。

因此，Valves 和 UserValves 类可以定义在 `Pipe`、`Filter`、`Action` 或 `Tools` 类中。`Event` 类也可以携带 `Valves`，但绝不能携带 `UserValves`，因为事件处理器运行时并不存在具体用户。

函数级别的 Valves 只能由管理员配置，因为 Functions 仅限管理员使用。工具级别的 Valves 还可以由工具的所有者以及任何持有其写入权限的人修改，因此请把工具的 valves 视为对所有被授予写入权限的人可读。UserValves 则可以由任何用户直接在聊天会话中配置，位置在 **模型控制 > 控件** 下的 **Valves** 区域。该区域只列出已启用的工具和函数。

<details>
<summary>带注释的示例</summary>

``` python

from pydantic import BaseModel, Field
from typing import Literal

# Define Valves and UserValves
class Filter:
    # Notice the indentation: Valves and UserValves are declared as
    # attributes of a Tools, Filter or Pipe class. Here we take the
    # example of a Filter.
    class Valves(BaseModel):
        # Valves and UserValves inherit from pydantic's BaseModel. This
        # enables complex use cases like model validators etc.
        test_valve: int = Field(  # Notice the type hint: it is used to
            # choose the kind of UI element to show the user (buttons,
            # texts, etc).
            default=4,
            description="A valve controlling a numerical value",
        )
        # To give the user the choice between multiple strings, you can use Literal from typing:
        choice_option: Literal["choiceA", "choiceB"] = Field(
            default="choiceA",
            description="An example of a multi choice valve",
        )
        # The priority field is optional but if present will be used to
        # order the Filters.
        priority: int = Field(
            default=0,
            description="Priority level for the filter operations. Lower values are passed through first",
        )

    # UserValves are defined the same way.
    class UserValves(BaseModel):
        test_user_valve: bool = Field(
            default=False, description="A user valve controlling a True/False (on/off) switch"
        )

    def __init__(self):
        self.valves = self.Valves()
        # Because they are set by the admin, they are accessible directly
        # upon code execution.

    # The inlet method is only used for Filter but the __user__ handling is the same
    def inlet(self, body: dict, __user__: dict):
        # Because UserValves are defined per user they are only available
        # on use.
        # Note that although __user__ is a dict, __user__["valves"] is a
        # UserValves object. Hence you can access values like that:
        test_user_valve = __user__["valves"].test_user_valve
        # Or:
        test_user_valve = dict(__user__["valves"])["test_user_valve"]
        # But this raises TypeError, a pydantic model is not subscriptable:
        # test_user_valve = __user__["valves"]["test_user_valve"]  # Do not do that!
        return body
```

</details>

## 修改现有代码中的阀门 {#changing-valves-in-existing-code}

保存工具或函数时，系统会把已存储的 Valve 值与新代码进行校验。当某个已存储的值无法通过校验时——例如新代码改变了字段的类型或取值范围——保存会被拒绝，并提示 `Current Valves are incompatible with this code: <field>: <message>`，已保存的代码保持原样。请让修改后的字段与已存储的值保持兼容，或者先调整 Valves。只有存在已存储值的字段才会被校验。将较旧的版本设为生产版时同样会执行该检查。

## 翻译阀门标签 {#translating-valve-labels}

阀门标题、帮助文本和下拉选项标签都可以按语言分别存储，入口是工具或函数编辑器中的地球图标选择器。只有标签会改变，字段名称以及你在代码中收到的值都保持原样。参见[翻译](/features/administration/translations#translating-valve-labels)。

## 输入类型 {#input-types}

Valves 支持一些特殊输入类型，它们会影响字段在 UI 中的渲染方式。你可以在 Pydantic `Field` 中通过 `json_schema_extra` 的 `input` 键进行配置。

渲染器会按固定顺序选择控件：`Literal` 或枚举字段始终渲染为下拉选择，`bool` 渲染为开关，多选渲染为独立控件，区间渲染为滑块，其他所有非字符串类型渲染为普通文本框并忽略 `input.type`。因此 `password` 和 `select` 输入类型只对 `str` 字段生效。

### Password Input（掩码输入） {#password-input-masked-fields}

对于密码、API key、secret 等敏感字段，你可以使用 password 输入类型，让其在 UI 中以掩码方式显示，从而避免明文暴露在屏幕上（防止肩窥）。

```python
from pydantic import BaseModel, Field

class Tools:
    class UserValves(BaseModel):
        service_password: str = Field(
            default="",
            description="Your service password",
            json_schema_extra={"input": {"type": "password"}}
        )
```

渲染后，这个字段会以掩码输入框显示（字符显示为圆点），并带有显示 / 隐藏切换，底层使用的是 Open WebUI 的 `SensitiveInput` 组件。

:::tip
任何凭证或 secret 类型的用户配置项，都建议使用 password 输入类型。对于 UserValves 尤其重要，因为它们允许终端用户直接在聊天界面中配置。
:::

### 静态加密阀门值 {#encrypting-valve-values-at-rest}

password 输入类型只会遮蔽界面中的显示，并不会改变值的存储方式。默认情况下，Valve 的值（包括各种 secret）会以明文 JSON 形式保存在数据库中。若要静态加密，管理员可以设置 [`ENABLE_VALVE_ENCRYPTION=true`](/reference/env-configuration#enable_valve_encryption)，它会使用由 [`WEBUI_SECRET_KEY`](/reference/env-configuration#webui_secret_key) 派生的密钥，以 Fernet（AES-128）加密工具与函数的 Valve 值。

:::warning
任意长度的 `WEBUI_SECRET_KEY` 都会被哈希成合法的 Fernet 密钥，但有一个例外：长度恰好为 44 个字符的密钥会被原样使用，因此它必须是能够解码为 32 字节的 URL 安全 Base64 字符串。最关键的是它必须保持稳定，因为轮换该密钥会导致此前加密的 Valve 值无法读取，必须重新填写。详情参见 [`ENABLE_VALVE_ENCRYPTION`](/reference/env-configuration#enable_valve_encryption)。
:::

### 选择下拉输入 {#select-dropdown-input}

对于用户应从预定义选项中选择的字段，可以使用 select 输入类型把它渲染为下拉菜单。选项既可以是静态列表，也可以是运行时动态生成的内容。

#### 静态选项 {#static-options}

对于不会变化的选项，直接使用列表即可：

```python
from pydantic import BaseModel, Field

class Tools:
    class Valves(BaseModel):
        priority: str = Field(
            default="medium",
            description="Processing priority level",
            json_schema_extra={
                "input": {
                    "type": "select",
                    "options": ["low", "medium", "high"]
                }
            }
        )
```

也可以使用 label/value 键值对，以获得描述性更强的选项：

```python
from pydantic import BaseModel, Field

class Tools:
    class Valves(BaseModel):
        log_level: str = Field(
            default="info",
            description="Logging verbosity",
            json_schema_extra={
                "input": {
                    "type": "select",
                    "options": [
                        {"value": "debug", "label": "Debug (Verbose)"},
                        {"value": "info", "label": "Info (Standard)"},
                        {"value": "warn", "label": "Warning (Minimal)"},
                        {"value": "error", "label": "Error (Critical Only)"}
                    ]
                }
            }
        )
```

#### 动态选项 {#dynamic-options}

对于需要在运行时生成的选项（例如获取可用模型、数据库或与用户相关的资源），请把方法名以字符串形式指定。该方法会在每次打开 valves 对话框时被同步调用，并且必须返回一个列表。`async def` 返回的是协程，无法通过该检查，会导致该字段没有任何选项，并在日志中留下警告。该方法可以接收 `__user__` 或 `user` 参数，以 dict 的形式接收当前用户：

```python
from pydantic import BaseModel, Field

class Tools:
    class Valves(BaseModel):
        selected_model: str = Field(
            default="",
            description="Choose a model to use",
            json_schema_extra={
                "input": {
                    "type": "select",
                    "options": "get_model_options"  # Method name as string
                }
            }
        )

        @classmethod
        def get_model_options(cls, __user__=None) -> list[dict]:
            """
            Dynamically fetch available models.
            Called when the Valves configuration UI is opened.
            """
            # Example: Return options based on runtime state
            return [
                {"value": "gpt-5.6-sol", "label": "GPT-5.6 Sol"},
                {"value": "gpt-5.6-luna", "label": "GPT-5.6 Luna"},
                {"value": "claude-opus-5", "label": "Claude Opus 5"}
            ]
```

该方法可以接受一个可选的 `__user__` 参数，用于生成与用户相关的选项：

```python
from pydantic import BaseModel, Field

class Tools:
    class UserValves(BaseModel):
        workspace: str = Field(
            default="",
            description="Select your workspace",
            json_schema_extra={
                "input": {
                    "type": "select",
                    "options": "get_user_workspaces"
                }
            }
        )

        @classmethod
        def get_user_workspaces(cls, __user__=None) -> list[dict]:
            """
            Return workspaces available to the current user.
            __user__ contains the user's information as a dict.
            """
            if not __user__:
                return []

            user_id = __user__.get("id")
            # Fetch user-specific workspaces from your data source
            return [
                {"value": "ws-1", "label": "Personal Workspace"},
                {"value": "ws-2", "label": "Team Workspace"}
            ]
```

### 多选输入 {#multi-select-input}

当一个字段需要保存**多个**可选选项而不是一个时，请把它声明为列表，并使用 multiselect 输入类型。它会渲染成一个带复选框的下拉菜单，关闭状态下显示已选中的标签：

```python
from pydantic import BaseModel, Field

class Tools:
    class Valves(BaseModel):
        enabled_regions: list[str] = Field(
            default=["eu-west-1"],
            description="Regions to query",
            json_schema_extra={
                "input": {
                    "type": "multiselect",
                    "options": [
                        {"value": "eu-west-1", "label": "Europe (Ireland)"},
                        {"value": "us-east-1", "label": "US East (N. Virginia)"},
                        {"value": "ap-south-1", "label": "Asia Pacific (Mumbai)"}
                    ]
                }
            }
        )
```

选项的声明方式与 select 完全相同：可以是纯字符串列表，也可以是 `{"value": ..., "label": ...}` 键值对，或者是一个返回这些选项的方法名。

该值在整条链路上始终是一个真正的列表。其他 `list` 类型的 valves 会以逗号分隔的文本形式编辑，并在保存时再拆分回去，这导致任何包含逗号的选项都无法表达；multiselect 字段完全跳过了这一往返过程，因此你的代码接收到的就是与定义时完全一致的列表。

:::tip
动态选项尤其适合以下场景：
- 从已连接的提供商获取可用 API 模型
- 根据当前系统状态加载数据库或文件选项
- 呈现与用户相关的资源，例如项目或工作区
- 任何选项会随运行时上下文变化的情形
:::

### 滑块输入（数值区间） {#slider-input-number-ranges}

数值字段可以渲染为一个滑块，旁边配一个数字输入框。两者编辑的是同一个值，因此你可以拖动也可以直接输入。使用 range 输入类型，并通过 `ge` 与 `le` 设置两端边界：

```python
from pydantic import BaseModel, Field

class Tools:
    class Valves(BaseModel):
        temperature: float = Field(
            default=0.7,
            ge=0,
            le=2,
            description="Sampling temperature",
            json_schema_extra={"input": {"type": "range", "step": 0.1}}
        )
```

`step` 是可选的。不设置时，滑块以 1 为步长移动。请始终设置 `ge` 和 `le`，否则滑块的取值范围是 0 到 100。它在 `Valves` 和 `UserValves` 中都有效。

# 🪄 特殊参数 {#special-arguments}

在开发自己的 `Tools`、`Functions`（`Filters`、`Pipes`、`Actions`）、`Pipelines` 等时，你可以使用这些特殊参数来访问 Open WebUI 提供的完整上下文能力。

本页会详细说明每个特殊参数的类型、结构与示例。
### `body` {#body}

一个 `dict`，通常会几乎原样发送给模型。严格来说它不属于特殊参数，但因为它本身包含了一些特殊字段，所以这里也一并列出，便于查阅。

:::note `body` 在 Filter 的 `inlet()` 与 `request()` 中是不同的
`inlet()` 看到的是较早的 body，此时管道尚未运行；`request()` 看到的是最后的 body，即它发往提供方之前的样子。到那时，`features`、`variables`、`tool_ids`、`files`、`folder_id` 和 `skill_ids` 等键已被移除，而检索到的 RAG 来源以及解析后的 `tools` 数组则已被加入。下面的示例是一个 `inlet()` 形态的 body。参见 [`request` 在管道中的位置](/features/extensibility/plugin/functions/filter#where-request-sits-in-the-pipeline)。
:::

<details>
<summary>示例</summary>

```json

{
  "stream": true,
  "model": "my-cool-model",
  # lowercase string with - separated words: this is the ID of the model
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "What is in this picture?"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAdYAAAGcCAYAAABk2YF[REDACTED]"
            # Images are passed as base64 encoded data
          }
        }
      ]
    },
    {
      "role": "assistant",
      "content": "The image appears to be [REDACTED]"
    },
  ],
  "features": {
    "image_generation": false,
    "code_interpreter": false,
    "web_search": false
  },
  "stream_options": {
    "include_usage": true
  },
  "metadata": "[The exact same dict as __metadata__, present for Filters, removed before a Pipe sees it]",
  "files": "[The exact same list as __files__]"
}

```

### `__user__` {#\_\_user\_\_}
包含用户信息的 `dict`。它是 `UserModel.model_dump()` 返回的完整用户记录：`id`、`email`、`username`、`role`、`name`、`profile_image_url`、`profile_banner_image_url`、`bio`、`gender`、`date_of_birth`、`timezone`、`presence_state`、`status_emoji`、`status_message`、`status_expires_at`、`info`、`settings`、`oauth`（每个提供方一个条目，保存该提供方分配的 `sub`）、`scim`、`last_active_at`、`updated_at` 和 `created_at`。用户的 `variables` 不会包含在该转储中。下面的示例只展示了大多数插件会读取的字段。

请注意：如果定义了 `UserValves` 类，那么其实例必须通过 `__user__["valves"]` 访问；否则，`valves` 键将不会出现在 `__user__` 中。

<details>
<summary>示例</summary>

```json
{
  "id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "email": "cheesy_dude@openwebui.com",
  "name": "Patrick",
  "role": "user",
  # role can be either `user` or `admin`
  "valves": "[the UserValve instance]"
}
```

</details>

:::tip 判断请求来源

元数据中没有任何字段会直接指明调用方。区分它们的是聊天上下文：来自 Web 界面的请求总是带有 `chat_id` 和 `session_id`，而直接 API 调用得到的 `chat_id` 为空、`session_id` 为 `null`，除非客户端自行设置。这两个键始终存在，因此请检查它们的取值而不是是否存在：

```python
async def inlet(self, body: dict, __metadata__: dict = None) -> dict:
    metadata = __metadata__ or {}

    if metadata.get("chat_id") and metadata.get("session_id"):
        # Request from a chat session
        pass
    else:
        # Direct API request
        pass
    return body
```

:::

:::tip 在包裹前读取用户消息

当消息带有来源（sources）时，chat-completions 中间件会用默认引用模板包裹用户的最新消息。包裹发生在 Pipe 或 `pipe()` 调用看到 body 之前，仅当消息附带了来源时触发。直接读取 `body["messages"][-1]["content"]` 的 Pipe 会看到包裹后的形式。

`__metadata__["user_prompt"]` 保存的是包裹发生前的原始用户消息。原生工具调用循环和 Pipes 都从此读取，因此无论是否附加来源，它都是安全的。对于任何需要将用户输入交给下游模型的 Pipe，都应使用它。

```python
async def pipe(self, body: dict, __metadata__: dict, __user__: dict) -> str:
    user_prompt = __metadata__.get("user_prompt") or ""
    system_prompt = __metadata__.get("system_prompt")

    messages = []
    if system_prompt:
        messages.append({"role": "system", "content": system_prompt})
    messages.append({"role": "user", "content": user_prompt})
    # pass messages to your downstream model
```

如果 Pipe 运行的路径跳过了标准预处理（如直接 API 调用、某些测试场景），`__metadata__` 可能不存在。这时应扫描 `body["messages"]` 获取最后一条用户消息。

:::

### `__messages__` {#\_\_messages\_\_}

一个 `list`，包含此前的消息。

可参考前文 `body["messages"]` 的值结构。

### `__chat_id__` {#\_\_chat\_id\_\_}

当前聊天 / 会话唯一标识 `chat_id` 的字符串值。

Pipe、Tool 以及过滤器的 `inlet()` 和 `request()` 都会收到它（只要调用源自聊天上下文），包括：
- 普通用户消息
- 内部任务调用（标题生成、查询生成、标签生成等）

过滤器的 `stream()` 和 `outlet()` 拿不到它，Action 也一样。在那里请改读 `body["chat_id"]`。

这使得有状态的 functions / pipes / manifolds 能够以聊天粒度维护状态，而不会碎片化。

你也可以通过 `__metadata__["chat_id"]` 访问同一值。

### `__session_id__` {#\_\_session\_id\_\_}

`session_id` 的字符串值。

可参考 `__metadata__["session_id"]`。

### `__message_id__` {#\_\_message\_id\_\_}

`message_id` 的字符串值。

可参考 `__metadata__["message_id"]`。

### `__event_emitter__` {#\_\_event\_emitter\_\_}

一个 `Callable`，通过 socket.io 将当前聊天轮次的事件发送给所有订阅客户端（WebUI 是标准的订阅方）。Open WebUI 为当前助手轮次跟踪的 `message_id` 会自动包含在内。

最常见的事件是状态气泡：

```python
await __event_emitter__({
    "type": "status",
    "data": {"description": "Working...", "done": False},
})
```

`type` 字段不限于内建渲染类型。任意 `type` 字符串的事件都会通过 socket.io 转发，保留原始 `type` 值。当 Pipe 需要发送控制信号或自定义 UI 标记，让前端监听方（例如用户脚本）响应而不渲染到流式消息中时，这非常有用：

```python
await __event_emitter__({
    "type": "my-pipe:phase-changed",
    "data": {"phase": "reasoning"},
})
```

`status` 事件在聊天中原生渲染，因此用于展示用户应看到的进度信息。自定义事件类型则用于前端监听方在 Pipe 运行期间响应事件，而不改变可见的消息内容。

### `__event_call__` {#\_\_event\_call\_\_}
用于发送事件并等待浏览器回应的 `Callable`。Pipes、Filters、Tools 和 Actions 均可使用。

它会返回浏览器回传的内容。无法得到回应时，它不会抛出异常，而是返回一个带 `error` 键的 `dict`：如果标签页已经消失，则返回 `{"error": "Client session disconnected."}`；如果设置了 [`WEBSOCKET_EVENT_CALLER_TIMEOUT`](/reference/env-configuration#websocket_event_caller_timeout) 且已超时，则返回 `{"error": "Event call timed out. The browser tab may be inactive or closed."}`。未设置该变量时完全没有超时，调用将无限期等待。

### `__files__` {#\_\_files\_\_}

通过聊天发送的文件的 `list`，没有附件的消息中为空列表。管道和工具都会收到它。注意图片不视为文件，而是直接作为 `body["messages"]` 列表的一部分发送给模型。

出于性能考虑，参数中不包含文件的实际二进制内容，但仍可通过路径访问文件。例如使用 `docker` 时，路径的 Python 写法如下：

```python
from pathlib import Path

# `path` is a filesystem path under local storage; on S3, GCS or Azure it is a bucket URL
the_file = Path(__files__[0]["file"]["path"])
assert the_file.exists()
```

同一 files dict 也可通过 `__metadata__["files"]` 访问（未发送文件时其值为 `None`），或通过 `body["files"]` 访问（未发送文件时该键完全缺失）。

### `__request__` {#\_\_request\_\_}

`fastapi.Request` 的实例。详情可参阅[迁移页面](/features/extensibility/plugin/migration/)或 [FastAPI 官方文档](https://fastapi.tiangolo.com/reference/request/)。

### `__task__` {#\_\_task\_\_}

任务类型的 `str`。等同于 `__metadata__["task"]`，不存在则为 `None`。只有管道会收到它；声明了该参数的过滤器或工具即使在真正的任务调用中也不会拿到取值。

```json
    "memory_review"

```

### `__task_body__` {#\_\_task\_body\_\_}

包含执行给定 `__task__` 所需 `body` 的 `dict`。等同于 `__metadata__["task_body"]`，不存在则为 `None`。

其结构与上文的 `body` 相同，但会根据具体任务做相应调整，例如切换为合适的模型和系统消息等。

### `__tools__` {#\_\_tools\_\_}

以工具函数名为键的 `dict`，仅为管道注入。每个值包含 `tool_id`、`callable`（运行该工具的可等待对象）和 `spec`（发送给模型的 OpenAI 函数规范）。本地 Python 工具的条目还带有 `metadata`，而内置工具与外部工具服务器条目则带有 `type`，值为 `builtin` 或 `external`。

该 dict 由 [tools.py](https://github.com/open-webui/open-webui/blob/main/backend/open_webui/utils/tools.py) 中的 `get_tools()` 组装。

### `__oauth_token__` {#\_\_oauth\_token\_\_}

已登录用户的 OAuth 令牌数据（`access_token` 以及提供商返回的其余内容，过期后会刷新）组成的 `dict`；若该用户不是通过 OAuth 登录，或没有存储会话令牌，则为 `None`。管道、工具以及过滤器的 `inlet()` 和 `request()` 都会收到它。该令牌来自浏览器的 OAuth 会话 cookie；对于自动化以及不带 cookie 发起的 API 调用，会回退到该用户最近一次存储的 OAuth 会话。

### `__id__` {#\_\_id\_\_}

插件本身的 `str` 类型 id：对工具而言是工具 id，对过滤器而言是过滤器 id，对操作而言是操作 id（点击子操作时则是子操作 id）。管道不会收到它。

### `__body__` {#\_\_body\_\_}

仅过滤器可用。`stream()` 会把每个数据块作为 `event` 而非 `body` 接收，因此 `__body__` 承载的是该轮次发起时的请求体，其状态为 `inlet()` 过滤器运行之后。

### `__features__` {#\_\_features\_\_}

仅工具可用。来自请求的 `features` 字典（`web_search`、`image_generation`、`code_interpreter` 以及客户端发送的其他开关），取自 `inlet()` 过滤器运行之后的请求体，因此工具可以看到用户开启了哪些开关。

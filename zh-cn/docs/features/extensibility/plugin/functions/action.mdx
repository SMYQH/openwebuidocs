# 🎬 Action Function：自定义交互按钮 {#action-function-custom-interactive-buttons}

:::danger ⚠️ 关键安全警告
**Action Functions 会在你的服务器上执行任意 Python 代码。** 只有管理员才能创建 Function。请只从可信来源安装，并在导入前审查代码。恶意 Function 可能访问文件系统、窃取数据，甚至危及整套系统。完整说明请参阅 [Plugin Security Warning](/features/extensibility/plugin/)。
:::

Action functions 允许你编写自定义按钮，并将其展示在消息工具栏中供终端用户交互。这一能力可以让消息交互更加丰富：例如，在执行任务前向用户请求授权、为结构化数据生成可视化、下载聊天音频片段等等。

:::warning 为未来兼容性，请使用异步函数
Action functions 应始终定义为 `async`。后端正在逐步迁移到完全异步执行模型，同步函数在未来版本中可能阻塞执行或带来兼容性问题。
:::

Actions 是由管理员管理的函数，用于为聊天界面增加自定义交互能力。当某个模型启用了 actions 后，这些 action 会以可点击按钮的形式显示在消息上方。

下方的 [函数结构](#function-structure) 小节给出了最小脚手架示例。若要查看社区构建的真实 Action 示例，可前往 [openwebui.com](https://openwebui.com/)。

## Action Function 架构 {#action-function-architecture}

Actions 是基于 Python 的函数，可直接集成到聊天消息工具栏中。它们在服务端执行，并能通过实时事件与用户交互、修改消息内容，以及访问完整的 Open WebUI 上下文。

### 函数结构 {#function-structure}

Action 采用特定的类结构，核心入口是 `action` 方法：

``` python
class Action:
    def __init__(self):
        self.valves = self.Valves()

    class Valves(BaseModel):
        # 配置参数
        parameter_name: str = "default_value"
        priority: int = 0  # Controls button display order (lower = appears first)

    async def action(self, body: dict, __user__=None, __event_emitter__=None, __event_call__=None):
        # Action 逻辑
        return {"messages": [{"id": body["id"], "content": "Modified message content"}]}
```

### Action 方法参数 {#action-method-parameters}
`action` 方法会收到多个参数，用于提供执行上下文：

- **`body`**：聊天发送的请求，包含 `messages`（到目前为止的对话，每条记录带有 `id`、`role`、`content`、`timestamp`，以及消息存在时的 `info` 和 `sources`）、`model`、`chat_id`、`session_id` 和 `id`，其中 `id` 是触发该按钮的消息 ID。`content` 是该消息的输出文本（如果有）。其中不携带任何附件。
- **`__user__`**：以普通 `dict` 形式表示的用户记录（`UserModel.model_dump()`），当函数定义了 `UserValves` 时会额外加入 `valves` 条目
- **`__event_emitter__`**：向前端发送实时更新的函数
- **`__event_call__`**：用于双向通信（确认、输入）的函数
- **`__model__`**：触发该 action 的模型信息
- **`__request__`**：FastAPI request 对象，可访问 headers 等
- **`__id__`**：单个 action 的函数 ID。对于子 action，它只是子 action 的 ID（`summarize`，而不是 `my_fn.summarize`），因此子 action 的 ID 不能包含点号

### 返回值 {#return-value}

若要改变对话中显示的内容，请返回 `{"messages": [...]}`，其中每一项都携带某条已有消息的 `id` 以及要覆盖到它上面的字段。其它任何返回值都会交还给调用方并被丢弃，因此单独写一个 `{"content": "..."}` 什么也不会发生。唯一的例外是带有 `Content-Disposition: inline` 的 `HTMLResponse`，它会变成一个[富 UI 嵌入](/features/extensibility/plugin/development/rich-ui)。对于只负责产生副作用或更新事件发射器的操作，什么都不返回也没有问题。

## 事件系统集成 {#event-system-integration}

Actions 可以使用 Open WebUI 的实时事件系统构建交互体验：

### 事件发射器（`__event_emitter__`） {#event-emitter-\_\_event\_emitter\_\_}

**有关 Events 与 Event emitters 的完整说明，请参阅 [Events and Event Emitters](/features/extensibility/plugin/development/events/)。**

可在 action 执行过程中向前端发送实时更新：

``` python
async def action(self, body: dict, __event_emitter__=None):
    # 发送状态更新
    await __event_emitter__({
        "type": "status",
        "data": {"description": "Processing request..."}
    })

    # 发送通知
    await __event_emitter__({
        "type": "notification",
        "data": {"type": "info", "content": "Action completed successfully"}
    })
```

### 事件调用（`__event_call__`） {#event-call-\_\_event\_call\_\_}

在执行过程中请求用户输入或确认：

``` python
async def action(self, body: dict, __event_call__=None):
    # 请求用户确认
    response = await __event_call__({
        "type": "confirmation",
        "data": {
            "title": "Confirm Action",
            "message": "Are you sure you want to proceed?"
        }
    })

    # 请求用户输入
    user_input = await __event_call__({
        "type": "input",
        "data": {
            "title": "Enter Value",
            "message": "Please provide additional information:",
            "placeholder": "Type your input here..."
        }
    })
```

当浏览器无法作答时，`__event_call__` 会返回一个带 `error` 键的 `dict`，而不是抛出异常：可能是该标签页已经断开连接，或者设置了 [`WEBSOCKET_EVENT_CALLER_TIMEOUT`](/reference/env-configuration#websocket_event_caller_timeout) 且在超时前无人响应。使用结果前请先检查该键。参见[事件 → 交互式事件](/features/extensibility/plugin/development/events#interactive-events)。
## Action 类型与配置方式 {#action-types-and-configurations}

### 单一 Action {#single-actions}

标准 action 只有一个 `action` 方法：

``` python
async def action(self, body: dict, **kwargs):
    # 单 Action 实现
    return {"messages": [{"id": body["id"], "content": "Action result"}]}
```

### 多重 Action {#multi-actions}

Functions 可以通过 `actions` 数组定义多个子 action：

``` python
class Action:
    actions = [
        {
            "id": "summarize",
            "name": "Summarize",
            "icon_url": "https://example.com/icons/summarize.svg"
        },
        {
            "id": "translate",
            "name": "Translate",
            "icon_url": "https://example.com/icons/translate.svg"
        }
    ]

    async def action(self, body: dict, __id__=None, **kwargs):
        if __id__ == "summarize":
            # Summarization logic
            return {"messages": [{"id": body["id"], "content": "Summary: ..."}]}
        elif __id__ == "translate":
            # Translation logic
            return {"messages": [{"id": body["id"], "content": "Translation: ..."}]}
```

### 全局 Action 与模型级 Action {#global-vs-model-specific-actions}
- **全局 Action** —— 在 Action 的设置中打开开关，即可为所有用户和所有模型全局启用它。
- **模型专属 Action** —— 在模型设置中为特定模型配置已启用的 Action。

只有在启用状态下才会提供某个 Action。非管理员用户只能在其有权访问且会展示该 Action 的模型上运行它，而且只能在自己拥有的对话中运行。将 [`ENABLE_PLUGINS`](/reference/env-configuration#enable_plugins) 或 [`ENABLE_FUNCTIONS`](/reference/env-configuration#enable_functions) 设为 `false` 会完全禁用 Actions。

### 按钮显示顺序（Priority） {#button-display-order-priority}

助手消息下方的 action 按钮会根据 `priority` valve 值按**升序**排序——值越小越靠前（最左侧），值越大越靠后（最右侧）。默认值是 `0`。

若要控制顺序，请在 Action 的 Valves 中加入 `priority` 字段：

``` python
class Valves(BaseModel):
    priority: int = 0  # Lower = appears first in the button row
```

这与 [filter functions](/features/extensibility/plugin/functions/filter) 使用的是同一套优先级机制，因此整个插件系统的行为保持一致。若未定义 `priority` valve，则默认值为 `0`，同优先级之间按 **function ID 字母序** 排序。

## 高级能力 {#advanced-capabilities}

### 后台任务执行 {#long-running-actions}

对于耗时较长的操作，actions 可以与任务系统结合：

``` python
async def action(self, body: dict, __event_emitter__=None):
    # 开始长任务
    await __event_emitter__({
        "type": "status",
        "data": {"description": "Starting background processing..."}
    })

    # 执行耗时操作
    result = await some_long_running_function()

    return {"messages": [{"id": body["id"], "content": f"Processing completed: {result}"}]}
```

### 文件与媒体处理 {#file-and-media-handling}

action 收到的 payload 携带的是对话中的消息，而不是它们的附件，因此返回 `files` 列表不会产生任何作用。要访问某个聊天的文件，请结合聊天与文件 API 使用 `body["chat_id"]`，并通过 `__event_emitter__` 或改写消息内容来展现你的产出。

### 用户上下文与权限 {#user-context-and-permissions}

Actions 可以读取用户信息并遵循权限控制：

``` python
async def action(self, body: dict, __user__=None):
    if __user__["role"] != "admin":
        return {"messages": [{"id": body["id"], "content": "This action requires admin privileges"}]}

    user_name = __user__["name"]
    return {"messages": [{"id": body["id"], "content": f"Hello {user_name}, admin action completed"}]}
```

## 示例：指定 Action Frontmatter {#example-specifying-action-frontmatter}

每个 Action function 都可以在顶部 docstring 中写入元数据，用于自定义其在 Open WebUI 中的显示和行为。

支持的 frontmatter 字段包括：
- `title`：Action 显示名称
- `author`：作者名
- `version`：版本号
- `required_open_webui_version`：最低兼容的 Open WebUI 版本
- `icon_url (optional)`：图标 URL，可指向 PNG、SVG、JPEG 等。虽然技术上也支持 base64 data URI，但**强烈建议使用托管 URL**——见下方警告

:::danger 避免使用 Base64 图标——请改用 URL
不要把 base64 编码图片直接嵌入到 `icon_url` 中。每个 action 的图标数据都会被包含在 `/api/models` API 响应中，而该响应会在每次页面加载时，为**每个启用了该 action 的模型**发送到前端。

**影响示例：** 如果你给某个 action 使用了一个 500 KB 的 base64 图标，并且该 action 被 20 个模型启用，那么这个 API 响应就会额外膨胀 **20 × 500 KB = 约 10 MB**。如果再有 3 个类似 action，就会变成 **约 30 MB 的无谓载荷**。这会：
- **显著拖慢前端加载速度**
- **增加后端内存占用与网络带宽开销**
- **整体降低用户体验**，特别是在较慢网络环境下

正确做法是：把图标托管为静态资源（例如你的 Web 服务器、CDN 或公开 URL），然后用 URL 引用它。这样可以把 API 负载维持在最小水平。
:::

**示例（推荐做法：URL 图标）**

<summary>示例</summary>

``` python
"""
title: Enhanced Message Processor
author: @admin
version: 1.2.0
required_open_webui_version: 0.5.0
icon_url: https://example.com/icons/message-processor.svg
requirements: requests,beautifulsoup4
"""

from pydantic import BaseModel

class Action:
    def __init__(self):
        self.valves = self.Valves()

    class Valves(BaseModel):
        api_key: str = ""
        processing_mode: str = "standard"

    async def action(
        self,
        body: dict,
        __user__=None,
        __event_emitter__=None,
        __event_call__=None,
    ):
        # Send initial status
        await __event_emitter__({
            "type": "status",
            "data": {"description": "Processing message..."}
        })

        # Get user confirmation
        response = await __event_call__({
            "type": "confirmation",
            "data": {
                "title": "Process Message",
                "message": "Do you want to enhance this message?"
            }
        })

        if not response:
            return None

        # Process the message the button was pressed on
        message = body["messages"][-1]
        enhanced_content = f"Enhanced: {message.get('content', '')}"

        return {"messages": [{"id": body["id"], "content": enhanced_content}]}
```

## 最佳实践 {#best-practices}

### 错误处理 {#error-handling}

始终在 action 中做好错误处理：

``` python
async def action(self, body: dict, __event_emitter__=None):
    try:
        # Action logic here
        result = perform_operation()
        return {"messages": [{"id": body["id"], "content": f"Success: {result}"}]}
    except Exception as e:
        await __event_emitter__({
            "type": "notification",
            "data": {"type": "error", "content": f"Action failed: {str(e)}"}
        })
        return {"messages": [{"id": body["id"], "content": "Action encountered an error"}]}
```

从 `action()` 中逃逸出的异常会变成 HTTP 400、界面上的一个 toast 提示，以及按钮所在那条消息上的一个错误标记。

### 性能注意事项 {#performance-considerations}

- 对 I/O 操作使用 async / await
- 为外部 API 调用设置超时
- 对长时间任务提供进度反馈
- 对重型处理考虑使用后台任务

### 用户体验 {#user-experience}

- 始终通过 event emitters 提供清晰反馈
- 对破坏性操作使用确认对话框
- 提供有帮助的错误消息

## 与 Open WebUI 其他能力的集成 {#integration-with-open-webui-features}

Actions 可以与其他 Open WebUI 能力无缝协作：
- **Models** —— Actions 可按模型启用，也可全局启用
- **Tools** —— Actions 可调用外部 tools 与 API
- **Files** —— Actions 可处理上传文件并生成新文件
- **Memory** —— Actions 可访问对话历史与上下文
- **Permissions** —— Actions 遵守用户角色与访问控制
- **[Rich UI Embedding](/features/extensibility/plugin/development/rich-ui)** —— Actions 可以返回 HTML 内容，并在聊天中渲染为交互式 iframe

若要查看更多示例与社区贡献的 actions，请访问 [https://openwebui.com/search](https://openwebui.com/search)，在那里你可以发现、下载并研究由 Open WebUI 社区构建的自定义 functions。

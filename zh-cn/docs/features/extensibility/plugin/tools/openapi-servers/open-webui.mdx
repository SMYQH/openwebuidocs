## 概览 {#overview}

Open WebUI v0.6+ 支持通过 OpenAPI servers 无缝集成外部工具——这意味着你可以非常方便地使用自定义或社区提供的工具服务器来扩展自己的 LLM 工作流 🧰。

在本指南中，你将学习如何启动一个兼容 OpenAPI 的工具服务器，并通过直观的图形界面将其连接到 Open WebUI。开始吧！🚀

:::tip 选择能可靠使用工具的模型
外部工具依赖模型选择工具、生成有效参数并理解响应。支持工具调用并不代表能可靠地完成这些步骤。如果已经连接并启用的工具被忽略或使用不当，请先**尝试原生工具调用能力更可靠的强模型**，再判断是否为 Open WebUI 的问题。这适用于 OpenAPI 工具、原生 MCP 连接，以及通过 `mcpo` 暴露的 MCP 工具。
:::

---

## 第 1 步：启动一个 OpenAPI 工具服务器 {#step-1-launch-an-openapi-tool-server}

首先，你需要启动 [openapi-servers repo](https://github.com/open-webui/openapi-servers) 中提供的某个参考工具服务器。为了便于测试，这里以 time 工具服务器为例。

🛠️ 示例：在本地启动 `time` 服务器

```bash
git clone https://github.com/open-webui/openapi-servers
cd openapi-servers

# Navigate to the time server
cd servers/time

# Install required dependencies
pip install -r requirements.txt

# Start the server
uvicorn main:app --host 0.0.0.0 --reload
```

启动后，它会在 `http://localhost:8000` 提供一个本地 OpenAPI 服务器，你可以把 Open WebUI 指向该地址。

![Time 服务器](/images/openapi-servers/open-webui/time-server.png)

## 第 2 步：在 Open WebUI 中连接工具服务器 {#step-2-connect-tool-server-in-open-webui}

接下来，将正在运行的工具服务器连接到 Open WebUI。工具服务器有两种注册方式：

#### 1. 管理员添加的工具服务器 {#1-tool-servers-added-by-an-admin}

管理员添加供部署中的全部或指定用户使用的共享工具服务器：

1. 打开**设置 > 集成**（管理员区域），进入**工具**部分。
2. 点击加号按钮添加工具服务器。
3. 输入你的 OpenAPI 工具服务器的 URL，例如 `http://localhost:8000`。
4. 点击**保存**。

![设置页面](/images/openapi-servers/open-webui/settings.png)

请求由 Open WebUI 后端发送，因此后端必须能够访问该 URL。`localhost` 指后端服务器。如果后端在 Docker 中运行，容器中的 `localhost` 无法访问宿主机，请使用 `host.docker.internal` 或宿主机的实际 IP。如果工具服务器运行在同一个 Docker 网络的另一个容器中，请使用该容器的服务名和它在自己容器内监听的端口，例如 `http://time-server:8000`，而不是 `localhost` 或宿主机上发布的端口。参见 Docker 的 [Compose 中的网络](https://docs.docker.com/compose/how-tos/networking/)。只公开可供多人安全使用的端点。

#### 2. 在 Tether 中添加的工具服务器 {#2-tool-servers-added-in-tether}

用户在 Tether 应用中添加自己的 OpenAPI 工具服务器。服务器仅对添加者可见，从该用户的电脑经 Tether 访问，并显示在 **+** 菜单的**工具**列表中的**你的设备**下。参见[使用自己的模型和工具](/ecosystem/tether#bring-your-own-models-and-tools)。

### 👉 可选：结合 mcpo 使用配置文件 {#optional-using-a-config-file-with-mcpo}

如果你通过 mcpo 配置文件同时运行多个工具，需要注意：

🧩 每个工具都会挂载到一个独立路径下！

例如，如果你通过 mcpo 同时运行 memory 和 time 两个工具，它们会分别通过不同路由提供：

- `http://localhost:8000/time`
- `http://localhost:8000/memory`

这意味着：

- 在 Open WebUI 中连接工具时，必须填写该工具的完整路径，不要只填写根 URL（`http://localhost:8000`）。
- 在**设置 > 集成**（管理员区域）中，使用各工具对应的子路径 URL 逐一添加。

![MCPO 配置工具设置](/images/openapi-servers/open-webui/mcpo-config-tools.png)

✅ 正确示例：

`http://localhost:8000/time`  
`http://localhost:8000/memory`

🚫 错误示例：

`http://localhost:8000`

这样 Open WebUI 才能正确识别并连接到每个独立的工具服务器。

---

:::info 转发 Cookie

**高级 > 转发 Cookie**决定是否将浏览器请求中的 Cookie 发给该服务器。此项默认关闭。

只为你自己掌控、并且通过 Cookie 来认证请求发起者的服务器开启它，通常是你自己网络内、使用同一套登录体系的那类服务器。浏览器为你的 Open WebUI 域名保存的 Cookie 都会随请求发出，包括会话 Cookie，因此第三方端点绝不应该开启此项。

**这一点发生了变化：** 使用 **Session** 或 **System OAuth** 认证类型的连接过去会无条件转发 Cookie，现在不会了。如果这类连接在升级后不再能够通过认证，请开启此项。

:::

## 第 3 步：确认工具服务器已连接成功 ✅ {#step-3-confirm-your-tool-server-is-connected}

当聊天已选择工具，并且在 **设置 > 界面** 中开启了 **显示输入选择项** 时，消息输入框的 **+** 按钮旁会出现工具指示器：

![工具服务器指示器](/images/openapi-servers/open-webui/message-input.png)

点击该图标后，会弹出一个窗口，你可以：

- 查看当前聊天选择的工具，以及它们来自哪些工具服务器
- 展开 MCP 服务器，实时加载工具名称和说明
- 检查各个服务器是否已连接，或是否显示 **需要认证**，并通过 **重新连接** 再次登录

通过**系统 OAuth** 转发用户 SSO 令牌的工具服务器，会在该 SSO 会话失效后，在 **+ > 工具**中显示需要登录。选择该服务器会跳转到登录页面。

要断开 MCP 服务器的 OAuth，请在消息输入框的 **+ > 工具** 中，点击该工具旁的 **断开 OAuth**。

🔍 下图是工具信息弹窗展开后的样子：

![工具信息弹窗展开](/images/openapi-servers/open-webui/info-modal.png)

### 🛠️ 全局工具服务器的显示方式不同——而且默认隐藏！ {#global-tool-servers-look-different-and-are-hidden-by-default}

如果你连接了全局工具服务器（即由管理员配置的服务器），它不会自动出现在输入区域。

相反：

- 全局工具默认是隐藏的，必须按用户手动启用
- 你需要打开消息输入框的 **+** 菜单，选择 **工具**，再手动启用需要的全局工具
- 若希望使用某个模型的每个新对话都默认带上它，请把它加入模型编辑器（**工作区 > 模型**）中该模型的 **工具** 列表。该模型的每个新对话开始时，有权访问它的用户都会自动开启该工具服务器。用户仍可在对话中把它关闭。

效果如下：

![全局工具服务器消息输入](/images/openapi-servers/open-webui/global-message-input.png)

⚠️ 全局工具服务器注意事项：

- 在你从 **+** 菜单启用之前，它们不会显示在工具指示器弹窗中
- 每个全局工具都必须单独打开，才能在当前聊天中生效，除非该模型已把它列入 **工具** 列表
- 管理员可通过基于角色的权限控制来限制全局工具访问

这非常适合团队场景或共享环境：例如文档检索、memory 或 web lookup 这类常用工具，可以集中提供给多个用户使用。

## （可选）第 4 步：选择函数调用模式 {#optional-step-4-choosing-the-function-calling-mode}

原生函数调用是默认方式，因此不需要为它开启什么。模型使用自己内置的工具调用能力，这要求模型确实支持原生工具调用。某些本地模型口称支持原生工具调用，但实际效果往往差，所以如果可以选择，请优先使用原生工具调用能力稳健的模型。

`Legacy` 是另一种选项：Open WebUI 会将工具定义注入提示词，并在生成之前调用一次工具。它适用于更广泛的模型，但只能进行一轮工具调用；原生模式则会持续调用工具，直到模型完成。

切换模式的方法：

1. 打开聊天窗口。
2. 打开消息输入框旁的 **模型控制 > 控制 > 高级参数**。
3. 设置 **函数调用** 参数。`Default` 与 `Native` 行为完全一致，`Legacy` 则选择提示词注入。

![原生工具调用](/images/openapi-servers/open-webui/native.png)

## 故障排查与建议 🧩 {#troubleshooting--tips}

### 工具已启用，但模型没有正确使用它们 {#tools-are-enabled-but-the-model-does-not-use-them-correctly}

如果模型没有调用所需的工具就给出了回答、编造了工具结果、传入了无效参数，或在任务中途停下，原因可能出在模型能力上。Open WebUI 负责提供工具并执行调用；如何使用它们由模型决定。

1. 确认该工具在当前对话中已启用，并且所选模型支持原生工具调用。
2. 新开一个对话，只保留完成简单请求所需的工具，例如让时间工具返回当前时间。
3. 保持工具和服务端配置不变，换用能力更强的模型重复同一请求。如果该模型成功，那么原来的模型或其服务配置很可能就是原因。即使简单调用正常，多步骤工作流也可能需要更强的模型。

连接失败、认证错误和工具服务端错误仍需单独排查；换模型无法解决这些问题。关于模型选择的更多内容，请参阅[模型要求与注意事项](/features/extensibility/plugin/tools#model-requirements--caveats)。

### 添加 URL 后立刻连接失败 {#connection-fails-immediately-after-adding-the-url}

**先检查协议（HTTP vs HTTPS）。** 大多数本地工具服务器并未启用 TLS，因此 URL 应使用普通的 `http://`，例如 `http://localhost:8000`。

**再检查端口号。** 默认端口取决于 server 实现。例如 uvicorn 默认是 `8000`，而 Open Terminal 默认是 `8888`。请确认你填入的 URL 中端口与实际监听端口一致。

### 服务器正在运行，但连接失败 {#connection-fails-even-though-the-server-is-running}

**确认“localhost”指哪台机器。** 这是最常见的连接问题。请求由后端发送，因此 `localhost` 和 `host.docker.internal` 遵循[管理员所添加服务器的规则](#1-tool-servers-added-by-an-admin)。如果工具服务器位于另一台机器上，请确保它绑定到 `0.0.0.0`。

### 部分端点未出现在工具列表中 {#some-endpoints-are-missing-from-the-tool-list}

Open WebUI 会把 OpenAPI 规范中每个带 `operationId` 的操作变成一个工具，并以 `operationId` 作为工具名称。没有 `operationId` 的操作会被直接排除，既不报错也没有日志消息。请为模型应当调用的每个端点设置唯一的 `operationId`。

### 通用建议 {#general-tips}

- 🔒 如果你使用远程服务器，请检查防火墙与 HTTPS 配置
- 📝 如果你希望服务器在重启后仍保持运行，建议用 Docker 或系统服务来部署
- 无法判断时，请从发送请求的机器（Open WebUI 后端宿主机）上尝试打开工具服务器 URL，例如 `http://localhost:8000/docs`。

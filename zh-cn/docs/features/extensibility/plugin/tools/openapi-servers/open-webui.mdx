## 概览 {#overview}

Open WebUI v0.6+ 支持通过 OpenAPI servers 无缝集成外部工具——这意味着你可以非常方便地使用自定义或社区提供的工具服务器来扩展自己的 LLM 工作流 🧰。

在本指南中，你将学习如何启动一个兼容 OpenAPI 的工具服务器，并通过直观的图形界面将其连接到 Open WebUI。开始吧！🚀

---

## 第 1 步：启动一个 OpenAPI 工具服务器 {#step-1-launch-an-openapi-tool-server}

首先，你需要启动 [openapi-servers repo](https://github.com/open-webui/openapi-servers) 中提供的某个参考工具服务器。为了便于测试，这里以 time 工具服务器为例。

🛠️ 示例：在本地启动 `time` 服务器

```bash
git clone https://github.com/open-webui/openapi-servers
cd openapi-servers

# 进入 time server 目录
cd servers/time

# 安装所需依赖
pip install -r requirements.txt

# 启动 server
uvicorn main:app --host 0.0.0.0 --reload
```

启动后，它会在 `http://localhost:8000` 提供一个本地 OpenAPI 服务器，你可以把 Open WebUI 指向该地址。

![Time 服务器](/images/openapi-servers/open-webui/time-server.png)

---

## 第 2 步：在 Open WebUI 中连接工具服务器 {#step-2-connect-tool-server-in-open-webui}

接下来，把正在运行的工具服务器连接到 Open WebUI：

1. 在浏览器中打开 Open WebUI
2. 打开 ⚙️ **设置**
3. 点击 ➕ **工具** 添加一个新的工具服务器
4. 输入你的 OpenAPI 工具服务器运行地址（例如 `http://localhost:8000`）
5. 点击 “保存”

![设置页面](/images/openapi-servers/open-webui/settings.png)

### 🧑‍💻 用户级工具服务器 vs. 🛠️ 全局工具服务器 {#user-tool-servers-vs-global-tool-servers}

在 Open WebUI 中，有两种注册工具服务器的方式：

#### 1. 用户级工具服务器（通过普通设置添加） {#1-user-tool-servers-added-via-regular-settings}

- 仅对注册该工具服务器的用户可见
- 连接由用户浏览器直接发起（client-side）
- 非常适合个人工作流，或测试自定义 / 本地工具
- 只有在管理员在 **设置 > 管理 > 集成** 的 **用户连接** 分区中开启了 **直连集成**（[`ENABLE_DIRECT_INTEGRATIONS`](/reference/env-configuration#enable_direct_integrations)，默认关闭）时，设置中的集成标签页才会显示。开启后管理员会立即看到它。其他人还需要 **直连工具服务器** 权限（也是默认关闭）。在 **直连集成** 关闭期间，在这里保存的工具服务器不会在聊天中被使用；开启后会重新生效
- **Auth** 决定你的浏览器向服务器发送什么，既适用于对话框中的连接检查，也适用于保存后的连接：**Bearer** 发送密钥，**Session** 发送你的 Open WebUI 令牌，**None** 不发送任何内容

#### 2. 全局工具服务器（通过管理员设置添加） {#2-global-tool-servers-added-via-admin-settings}

管理员可以把共享工具服务器配置给整个部署中的所有用户或部分用户：

- 前往 🛠️ **管理员设置 > 工具**
- 按和普通用户设置相同的方式添加工具服务器 URL
- 这些工具的行为与 Open WebUI 自带工具类似

#### 核心区别：请求是从哪里发出的？ {#main-difference-where-are-requests-made-from}

**用户级工具服务器** 和 **全局工具服务器** 的主要区别，在于 API 连接与请求的实际发起位置：

- **用户级工具服务器**
  - 请求由**你的浏览器直接发出**
  - 这意味着你可以安全地连接 localhost 地址（如 `http://localhost:8000`）——甚至暴露你自己的本地文件系统或开发环境 endpoint，而不会把它们暴露给外网或其他用户
  - 你的连接是隔离的，只有你的浏览器可以访问该工具服务器

- **全局工具服务器**
  - 请求由 **Open WebUI 后端 / 服务器** 发出，而不是浏览器
  - 因此这里的 `localhost` 指的是后端服务器自身，而不是你的个人电脑
  - 适合需要在整个部署中共享的工具，但要注意：由于是后端发请求，所以它不能通过这种方式访问你个人电脑上的本地资源（例如你自己的文件系统）
  - 因此在安全上要格外注意：只暴露那些适合被多个用户访问的远程 / 全局 endpoint

**总结表：**

| 工具服务器类型   | 请求来源        | 是否可用 Localhost | 典型场景 |
| ------------------ | -------------------- | ------------------ | ---------------------------------------- |
| 用户级工具服务器   | 用户浏览器（Client-side） | 可以（仅你可用） | 个人工具、本地开发 / 测试 |
| 全局工具服务器 | Open WebUI 后端（Server-side） | 不可以（除非它本身就跑在后端机器上） | 团队共享工具、企业集成 |

:::tip

用户级工具服务器更适合个人或实验性工具，特别是运行在你自己机器上的工具；全局工具服务器则更适合生产环境或共享部署，让所有人都能访问同一组工具。

:::

### 👉 可选：结合 mcpo 使用配置文件 {#optional-using-a-config-file-with-mcpo}

如果你通过 mcpo 配置文件同时运行多个工具，需要注意：

🧩 每个工具都会挂载到一个独立路径下！

例如，如果你通过 mcpo 同时运行 memory 和 time 两个工具，它们会分别出现在不同 route 上：

- `http://localhost:8000/time`
- `http://localhost:8000/memory`

这意味着：

- 在 Open WebUI 中连接工具时，你必须填写该工具的**完整路径**
- **不要**只填写根 URL（`http://localhost:8000`）
- 你需要在 Open WebUI Settings 中用各自的子路径 URL 分别添加每个工具

![MCPO 配置工具设置](/images/openapi-servers/open-webui/mcpo-config-tools.png)

✅ 正确示例：

`http://localhost:8000/time`  
`http://localhost:8000/memory`

🚫 错误示例：

`http://localhost:8000`

这样 Open WebUI 才能正确识别并连接到每个独立的工具服务器。

---

:::info 转发 Cookie

**高级设置 > 转发 Cookie** 决定浏览器请求中的 Cookie 是否会被转发到该服务器。它默认关闭，且只作用于管理员配置的连接；用户自己的直连永远不会转发 Cookie。

只为你自己掌控、并且通过 Cookie 来认证请求发起者的服务器开启它，通常是你自己网络内、使用同一套登录体系的那类服务器。浏览器为你的 Open WebUI 域名保存的所有内容都会随请求一起过去，包括会话 Cookie，因此第三方端点绝不应该开启它。

**这一点发生了变化：** 使用 **Session** 或 **System OAuth** 认证类型的连接过去会无条件转发 Cookie，现在不会了。如果这类连接在升级后不再能够通过认证，请开启此项。

:::

## 第 3 步：确认工具服务器已连接成功 ✅ {#step-3-confirm-your-tool-server-is-connected}

当工具服务器成功连接后，Open WebUI 会在消息输入区域直接显示一个 👇 工具服务器指示器：

📍 你会在输入框下方看到这个图标：

![工具服务器指示器](/images/openapi-servers/open-webui/message-input.png)

点击该图标后，会弹出一个窗口，你可以：

- 查看已连接工具服务器的信息
- 查看有哪些工具可用，以及它们来自哪个服务器
- 在需要时调试或断开某个工具

🔍 下图是工具信息弹窗展开后的样子：

![工具信息弹窗展开](/images/openapi-servers/open-webui/info-modal.png)

### 🛠️ 全局工具服务器的显示方式不同——而且默认隐藏！ {#global-tool-servers-look-different-and-are-hidden-by-default}

如果你连接的是全局工具服务器（也就是管理员配置的工具），它不会像用户级工具服务器一样自动出现在输入区域。

相反：

- 全局工具默认是隐藏的，必须按用户手动启用
- 你需要点击聊天输入框左下角的 ➕ 按钮，并手动打开你想使用的特定全局工具

效果如下：

![全局工具服务器消息输入](/images/openapi-servers/open-webui/global-message-input.png)

⚠️ 关于 Global Tool Servers 的重要说明：

- 在你从 ➕ 菜单启用之前，它们不会显示在工具指示器弹窗中
- 每个全局工具都必须单独打开，才能在当前聊天中生效
- 一旦启用，它们的使用方式就和用户级工具一样
- 管理员可通过基于角色的权限控制来限制全局工具访问

这非常适合团队场景或共享环境：例如文档检索、memory 或 web lookup 这类常用工具，可以集中提供给多个用户使用。

## （可选）第 4 步：启用 “Native” Function Calling（ReACT 风格）🧠 {#optional-step-4-choosing-the-function-calling-mode}

原生函数调用是默认方式，因此不需要为它开启什么。模型使用自己内置的工具调用能力，这要求模型确实支持原生工具调用。某些本地模型口称支持原生工具调用，但实际效果往往差，所以如果可以选择，请优先使用原生工具调用能力稳健的模型。

`Legacy` 是另一种选项：Open WebUI 会将工具定义注入提示词，并在生成之前调用一次工具。它适用于得太更广泛的模型，代价是只能限于那一轮单次工具调用，而原生模式会不断调用工具，直到模型完成。

切换模式的方法：

1. 打开聊天窗口。
2. 打开消息输入框旁的 **Model controls > Controls > Advanced Params**。
3. 设置 **Function Calling** 参数。`Default` 与 `Native` 行为完全一致，`Legacy` 则选择提示词注入。

![原生工具调用](/images/openapi-servers/open-webui/native.png)

## 故障排查与建议 🧩 {#troubleshooting--tips}

### 工具已启用，但模型没有正确使用它们 {#tools-are-enabled-but-the-model-does-not-use-them-correctly}

如果模型没有调用所需的工具就给出了回答、编造了工具结果、传入了无效参数，或在任务中途停下，原因可能出在模型能力上。Open WebUI 负责提供工具并执行调用；如何使用它们由模型决定。

1. 确认该工具在当前对话中已启用，并且所选模型支持原生工具调用。
2. 新开一个对话，只保留完成简单请求所需的工具，例如让时间工具返回当前时间。
3. 保持工具和服务端配置不变，换用能力更强的模型重复同一请求。如果该模型成功，那么原来的模型或其服务配置很可能就是原因。即使简单调用正常，多步骤工作流也可能需要更强的模型。

连接失败、认证错误和工具服务端错误仍需单独排查；换模型无法解决这些问题。关于模型选择的更多内容，请参阅[模型要求与注意事项](/features/extensibility/plugin/tools#model-requirements--caveats)。

### 添加 URL 后立刻连接失败 {#connection-fails-immediately-after-adding-the-url}

**先检查协议（HTTP vs HTTPS）。** “添加工具服务器” 弹窗可能会默认填入 `https://`。但大多数本地工具服务器并未启用 TLS，因此你需要改成普通的 `http://`。例如改为 `http://localhost:8000`（或你的实际端口）。

**再检查端口号。** 默认端口取决于 server 实现。例如 uvicorn 默认是 `8000`，而 Open Terminal 默认是 `8888`。请确认你填入的 URL 中端口与实际监听端口一致。

### 明明 server 在运行，但依然连接失败 {#connection-fails-even-though-the-server-is-running}

**理解 “localhost” 指向的是哪台机器。** 这是最常见的问题，而且会随工具服务器类型不同而变化：

- **用户级工具服务器** —— 请求来自**你的浏览器**。这里的 `localhost` 指的是*运行浏览器的那台机器*
- **全局工具服务器** —— 请求来自 **Open WebUI 后端**。这里的 `localhost` 指的是*后端服务器本身*，而不是你的电脑。如果后端跑在 Docker 中，那么容器里的 `localhost` 不会指向宿主机——此时应改用 `host.docker.internal` 或后端服务器实际 IP

:::warning 用户级工具服务器：浏览器所在地址也很重要

即使是用户级工具服务器，只有当你在浏览器中通过 `http://localhost:...` 访问 Open WebUI 时，`localhost` 才通常会正常工作。

如果你访问 Open WebUI 用的是其他 IP 地址——例如通过局域网里的 `http://10.0.0.5:3000` 从另一台设备访问，或者使用 `npm run dev` 输出的 network URL——那么此时浏览器眼中的 `localhost` 就**不是**工具服务器所在机器，而是**浏览器当前运行的设备**。

**解决办法：** 把 `localhost` 换成实际运行工具服务器那台机器的 IP（例如 `http://10.0.0.5:8000`），并确保工具服务器绑定在 `0.0.0.0` 上，而不是仅绑定到 `127.0.0.1`。

:::

### 浏览器控制台出现 CORS 错误 {#cors-errors-in-the-browser-console}

如果你看到了 CORS 报错，说明工具服务器需要允许来自 Open WebUI origin 的请求。你可以查看 [FAQ 中关于 CORS 的条目](/features/extensibility/plugin/tools/openapi-servers/faq)，其中提供了 FastAPI 示例。

### 通用建议 {#general-tips}

- 🔒 如果你使用远程服务器，请检查防火墙与 HTTPS 配置
- 📝 如果你希望服务器在重启后仍保持运行，建议用 Docker 或系统服务来部署
- 🔍 不确定时，直接在**同一个浏览器**中打开工具服务器 URL（例如 `http://localhost:8000/docs`）——如果能打开，说明浏览器能访问该服务器

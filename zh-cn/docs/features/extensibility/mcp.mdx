Open WebUI 从 **v0.6.31** 起原生支持 **MCP（Model Context Protocol）**。本页介绍如何快速启用、加固生产环境配置以及排查常见问题。

:::info 
需要 **Open WebUI v0.6.31+**。
:::

:::tip MCP 工具需要胜任的模型
MCP 把 Open WebUI 与你的工具连接起来，但它不会提升模型使用工具的能力。即使连接正常，模型也可能忽略工具、给出错误的参数，或无法完成多步骤任务。出现这种情况时，**请换用原生工具调用更可靠的更强模型**。仅仅是工具用得不好，并不代表 Open WebUI 或 MCP 集成出了问题。参见[排查模型工具使用问题](/features/extensibility/plugin/tools/openapi-servers/open-webui#tools-are-enabled-but-the-model-does-not-use-them-correctly)。
:::

:::danger 前置条件：WEBUI_SECRET_KEY
在 Docker 配置中，你**必须**设置 `WEBUI_SECRET_KEY` 环境变量。若未设置，每次重启或重建容器后，**通过 OAuth 连接的 MCP 工具（如 Notion）**都会**失效**（错误：`Error decrypting tokens`），迫使你重新进行身份验证。
:::

## 🚀 快速开始 {#quick-start}

1. 打开 **设置 > 集成**（管理员区域）。
2. 在 **外部工具服务器**，点击 **+ 添加连接**。“集成”页面包含多个部分，请确保您选择的是该部分。
3. 将**类型**设置为 **MCP (Streamable HTTP)**。
4. 输入你的**服务器 URL** 和**身份验证**详情（如需要，OAuth 2.1）。
5. **保存**。如有提示，重启 Open WebUI。

![管理员设置中的外部工具服务器](/images/admin/admin-integrations.png)

现在你可以从 Open WebUI 调用 MCP 服务器暴露的工具了。

Open WebUI 以无状态的 `2026-07-28` 协议修订版连接服务器，同时也兼容更旧的修订版。只有当重定向仍位于同一源时，它才会跟随重定向。

当 [`ENABLE_TOOL_SERVERS`](/reference/env-configuration#enable_tool_servers) 被设置为 `False` 时，**外部工具服务器**部分会置灰。

:::warning 常见错误：连接类型错误
添加 MCP 服务器时，请确保**类型**设置为 **MCP (Streamable HTTP)**，而不是 **OpenAPI**。

将 MCP 风格的配置（包含 `mcpServers` 的 JSON）输入到 OpenAPI 连接中会导致 UI 崩溃或显示无限加载页面。如遇此情况：

1. 通过 **设置 > 集成**（管理员区域）禁用存在问题的工具连接
2. 以正确的**类型**重新添加为 **MCP**
:::

## 🔒 MCP 服务器仅限管理员添加 {#mcp-servers-are-admin-only}

只有**管理员**能在**设置 > 集成**（管理员区域）中向实例添加 MCP 服务器。根据设计，普通用户无法在实例上注册这类服务器。

MCP 服务器的能力远超 OpenAPI 服务器，后者通过无状态 HTTP URL 提供一组固定的已声明端点。前者有状态，支持采样、信息征询和持久会话，还可以经 stdio 传输执行任意宿主机命令。它在 Open WebUI 的信任边界内以连接用户的完整权限运行。恶意或遭入侵的 MCP 服务器可能在该用户的权限范围内执行代码、读取或外泄数据，因此此能力仅限管理员。Open WebUI 自身只支持 Streamable HTTP，但协议本身具有高权限，所以只有管理员能添加 MCP 服务器。

如果用户需要使用 MCP 功能但不应获得服务器配置权限，管理员可添加一次服务器，并在**访问控制**中指定对应的用户或群组。用户也可在 [Tether](/ecosystem/tether#bring-your-own-models-and-tools) 应用中为自己添加 MCP 服务器。

## 🧭 何时使用 MCP vs OpenAPI {#when-to-use-mcp-vs-openapi}

:::tip 
对于大多数部署，**OpenAPI** 仍是**首选**集成路径。
:::

选择 **OpenAPI** 适合你需要：

* **企业就绪性**：深度 SSO、API 网关、审计、配额、类型化 SDK。
* **运营弹性**：标准 HTTP 动词、幂等性、缓存、丰富的错误码。
* **可观测性**：一流的链路追踪和策略集成。

选择 **MCP (Streamable HTTP)** 适合你需要：

* MCP 服务器/客户端已使用的**通用工具协议**。
* 通过 HTTP 进行的**流式**协议通信（注意：这指的是 MCP 的传输层流式传输，而不是 Open WebUI 的 [UI 事件系统](/features/extensibility/plugin/development/events)，后者仅适用于原生 Python 工具）。

> 你不必只选一个：许多团队内部使用 OpenAPI，并在边缘为特定客户端**封装 MCP**。

:::warning
基于浏览器的多用户部署会扩大攻击面（CORS/CSRF、用户间隔离、重连等）。在将 MCP 对外暴露之前，请先审查贵组织的认证、代理和限流策略。
:::

## ⚙️ 配置最佳实践 {#configuration-best-practices}

### 身份验证模式 {#authentication-modes}

*   **None**：适用于**本地 MCP 服务器**或不需要令牌的内网。
    *   **⚠️ 重要**：除非服务器严格要求令牌，否则默认选择 "None"。在未提供密钥的情况下选择 "Bearer" 会发送空的 Authorization 标头（`Authorization: Bearer`），导致许多服务器立即拒绝连接。
*   **Bearer**：**仅**在你的 MCP 服务器需要特定 API 令牌时使用。**必须**填写 "Key" 字段。
*   **Session**：将用户自身的 Open WebUI 会话令牌作为 bearer token 发送。适用于以 Open WebUI 自身为依据进行身份验证的服务器。
*   **OAuth**：将用户通过 Open WebUI SSO 登录时生成的访问令牌作为 bearer token 发送。仅在用户通过同一 OAuth 提供商登录 Open WebUI，且其令牌包含 MCP 服务器所需的权限范围时，此方法才有效。
*   **OAuth 2.1**：使用动态客户端注册（DCR）。最适合你的 MCP 服务器支持自动注册 OAuth 客户端的情况。
*   **OAuth 2.1（静态）**：使用预先创建的客户端 ID/客户端密钥。最适合你的提供商不支持 DCR，或你的安全团队要求手动管理凭据的情况。

:::info OAuth Resource 参数

使用 **OAuth 2.1** 或 **OAuth 2.1（静态）** 时，会出现 **OAuth 资源参数** 设置。它控制 Open WebUI 是否在授权和令牌请求中发送 OAuth `resource` 参数（[RFC 8707 资源指示符](https://datatracker.ietf.org/doc/html/rfc8707)）：

- **自动**（默认）：Open WebUI 根据服务器公告的内容决定。
- **包含**：始终发送 `resource` 参数。如果你的提供商要求此参数，请使用此项。
- **省略**：从不发送。如果你的提供商在存在 `resource` 参数时拒绝请求，请使用此项。

除非 OAuth 失败且提供商错误或文档指向 `resource` 参数，否则请保持默认的**自动**。

:::

:::info OAuth 作用域

在 **OAuth 2.1** 或 **OAuth 2.1（静态）** 模式下，**OAuth 作用域** 设置用于控制 Open WebUI 向服务器的授权服务器请求哪些范围：

- **使用已发现的范围**（默认）：请求服务器 OAuth 元数据中公告的范围。
- **自定义范围**：提供显式的、以空格或逗号分隔的列表来覆盖已发现的范围，例如请求比服务器公告的更窄的集合，或当服务器的元数据未列出可用的范围时。

:::

:::info 没有 OAuth 发现文档的服务器
Open WebUI 通过服务器发布的 OAuth 发现文档来定位授权服务器。有些 MCP 服务器不发布任何发现文档。当找不到发现文档、且服务器的受保护资源元数据也没有指明授权服务器时，Open WebUI 会使用 [MCP 2025-03-26 授权规范](https://modelcontextprotocol.io/specification/2025-03-26/basic/authorization)为这种情况定义的默认端点：在 MCP **URL** 的源（若设置了 **OAuth 服务器 URL**，则以其源）上的 `/authorize`、`/token` 和 `/register`。以 `https://mcp.example.com/v1/mcp` 为例，即 `https://mcp.example.com/authorize`、`https://mcp.example.com/token` 和 `https://mcp.example.com/register`。登录与令牌刷新使用 `/authorize` 和 `/token`，**OAuth 2.1** 则在 `/register` 注册其客户端。

当受保护资源的元数据指定了一个授权服务器，但无法获取任何发现文档时，**注册客户端**操作将因错误而失败。
:::

:::info 检查 OAuth 发现
在使用 **OAuth 2.1** 或 **OAuth 2.1（静态）** 的 MCP 连接中，URL 旁边的“验证”按钮显示为 **检查 OAuth 发现**，绿色结果会显示“OAuth 发现成功”。该过程会读取服务器的受保护资源元数据，随后获取 OAuth 发现文档并进行解析，其操作仅限于此。它既不列出任何工具，也不调用任何工具，因此检查通过仅表示已找到授权服务器，但无法说明工具调用是否能正常工作。

只有在找到发现文档时，该检查才会通过。未发布任何发现文档的服务器将导致检查失败，但对于该服务器而言，**注册客户端**仍可通过上述默认端点正常工作。

在 **OAuth 2.1（静态）** 模式下，如果已设置 **OAuth 服务器 URL**，则检查该地址；如果该字段留空，则检查 MCP **URL**。
:::

:::tip 在 OAuth 2.1 和 OAuth 2.1（静态）之间选择

- 如果服务器支持 DCR，从 **OAuth 2.1** 开始。
- 当你已经有来自 IdP 的凭据且希望 Open WebUI 直接使用时，使用 **OAuth 2.1（静态）**。

:::

### 连接账户 {#connecting-an-account}

管理员只需注册一次 MCP 服务器，随后每位用户分别连接自己的账户。当用户首次在对话中从 **+** 菜单启用 OAuth 2.1 工具时，Open WebUI 会将其引导至提供商。授予的访问权限仅保存在该用户的账户下，不会由其他人继承。

授权与发起它的账户以及发起它的浏览器会话绑定，因此必须在同一个浏览器中、以同一个人的身份、在 [`WEBUI_URL`](/reference/env-configuration#webui_url) 所指的地址上完成。退出登录会取消进行中的授权。任何其他情况都会让浏览器带着一条说明原因的通知回到 Open WebUI；重新启用该工具即可重试。

管理员也可以直接从连接本身发起该流程。OAuth 客户端注册完成并保存连接后，在**设置 > 集成**（管理员区域）中重新打开该连接，会在 **注册客户端** 旁边看到 **授权 OAuth** 按钮。它发出的授权请求与在对话中启用工具时发出的完全一致，条件也相同：授权存储在管理员自己的账户上，其他人不会继承。该按钮只有在客户端注册之后才会出现，并且在连接至少保存过一次之前保持置灰。

流程结束时，身份提供商会把浏览器送回 Open WebUI 首页，请重新打开**设置 > 集成**（管理员区域）继续编辑该连接。

### OAuth 2.1（静态）设置 {#oauth-21-static-setup}

当你已经有来自身份提供商的客户端 ID/客户端密钥时使用。

:::info 重定向 URI
身份提供商处的 OAuth 客户端必须允许以下重定向 URI：

```text
<WebUI URL>/oauth/clients/mcp:<Connection ID>/callback
```

对于位于 `https://ai.example.com` 的实例，以及 **Connection ID** 为 `notion` 的连接，即 `https://ai.example.com/oauth/clients/mcp:notion/callback`。`<WebUI URL>` 是**管理面板 > 设置 > 常规**中的 **WebUI URL** 字段（[`WEBUI_URL`](/reference/env-configuration#webui_url)）。点击**注册客户端**之前，请把它设为用户访问 Open WebUI 的公开地址。该字段为空时，Open WebUI 会使用注册客户端时那次请求的地址。

**注册客户端**用它当时看到的 **WebUI URL** 和 **Connection ID** 拼出重定向 URI，保存后的连接会保留该值。更改 **WebUI URL** 或 **Connection ID** 之后，请再次点击**注册客户端**、点击**保存**，并在身份提供商处更新重定向 URI。**OAuth 2.1** 在动态客户端注册时发送同样的重定向 URI，因此你无需在任何地方输入它。
:::

1. 打开 **设置 > 集成**（管理员区域）。
2. 在 **外部工具服务器**，点击 **+ 添加连接**。“集成”页面包含多个部分，请确保您选择的是该部分。
3. 将**类型**设置为 **MCP（Streamable HTTP）**。
4. 输入你的 MCP 服务器 **URL**。
5. 在**认证**中，选择 **OAuth 2.1（静态）**。
6. 输入**客户端 ID** 和**客户端密钥**。
7. *（可选）* 如果你的身份提供商与 MCP 资源服务器不在同一主机上，输入 **OAuth 服务器 URL**。留空时，Open WebUI 会从 MCP 的 **URL** 获取 OAuth discovery 文档；填入后，discovery 和静态凭据注册都会改用此 URL。这对 MCP 服务器在独立源代理企业 IdP 的场景很有用。
8. 点击**注册客户端**。
9. 点击**保存**。

保存后：

1. 打开一个对话。
2. 点击 **+ > 工具**。
3. 启用你的 MCP 工具。
4. 在浏览器重定向中完成 OAuth 同意/授权流程。

重定向后，您将回到一个新的聊天界面，此时 MCP 工具已开启，并位于模型默认启用的其他工具旁边。

重新打开该连接并点击 **授权 OAuth**，无需打开对话也能为自己的账户完成同样的事。参见[连接账户](#connecting-an-account)。

:::info

`Register Client` 对 `oauth_2.1` 和 `oauth_2.1_static` 都是必需的。在静态认证下，Open WebUI 使用你提供的凭据以及服务器元数据发现（不进行动态客户端注册）。

静态认证会在请求体中发送客户端密钥（`client_secret_post`）。如果服务器声明只支持 `client_secret_basic` 认证方式，则改用 HTTP Basic 请求头。

:::

:::info 资源指示符（RFC 8707）

如果 MCP 服务器在其 [RFC 9728 Protected Resource Metadata 文档](https://datatracker.ietf.org/doc/html/rfc9728)（`/.well-known/oauth-protected-resource`）中发布了 `resource` 字段，Open WebUI 会在 discovery 期间捕获它，并作为 `resource` 参数转发到**授权重定向**、**令牌交换**和每次**刷新令牌调用**上。这样会在签发的令牌上正确设置 `aud` 声明，符合按照 [RFC 8707](https://datatracker.ietf.org/doc/html/rfc8707) 严格校验受众的身份提供商要求。

Open WebUI 这边不需要任何配置——resource indicator 会自动被发现。如果你的 IdP 以 `invalid_audience` 或类似错误拒绝 MCP 工具调用，请确认 MCP 服务器的受保护资源元数据文档中发布的 `resource` URL 正确。

:::

:::warning OAuth 2.1 工具不能被设为默认工具
**不要把 OAuth 2.1 MCP 工具设置为模型的默认/预启用工具。** OAuth 2.1 授权流程需要一个交互式浏览器重定向（用户同意、回调），这在 chat completion 请求过程中无法静默完成。

如果某个 OAuth 2.1 工具被设为默认工具，而用户此前从未进行过身份验证（或刷新令牌已过期），那么工具调用会失败并提示 **"Failed to connect to MCP server"**，因为后端无法在请求中途发起基于浏览器的认证流程。

**变通方案：** 用户应通过聊天输入区的 **+** 按钮按每个对话手动启用 OAuth 2.1 工具。这样会在工具被调用前触发认证流程。一旦完成初次认证，令牌刷新会自动进行。刷新过程中若发生临时提供商错误（速率限制、服务器错误或无法连接提供商），系统将保留已存储的登录信息，并在下次调用时再次尝试。若刷新请求被提供商拒绝，系统将清除已存储的登录信息，此时您需要重新登录。
:::


### 连接 URL {#connection-urls}

Open WebUI 后端会发起该连接，因此 URL 必须从后端可达，而不是从浏览器可达。该 URL 必须指向服务器的 Streamable HTTP 端点。SSE 端点不可用，参见[SSE URL 无法连接](#an-sse-url-does-not-connect)。

如果你在 **Docker** 中运行 Open WebUI，而 MCP 服务器在**宿主机**上：
*   使用 `http://host.docker.internal:<port>`（如 `http://host.docker.internal:3000/mcp`）而不是 `localhost`。

如果 MCP 服务器与 Open WebUI 运行在**同一个 Docker 网络的另一个容器**中：
*   使用该容器的服务名和服务器在其容器内监听的端口（如 `http://mcp-server:8000/mcp`）。从 Open WebUI 容器内部无法通过 `localhost` 或宿主机上发布的端口访问它。参见 Docker 的 [Compose 中的网络](https://docs.docker.com/compose/how-tos/networking/)。

### 自定义标头 {#custom-headers}
无论是 MCP 还是 OpenAPI 工具服务器连接，都支持一个自由格式的 **Headers** 字段（JSON 对象），其内容会被合并进每一次出站请求。Header 值支持模板占位符，例如 `{{USER_ID}}`、`{{USER_EMAIL}}`、`{{USER_GROUPS}}`、`{{CHAT_ID}}`、`{{MESSAGE_ID}}`、`{{MODEL_ID}}` 和 `{{USER_IP}}`，Open WebUI 会在请求发起时将它们展开。这样无需为每个用户、每个聊天或每条消息单独配置连接，就能让同一条连接路由到不同的后端逻辑，也允许工具服务器按用户组（而非单个用户）进行鉴权。

[自定义转发标头](/reference/env-configuration#custom-forwarded-headers-per-connection) 列出了每个占位符及其含义。对于本次请求没有取值的占位符（例如 **验证连接** 按钮上的 `{{CHAT_ID}}` 和 `{{USER_IP}}`），会变成空字符串。未知占位符按字面文本原样传递，非字符串的标头值会在替换前转换为字符串。**设置 > 连接**（管理员区域）中兼容 OpenAI 的模型连接所使用的自定义标头，其展开方式相同。

### 函数名称过滤列表 {#function-name-filter-list}

该字段用于限制向 LLM 暴露哪些工具。
*   **默认值**：留空即暴露全部工具（大多数情况下）。
*   **变通办法**：如果列表为空时遇到连接错误，可以尝试在该字段中添加一个逗号（`,`）。这会强制系统将其视为有效的（但为空的）过滤器，从而可能绕过某些解析问题。

### 模型看到的工具名称 {#tool-names-the-model-sees}

Open WebUI 会以 `<server ID>_<tool name>` 的形式向模型提供每个 MCP 工具。某些提供商（例如 OpenAI API 和 AWS Bedrock）会拒绝工具名超过 64 个字符的请求，因此较长的名称会被缩短为其前 55 个字符、一个下划线以及 8 位哈希。同一个工具总会得到相同的缩短名称，而调用 MCP 服务器时仍使用原始工具名。

启用大量 MCP 工具后，[工具搜索](/features/extensibility/plugin/tools#tool-search) 会把庞大的工具定义排除在每次请求之外，直到模型主动查找。它的 **始终加载的工具** 模式正是针对这些名称，因此 `github_*` 会让 ID 为 `github` 的服务器的所有工具保持加载。

### MCP 工具会收到什么 {#what-an-mcp-tool-receives}

当模型调用 MCP 工具时，Open WebUI 只会把工具名和模型写下的参数发给 MCP 服务器，不会发送其他内容。[工作区 Python 工具](/features/extensibility/plugin/development/reserved-args)获得的保留参数（例如 `__user__`、`__metadata__` 和 `__files__`）绝不会传给 MCP 工具，因此聊天中附加的文件到不了它那里。OpenAPI 工具服务器上的工具也是同样的处理：Open WebUI 会丢弃该操作未声明的所有参数，把其余参数作为路径、查询和请求体参数发送。

服务器通过以下请求头得知是谁发起了调用：

- **Auth** 设置所选择的令牌，参见[身份验证模式](#authentication-modes)。**Session**、**OAuth** 和 **OAuth 2.1** 发送属于该用户的令牌，而 **Bearer** 对所有人都发送同一把密钥。
- 你的[自定义标头](#custom-headers)，其中 `{{USER_ID}}`、`{{CHAT_ID}}` 等占位符已填入实际值。
- 当 [`ENABLE_FORWARD_USER_INFO_HEADERS`](/reference/env-configuration#enable_forward_user_info_headers) 设为 `true` 时，用户的姓名、ID、邮箱和角色会通过 `X-OpenWebUI-User-*` 请求头发送（或在设置了 `FORWARD_USER_INFO_HEADER_JWT_SECRET` 时发送一个签名 JWT），另外还有 `X-OpenWebUI-Chat-Id` 和 `X-OpenWebUI-Message-Id`。

要把聊天文件交给 MCP 或 OpenAPI 工具：

- **传递内容或 URL。** 给工具一个用于文本或可下载 URL 的参数，让模型自行填入。
- **传递文件 ID。** 当 **Function Calling** 未设为 **Legacy** 且模型的 **Builtin Tools** 能力开启时，每条用户消息到达模型时会带一个 `<attached_files>` 块，其中列出每个附加文件的 `id`。给工具一个文件 ID 参数，并让服务器用它收到的令牌从你的 Open WebUI 实例的 `/api/v1/files/<id>/content` 下载文件。使用 **Session** 认证时，那就是用户自己的 Open WebUI 令牌，对用户有权读取的文件有效。
- **使用工作区 Python 工具。** 在**工作区 > 工具**中编写的工具会在 `__files__` 中收到附加文件，并可自行转发给你的服务。

### 结构化工具结果 {#structured-tool-results}

MCP 工具可以在常规内容之外返回结构化数据（`structuredContent`）。Open WebUI 会把这些数据以 JSON 文本的形式添加到模型看到的工具结果中。当工具的某个文本结果已经包含同样的 JSON 时，结果会原样发送给模型，因此数据只出现一次。当结构化数据只是一个 `result` 字段、且其取值与文本结果一一对应时也是如此——使用官方 MCP Python SDK 构建的服务器就是这样返回普通值和列表的。

### 服务器指令 {#server-instructions}

MCP 服务器可以在 Open WebUI 连接时发送指令。Open WebUI 会把它们追加到系统提示词中，标题行为 `MCP server "<server ID>" instructions:`，这样模型就能了解该服务器期望如何使用它的工具。

### 请求你的输入 {#requests-for-your-input}

MCP 服务器可以在工具调用过程中向你征询输入（MCP elicitation）。Open WebUI 会显示一个对话框，其中包含服务器 ID 和服务器的消息：

- **表单请求** 会显示一个表单，其中包含服务器所请求的字段。点击 **提交** 会发送你的答案。Open WebUI 会依据服务器的 schema 校验这些答案，并且只发送与之匹配的答案。
- **链接请求** 会显示一个需要打开的链接。打开它即等于告诉服务器你已经照做。不以 `http://` 或 `https://` 开头的链接，或包含用户名或密码的链接，会在对话框出现之前被取消。

**拒绝** 会回绝该请求，**取消** 则关闭对话框，之后如何继续由服务器决定。对话框最多等待 120 秒，若 [`WEBSOCKET_EVENT_CALLER_TIMEOUT`](/reference/env-configuration#websocket_event_caller_timeout) 设置得更低则以该值为准，之后请求会被取消。只有在浏览器标签页中打开了该对话时，才会显示此对话框；否则请求会立即被取消。

### MCP 应用 {#mcp-apps}

MCP 工具可以附带交互式应用（[MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview)）。当工具的 `_meta.ui.resourceUri` 指向一个类型为 `text/html;profile=mcp-app` 的 `ui://` 资源（最大 5 MB）时，Open WebUI 会在工具运行后于对话中内嵌展示该应用。

应用在沙箱 iframe 中运行，可以运行脚本、下载文件、打开弹窗，但无法访问 Open WebUI 的源。其内容安全策略由资源的 `csp` 元数据（`resourceDomains`、`connectDomains`、`frameDomains`、`baseUriDomains`）设置，并额外应用 [`IFRAME_CSP`](/reference/env-configuration#iframe_csp)。应用可以读取和列出服务器资源、在新标签页中打开 `http` 和 `https` 链接、调用服务器工具，并向聊天发送消息。应用每次调用工具前，都会在**工具调用**对话框中请求确认。应用发送的消息会先在**确认来自嵌入内容的提示词**对话框中显示文本，确认后才会成为你的下一条聊天消息。应用只能发送文本，因此消息中的图像和文件会被省略。应用也可以提供文件下载。**下载**对话框会先列出文件和链接，确认后保存各个文件，并在新标签页打开 `http` 或 `https` 链接。

工具的 `_meta.ui.visibility` 决定谁可以使用它：没有 `model` 的工具对模型隐藏，没有 `app` 的工具无法被应用调用。MCP 应用需要稳定的 [`WEBUI_SECRET_KEY`](/reference/env-configuration#webui_secret_key)。

## 故障排除 {#troubleshooting}

### "Failed to connect to MCP server" {#failed-to-connect-to-mcp-server}

**现象**：
使用工具时，即便设置中的验证按钮已报告成功，对话也可能显示 "Failed to connect to MCP server"。连接采用任一种 OAuth 2.1 模式时，该按钮显示为 **检查 OAuth 发现**，只确认能否找到并解析授权服务器的发现文档。

服务器日志会以 error 级别记录每次失败，格式为 `Failed to connect to MCP server '<id>'`，随后是具体原因，因此请优先查看它。对话过程中变得不可达的服务器只会让那一次工具调用失败：模型会收到连接错误作为工具结果，并继续完成本次回复。

**解决方案**：
1.  **检查身份验证**：确保没有在没有密钥的情况下选择 `Bearer`。如果不需要令牌，切换到 `None`。
2.  **过滤列表 Bug**：如果"函数名称过滤列表"为空，尝试向其添加逗号（`,`）。
3.  **OAuth 2.1 默认工具**：如果失败的工具使用 OAuth 2.1 并被设置为模型的默认工具，这是已知限制。从模型的默认工具中删除它，让用户每次对话手动启用。
4.  **握手缓慢**：如果服务器冷启动较慢，或暴露了大量工具，连接、列出工具或读取资源都可能超出其超时时间。可以提高 [`MCP_INITIALIZE_TIMEOUT`](/reference/env-configuration#mcp_initialize_timeout)（默认 `10` 秒）。工具调用则使用 [`AIOHTTP_CLIENT_TIMEOUT_TOOL_SERVER`](/reference/env-configuration#aiohttp_client_timeout_tool_server)。

### OAuth 登录后出现 `{"detail":"Not Found"}` {#detailnot-found-after-the-oauth-sign-in}

**现象**：在提供商处批准访问后，浏览器落到 `/oauth/clients/mcp:<Connection ID>/callback`，页面上只显示 `{"detail":"Not Found"}`。

**原因**：Open WebUI 没有在该 URL 的 **Connection ID** 下保存 OAuth 客户端。redirect URI 保留的是你点击**注册客户端**时的那份 **Connection ID**，因此这种情况发生在 **Connection ID** 之后被改动过，或者该连接已被删除或从未保存。

**解决方案**：在**设置 > 集成**（管理员区域）中打开该连接，用当前的 **Connection ID** 点击**注册客户端**，然后点击**保存**。使用 **OAuth 2.1（静态）** 时，请在身份提供商处把 redirect URI 更新为相同值，参见 [OAuth 2.1（静态）设置](#oauth-21-static-setup)。然后在对话中重新启用该工具。

### SSE URL 无法连接 {#an-sse-url-does-not-connect}

**现象**：
URL 指向服务器 SSE 端点的连接（通常是结尾为 `/sse` 的 URL）无法连接。对话显示 "Failed to connect to MCP server"。

**原因**：
Open WebUI 只通过 Streamable HTTP 连接 MCP 服务器。它从不建立 SSE 连接，因此 SSE 端点无法应答它的请求。

**解决方案**：
1.  **使用 Streamable HTTP 路径**：如果服务器也提供 Streamable HTTP，请把该端点填为 **URL**。服务器的文档中会写明这个路径。
2.  **用 mcpo 桥接 SSE**：如果服务器只提供 SSE，请让它运行在 [mcpo](https://github.com/open-webui/mcpo) 之后，例如 `mcpo --port 8000 --server-type "sse" -- http://127.0.0.1:8001/sse`，并把 mcpo 的 URL 添加为 **OpenAPI** 连接。参见 [MCP 支持](/features/extensibility/plugin/tools/openapi-servers/mcp)。

### 出现 “Maximum tools limit reached” 错误 {#maximum-tools-limit-reached}

错误 `Maximum tools limit reached. <n> tools have been provided but the maximum is <m>` 来自模型提供商或其前方的代理，而不是 Open WebUI。该请求携带的工具定义超过了该端点所能接受的数量。Open WebUI 会发送聊天中启用的每个 MCP 服务器的全部工具（通过其 **Function Name Filter List** 的那些），再加上 Native 模式下的内置工具。

要减少发送的工具数量：

- **开启[工具搜索](/features/extensibility/plugin/tools#tool-search)。** 延迟加载的工具不会进入发送给提供商的工具列表，因此该列表只保留始终加载的工具加上 `search_tools` 和 `call_tool`。只有定义长度超过 **Deferral Threshold (characters)** 的工具才会被延迟。将其设为 `0` 可延迟所有工具。
- **只列出需要的工具**，在每个服务器的[函数名称过滤列表](#function-name-filter-list)中设置。
- **启用更少的 MCP 服务器**，或在对话中关闭模型不需要的[内置工具类别](/features/extensibility/plugin/tools#granular-builtin-tool-categories-per-model)。

### 添加外部工具后出现无限加载界面 {#infinite-loading-screen-after-adding-external-tool}

**现象**：
添加外部工具连接后，前端停留在加载旋转图标上。浏览器控制台显示类似 `Cannot convert undefined or null to object at Object.entries` 的错误。

**原因**：
你可能使用 **OpenAPI** 连接类型配置了 **MCP 服务器**，或者将包含 `mcpServers` 的 MCP 风格 JSON 输入到了 OpenAPI 连接中。

**解决方案**：
1.  打开 **设置 > 集成**（管理员区域）（侧边栏仍会加载）
2.  **禁用**或**删除**有问题的工具连接
3.  刷新页面（Ctrl+F5）
4.  使用正确的**类型**（设置为 **MCP（Streamable HTTP）**）重新添加连接

## ❓ 常见问题 {#faq}

**是否支持 stdio 或 SSE 传输？**

Open WebUI 中的原生 MCP 支持**仅限 Streamable HTTP**。这一设计选择反映了我们的架构：Open WebUI 是一个**基于 Web 的多租户环境**，而非本地桌面进程。

浏览器在严格的**沙盒化和事件驱动的 HTTP 约束**下运行，使得跨用户和会话安全维护长期的 stdio 或 SSE 连接非常困难。

使用 Tether 的用户可在自己的电脑上以本地命令运行 stdio MCP 服务器，见 [Tether](/ecosystem/tether#bring-your-own-models-and-tools)。要为整个实例桥接其他 MCP 传输方式，可使用 [**mcpo**](https://github.com/open-webui/mcpo)。这个开源代理将**基于 stdio 或 SSE 的 MCP 服务器转换成兼容 OpenAPI 的端点**。无需更改传输层，即可在 Open WebUI 中使用传统 MCP 工具。

**这里对 MCP 的支持稳定吗？**

已经支持，并在持续改进。相关生态仍在发展，偶尔可能出现破坏性变更。

**可以同时混合使用 OpenAPI 和 MCP 工具吗？**

可以。许多部署同时使用两者。

**用户能否添加自己的 MCP 服务器？**

普通用户只能通过 Tether 应用为自己添加，见[使用自己的模型和工具](/ecosystem/tether#bring-your-own-models-and-tools)。只有管理员可以向实例添加 MCP 服务器（**设置 > 集成**，管理员区域）。原因见[仅管理员可添加 MCP 服务器](#mcp-servers-are-admin-only)。

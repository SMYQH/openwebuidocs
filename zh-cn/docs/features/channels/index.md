**让你的团队与 AI 在同一时间线里实时协作思考。**

频道是持久化的共享空间，人类与 AI 模型会在同一段对话中共同参与。与个人且相互隔离的普通聊天不同，频道允许多位用户和多个模型在一条统一时间线中互动。无论是人类消息还是 AI 回复，每一次交流都会沉淀为整个团队都能继续利用的共享上下文。

Open WebUI 让知识被发现、创建与共享，而频道则让这一切真正协作起来。

---

## 为什么使用频道？ {#why-channels}

### 让 AI 成为参与者，而不是独立工具 {#ai-as-a-participant-not-a-separate-tool}

先用 `@gpt-5.6` 起草计划，再用 `@claude` 进行审阅。整个团队都能在同一条时间线中看到完整上下文下的两次回复，无需切换标签页，也无需在不同工具之间复制粘贴。

### 持久共享上下文 {#persistent-shared-context}

每条消息都会成为记录的一部分。当有人在下周继续提问时，AI 可以基于之前讨论过的全部内容作答。频道是持续演进的知识库，而不是一次性线程。

### 多个模型，同一段对话 {#multiple-models-one-conversation}

你可以在同一个频道里使用一个模型做代码审查、另一个做写作、第三个做数据分析。把它们串联起来，就能获得任何单一模型都难以给出的更丰富结果。

### 实时协作 {#real-time-collaboration}

即时更新、表情回应、线程回复、消息置顶以及未读提示一应俱全。

## 核心特性 {#key-features}

| | |
| :--- | :--- |
| **`@model` 标签** | 按需把任意 AI 模型召唤进当前对话 |
| **共享上下文** | 无论人类还是 AI，每条消息都会累积团队知识 |
| **线程与互动** | 通过回复、置顶和表情反应保持讨论有序 |
| **文件共享** | 可直接投放图像、文档和代码，AI 可读取并处理 |
| **消息队列** | 在消息或文件上传仍在进行时继续发送：新消息会排在输入框上方，可以编辑或删除，并按顺序发出 |
| **访问控制** | 支持公开、私有、基于群组和私信频道 |
| **AI 频道感知** | 模型可自主跨频道搜索并综合信息 |
| **[Apps](/features/channels/apps)** | 外部服务接入频道，响应 `@mentions` 并发布带按钮的消息 |
| **[加密聊天](/features/channels/encrypted-chats)** | 在私信和私有群组中进行临时端到端加密对话，绝不在服务器上保存 |

## 频道类型 {#channel-types}

| 类型 | 适用场景 |
|------|----------|
| **标准频道** | 按主题组织的房间（如 `#engineering`、`#marketing-strategy`），可公开或私有 |
| **群组频道** | 团队范围的空间，支持显式成员列表与用户组同步 |
| **[私信频道](#direct-messages)** | 私密的 1:1 或小组对话，并显示在线/离线状态 |

## 工作方式 {#how-it-works}

### 与 AI 对话 {#talking-to-ai}

频道**默认是被动式的**。AI 不会主动插入每一段讨论。当你需要某个模型参与时，只需 @ 它：

> **你：** `@gpt-5.6` 这是我们第三季度的营收数据，有哪些明显的趋势？
>
> *（GPT-5.6 分析数据并给出关键洞察）*
>
> **你：** `@claude` 你同意这个分析吗？还遗漏了什么？

这样一来，团队可以先自由讨论而不被 AI 打断，并在真正需要时调用最合适的模型。

#### 回复出现在哪里 {#where-the-reply-appears}

默认情况下，响应顶层提及的模型会在你的消息下**以线程形式**回复，这样冗长的回答不会把频道的对话挤出屏幕。管理员可以在 **Settings > General**（管理员区域）（**Model Response Mode**，或 [`CHANNEL_MODEL_RESPONSE_MODE`](/reference/env-configuration#channel_model_response_mode)）中修改：设为 **Channel** 后，回复会直接发布到时间线中，团队无需打开线程即可阅读。无论如何设置，在线程内部 @ 模型总是在该线程内作答。

### 完整的 Chat Completion 流水线 {#full-chat-completion-pipeline}

在频道里 @ 一个模型，会走与标准聊天相同的 Chat Completion 流水线。回复会随着模型的生成**实时流式输出**，并且模型可使用其配置所赋予的全部能力：

| 能力 | 在频道中启用的内容 |
|------------|------------------------------|
| **原生与默认函数调用** | 工具调用在消息中途解析并执行 |
| **内置工具** | 网络搜索、图像生成、代码解释器、日历 |
| **用户工具与 MCP 工具** | 模型被配置为可以调用的任何工具 |
| **过滤器** | Inlet / Outlet / Stream 过滤器的应用方式与聊天中一致 |
| **知识库（RAG）** | 绑定到模型的知识库会被查询并注入 |
| **附件文档** | 线程中上传的图像和**非图像文件**（PDF、DOCX 等）会被转发到模型上下文中 |
| **结构化回复** | 回复按模型的完整输出渲染，因此推理块、工具调用、生成的图像和代码结果会像在聊天中一样出现在频道里，而不是被压平成纯文本 |

换句话说，在频道里被召唤出来的模型就是一个装备齐全的智能体，而不是一次性补全。

### @ 同事与链接频道 {#tagging-people-and-linking-channels}

使用 `@username` 通知队友。建议列表会先列出频道自身的成员，然后再列出实例中名字与你输入内容匹配的其他所有人，因此你依然可以 @ 一个不在频道里的人。标签只会通知有权限读取该频道的人。使用 `#channel-name` 在不同对话之间建立可点击的交叉引用。

你也可以不借助列表、直接完整输入提及。粘贴或发送时，`@name` 如果恰好匹配一个人、一个模型或一个应用（或某个模型的 ID，例如 `@gpt-5.6`），就会变成真正的提及；`#name` 如果恰好匹配一个频道，就会变成频道链接。若有两个同名匹配项，则需要从列表中挑选。从其他消息粘贴来的提及仍会指向同一个人。

把鼠标指向某人在消息旁或频道成员列表中的头像，或指向对他们的 `@mention`，即可打开他们的资料卡片。卡片上显示姓名、在线状态、状态、简介、所属组、当地时间以及最近一次活跃时间。当地时间依据该用户上次使用 Open WebUI 时的浏览器时区显示。任何已登录用户都能打开其他用户的卡片，同样的信息加上邮箱地址和角色，也可通过 API 获取。

### 消息互动 {#message-interactions}

将鼠标悬停到任意消息上，即可添加表情反应、置顶以便引用、直接回复，或发起一个线程式旁支讨论。线程会在宽度不小于 768 px 的屏幕上显示在频道旁边，在更窄的屏幕上则覆盖在上方。

频道标题栏中的 **Search** 按钮会搜索该频道的消息。频道会作为筛选项显示在搜索框下方；移除它即可扩大搜索范围。

你可以删除自己的消息，管理员可以删除任何人的消息。删除一条开启了线程的消息，会连带删除该线程中的所有回复，包括其他人写的回复。

如果你只能读取某个频道，消息上不会显示悬停操作，下方的反应也无法点击。消息框会显示 **你在此频道中没有发送消息的权限。**

### 静音频道 {#muting-a-channel}

频道或私信的 **...** 菜单（无论在侧边栏还是频道标题栏中）里有一个 **Notifications** 设置。**Mentions only** 会为你静音该频道：它在侧边栏中变暗，也不显示未读计数。只有 @提及你的消息仍会弹出气泡、浏览器通知或[通知 webhook](/features/chat-conversations/chat-features/notifications)；对它来说未读计数同样保持隐藏。**All messages** 会重新打开通知。该设置按成员保存，因此静音一个频道不会影响其他人。另见你的[收件箱](/features/chat-conversations/chat-features/notifications#inbox)。

### 应用 {#apps}

外部服务也可以作为 [Apps](/features/channels/apps) 加入频道。管理员在 **Settings > Apps**（管理员区域） 中安装它们，然后由频道创建者或管理员将其加入频道。它们会以 **App** 徽章出现在成员列表中，当你 `@mention` 它们时会作答，也可以发布带按钮的消息。

### 私信 {#direct-messages}

私信是你和你选定的人之间的对话，每一组参与者对应一个私信。你可以在频道中某人的资料卡片上点击 **Message** 按钮开始，也可以从侧边栏 **Channels** 部分的 **(+)** 开始，并把 **Channel Type** 设为 **Direct Message**。给你发过消息的人再次发消息时，会重新打开你与他已有的那段对话及其历史，而不是在旁边再加一个。私信不必设置名称；未设置时，它会列在其他参与者的名字之下。

成员身份是按仍然存在的账户计算的。当某个人的账户被删除后，他们不再计入这段对话：他们会从成员列表和标题栏人物图标旁的成员计数中消失，而剩下的参与者再次互相发消息时，仍会回到同一段对话中。群组频道的成员计数方式相同。已经为同一组人创建的两个对话不会被合并，因此如果产生了重复项，它会连同其中发出的消息一起，与原对话并列留在侧边栏中。

### 加密聊天 {#encrypted-chats}

在私信或私有群组频道中，拥有 **Encrypted Channels** 权限的成员可以从对话的 **...** 菜单中用 **Encrypted Chat** 开始一段临时的[加密聊天](/features/channels/encrypted-chats)。消息在浏览器中端到端加密，绝不存储在服务器上。管理员在 **Settings > General**（管理员区域）（**Encrypted channels**）中开启该功能并授予相应权限——默认关闭。

## AI 的频道感知能力 {#ai-channel-awareness}

启用 [**原生函数调用**](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native) 后，模型可以自主浏览你的频道：

- **搜索频道**：按名称或描述查找
- **搜索消息**：在所有可访问频道中检索
- **读取线程**：理解完整讨论上下文

> **你：** `#dev-team` 里对迁移时间表敲定了什么？
>
> *（AI 会搜索该频道、阅读相关话题串，并给出综合答案，全程无需离开当前对话。）*

这样就不再需要你手动在私聊与共享频道之间搬运信息，AI 会替你完成这件事。

:::tip 社区 Action：Forward to Channel
如果你希望把聊天消息一键转发到频道，社区提供的 **[Forward to Channel](https://openwebui.com/posts/b60c1f03-e29c-47c0-862c-3741a382616e)** Action 会为每条助手消息增加一个按钮，可将整条回复或选定内容发送到你选择的频道。它非常适合把私聊里的优质答案提升到团队可见空间，而无需手动复制粘贴。
:::

## 开始使用 {#getting-started}

:::info Beta 功能
频道目前仍处于 Beta 阶段，必须由管理员启用。
:::

1. 前往 **Settings > General**（管理员区域）
2. 打开 **频道（Beta）** 开关并保存
3. 侧边栏会出现频道入口，点击 **(+)** 创建你的第一个频道

创建标准频道默认仅限管理员。拥有 **Channels** 权限（[`USER_PERMISSIONS_FEATURES_CHANNELS`](/reference/env-configuration#user_permissions_features_channels)）的人可以创建群组频道和私信。频道支持细粒度权限控制，包括只读、可写，以及通过环境变量或群组权限启用/禁用具体功能。

标准频道的 **Access** 决定谁能读写它：指定的用户、群组或实例中的所有用户。只有频道创建者或管理员可以修改它，而且只有管理员才能把它开放给所有用户。与用户或群组共享需遵循[共享权限](/features/authentication-access/rbac/permissions#2-sharing-permissions)。群组频道和私信没有 **Access** 设置，其成员自行决定谁可以读取。

## 使用场景 {#use-cases}

### 团队知识中心（`#engineering`） {#team-knowledge-hub-engineering}

团队在一周内持续讨论架构决策。有人 @ `@claude` 来评估不同方案的取舍，AI 的分析随之成为永久记录：可搜索、可引用，并能在该频道未来的每次对话中继续被利用。

### 多模型作战室（`#incident-response`） {#multi-model-war-room-incident-response}

粘贴日志和错误堆栈后，先 @ `@gpt-5.6` 分析堆栈，再 @ `@qwen3.6` 给出修复建议，最后 @ `@claude` 起草复盘。三个模型，共用一个上下文，共处一条时间线。

### 项目策略（`#product-launch`） {#project-strategy-product-launch}

在二十多条人类头脑风暴消息之后，再让 `@gpt-5.6` 阅读上方对话并产出带负责人和截止日期的优先级行动计划。AI 会把全部讨论综合成结构化交付物。

### 创意协作（`#story-mode`） {#creative-collaboration-story-mode}

适合长周期叙事项目，让多个“角色型”模型在同一时间线中互动，并在不丢失上下文的情况下切换不同人格。

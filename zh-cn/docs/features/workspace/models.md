**用自定义指令、工具和知识库包装任何模型，构建专属智能体。**

模型工作区让您创建叠加在任何基础模型之上的配置预设。选择 GPT-5.6、Claude、Qwen 3.6 或 Open WebUI 连接的任何其他模型，然后将系统提示词、知识库、工具、技能和参数覆盖绑定到它。结果是一个行为完全符合需求的专用智能体，无需修改底层模型。

一个始终使用您的风格指南的"Python 导师"。一个使用公司模板的"会议摘要助手"。一个内置了代码规范规则的"代码审查员"。每个智能体都是一个轻薄包装器：选择一个基础模型，配置它，然后与团队共享。

## 为什么使用模型？ {#why-models}

### 一个基础模型，多种角色 {#one-base-model-many-personas}

同一个 GPT-5.6 可以驱动编程助手、客户支持机器人和创意写作工具。每个预设都有自己的系统提示词、工具和知识库，因此根据所选预设，模型的行为会有所不同。

### 知识库和工具预先附加 {#knowledge-and-tools-come-pre-attached}

不再需要每次对话都手动附加文档和启用工具，只需将它们一次性绑定到模型预设。用户开箱即可获得完全配置的智能体。

### 细粒度访问控制 {#granular-access-control}

将模型限制为特定用户或用户组。财务团队看到他们的模型；工程团队看到他们的模型。管理员控制实例范围内的可用内容。

### 动态系统提示词 {#dynamic-system-prompts}

使用 `{{USER_NAME}}` 和 `{{CURRENT_DATE}}` 之类的变量，使系统提示词自动适应每个用户和会话。花括号内部不要留空格：带空格的形式会作为纯文本原样传给模型。只有聊天变量和用户变量（`{{ chat.variables.x }}`、`{{ user.variables.x }}`）允许空格。

## 创建模型 {#creating-a-model}

在**工作区 > 模型**中点击 **+ 新建模型**，或点击现有模型上的省略号（**...**）并选择**编辑**。

### 编辑器布局 {#editor-layout}

编辑器打开时会显示一个横幅页眉：背景图铺满横幅，模型的图片、名称和 ID 叠加在其下缘之上。其下依次是描述、基础模型、标签和系统提示词。已保存的系统提示词默认折叠为一段简短预览；点击它或 **显示更多** 即可编辑。系统提示词旁的 **对比版本** 会在旁边打开一个空的 **建议版本** 面板。把修改后的版本粘贴进去并点击 **对比** 即可标记改动，然后用箭头逐条浏览。**应用到草稿** 会把右侧面板的内容写入系统提示词；如果某项改动你不想要，可以用 **原文 →**，它会把该改动的原文复制到右侧面板。对于替换文本的改动，**两者都保留** 会把原文加上建议文本一起放入右侧面板。之后保存模型即可。

其余内容都按行排列，每行一项设置。每行会显示已配置内容的简短摘要，例如 **默认**、**已修改 3 项**、**自定义 · 4** 或 **视觉、文件上传、网页搜索 +2**，点击即可展开。将鼠标悬停在设置名称上可以看到它的作用。

- **开关**：**能力**、**默认功能** 和 **内置工具** 会展开为开关。将鼠标悬停在开关标签上可以看到它的作用。
- **选择器**：**知识库**、**工具**、**技能**、**过滤器** 和 **操作** 会打开一个可搜索的选择器。**清除** 会移除所有已选项，**管理** 会打开创建这些条目的工作区页面。**全选** 会选中所有匹配搜索的条目（知识库对应的是 **上传文件**）。标记为 **全局** 的条目始终启用。工具、技能、过滤器、操作和子代理会在名称下方显示各自的描述。当列表为空时，选择器会提示添加条目的工作区页面。
- **高级参数** 会显示你改动过的参数数量（**已修改 N 项**），未改动时显示 **默认**。
- **提示词** 保存该模型的提示词建议。
- **语音** 保存实时语音、语音头像和 TTS 语音。

**保存并更新**（新模型为 **保存并创建**）在滚动时始终固定在编辑器底部。编辑已有模型时，按钮旁会出现 **描述此次变更** 输入框。**保存并创建** 始终可用；**保存并更新** 则在有改动后才可用。

### 核心配置 {#core-configuration}

| 字段 | 说明 |
| :--- | :--- |
| **头像** | 上传自定义图片。支持动态 GIF 和 WebP |
| **背景** | 在使用该模型的对话中显示于编辑器横幅和对话背景上的图片。将鼠标悬停在横幅上，使用 **添加背景**、**更换** 或 **移除**。必须在此处上传，因为只接受由本实例持有的文件：外部 URL 或粘贴的 data URI 会被直接拒绝。支持 PNG、JPEG、WebP 或 GIF，最大 5 MiB 且不超过 2500 万像素 |
| **名称和 ID** | 显示名称和唯一标识符。ID 中不能包含空格或制表符，且最长 256 个字符 |
| **基础模型（来源）** | 驱动此智能体的实际模型。管理员可以在这里选择隐藏模型。其他用户只有在拥有 [**隐藏模型**](/features/authentication-access/rbac/permissions#1-workspace-permissions) 权限（默认关闭）时才能在此列表中看到它们。隐藏模型仍然不会出现在他们的对话模型选择器中。该权限只影响此列表，不改变谁可以使用隐藏模型 |
| **描述** | 模型选择器中显示的简短摘要 |
| **标签** | 在下拉菜单中组织模型 |
| **提供商详情** | 仅管理员可见。即提供商的模型列表为该模型报告的信息：输入与输出、上下文窗口、最大输出和支持的参数。提供商未填写的字段会显示 **未提供**。当提供商未报告任何一项时，该行会被隐藏 |
| **访问权限** | 右上角的 **访问权限** 按钮用于设置谁可以使用该模型：私有（指定用户/用户组）或公开。非管理员只有在拥有 [**模型共享**](/features/authentication-access/rbac/permissions#2-sharing-permissions) 权限时才能看到它。在已保存的模型上，每次改动都会立即保存，无需 **保存并更新**。超出共享权限允许范围的改动会被拒绝，并提示“你没有权限与请求的受众共享” |
| **语言** | 右上角紧邻 **访问权限** 的地球图标选择器，会将编辑器切换为名称、描述、提示词建议和模型控件的翻译版本。参见[翻译](#translations) |

![包含基础模型、描述和系统提示词的模型编辑器](/images/workspace/model-editor.png)

:::warning 模型 ID 中含空格时保存

现在，含空白的 ID 在编辑器、API 和导入时都会被拒绝；在导入环节，这样的模型会被跳过而不是创建。

已经以含空格的 ID 存储的模型仍会继续响应请求，但保存它或修改其访问授权会失败，因为两者都要经过同一项检查。请使用不含空白的 ID 重新创建，并删除旧的模型。

:::
### 系统提示词和变量 {#system-prompt-and-variables}

系统提示词定义了行为和角色。若要在使用前审阅改写后的系统提示词，请使用字段旁的 **对比版本**（参见[编辑器布局](#editor-layout)）。使用动态变量实现上下文感知的指令：

| 变量 | 输出示例 |
| :--- | :--- |
| `{{CURRENT_DATE}}` | `2024-10-27` |
| `{{CURRENT_TIME}}` | `14:30:05` |
| `{{USER_NAME}}` | `Admin` |
| `{{USER_GROUPS}}` | `Engineering, Beta Testers`（逗号分隔，包含通过父组继承的组；若用户不属于任何组则为空） |

```
You are a helpful assistant for {{USER_NAME}}.
The current date is {{CURRENT_DATE}}.
```

:::note 系统提示词是指令，而非保证

Open WebUI 不要求系统提示词采用特殊格式。纯文本、Markdown 列表和简短的结构化小节都可以；Open WebUI 在此处唯一处理的特殊语法就是 `{{CURRENT_DATE}}` 这类受支持的变量，以及对话/用户变量。

助手遵循提示词的程度取决于所选的 **基础模型**、提供商或本地服务器的对话模板、完整的对话上下文，以及工具、文件、RAG、技能、记忆或过滤器附加的任何额外指令。如果提示词配置在正确的位置但模型仍忽略规则，请与指令遵循能力更强的模型对比，并检查提供商/后端的请求格式，而不要先假定提示词需要某种 Open WebUI 专有格式。

:::

:::tip 群组感知的系统提示词
`{{USER_GROUPS}}` 让一个共享模型能够根据调用者的 RBAC 用户组自适应其行为，例如：*“仅当 `{{USER_GROUPS}}` 包含 'Engineering' 时，你才可以讨论内部路线图项目。”* 该占位符在对话时由服务端解析，并且数据库查询仅在模板中实际引用该变量时才会执行。
:::
### 能力和绑定 {#capabilities-and-bindings}

在选择器各行中绑定资源：

| 设置 | 控制内容 |
| :--- | :--- |
| **知识库** | 附加知识库、笔记或文件，这也会[把模型的知识搜索限制在这些内容上](/features/workspace/knowledge#scoped-access-keeps-things-organized)。选择器中的 **上传文件** 可直接从你的电脑添加文件。点击已附加项可在专注检索和全文上下文之间切换。参见[检索模式](/features/workspace/knowledge#retrieval-modes) |
| **工具** | 强制启用特定工具（例如为数学机器人启用计算器） |
| **技能** | 绑定[技能](/features/workspace/skills)。使用该模型的每个新对话都会默认选中它们。参见[模型附加的技能](/features/workspace/skills#model-attached-skills) |
| **过滤器** | 附加流水线过滤器（例如 PII 脱敏）。每个附加的[可切换过滤器](/features/extensibility/plugin/functions/filter#toggleable-filters-making-filters-user-controllable-selftoggle)在选择器中都有一个 **在新对话中默认启用** 开关，用于设置该模型的默认过滤器。当实例中至少存在一个过滤器函数后，该行才会出现 |
| **操作** | 附加操作脚本（例如“添加到记忆”）。当实例中至少存在一个操作函数后，该行才会出现 |

在 **能力** 一行及其后的两行中切换模型可以做什么：

编辑器只显示在本实例上可用的选项，例如只有开启网页搜索时才会显示 **网页搜索**。隐藏的选项会保留其已保存的值。

![模型编辑器中的能力与内置工具类别](/images/workspace/model-editor-capabilities.png)

| 设置 | 控制内容 |
| :--- | :--- |
| **视觉** | 启用图像分析（需要支持视觉的基础模型）。位图（PNG、JPEG、WebP、GIF）会作为图像输入送达模型；SVG 则作为文档读取，因此它通过 **文件上传** 传输，模型基于其源文本工作。关闭视觉时，工具返回的图像会以简短的 `[image]` 说明送达模型。 |
| **网页搜索** | 启用已配置的搜索提供商 |
| **代码解释器** | 启用 Python 代码执行 |
| **终端** | 允许模型驱动已附加的[Open Terminal](/features/open-terminal)服务器来运行命令并处理文件。默认开启；关闭后，对话中的终端绝不会交给模型 |
| **图像生成** | 启用图像生成 |
| **用量** | 要求提供商在流式回复中报告 token 计数（`stream_options.include_usage`）。默认关闭。大多数兼容 OpenAI 的提供商在被询问前不会报告任何内容，因此不开启时回复中不会出现 token 数值，也无法在[分析](/features/administration/analytics)中汇总 |
| **引用** | 显示回复背后的来源，包括知识库、文件检索以及返回来源的内置工具。默认开启；关闭后不显示任何来源。在原生模式下网页搜索结果不算来源，参见[智能体搜索](/features/chat-conversations/web-search/agentic-search) |
| **状态更新** | 显示回复执行过程中输出的进度行，例如网页搜索的各个步骤。默认开启 |
| **记忆** | 用户存储的记忆是否会被注入该模型的上下文（默认开启）。对于应在无个人上下文情况下回答的模型可以关闭；这不会删除任何内容，且它与 **记忆** 内置工具类别不同，后者指的是模型自行读写记忆 |
| **内置工具** | 该能力开关会整体启用内置工具。开启时，**能力** 下方的 **内置工具** 一行用于控制哪些工具类别可用：时间与计算、询问用户、记忆、聊天历史、笔记、知识库、文件、频道、通知、网页搜索、图像生成、代码解释器、任务管理、自动化、日历、子代理、技能、工具创建。只有当对应功能开启时才会显示某个类别 |
| **子代理** | 当 **子代理** 内置工具类别开启时显示：即该模型可以分派[子代理](/features/chat-conversations/chat-features/subagents)工作的模型。用户只会得到其中自己有权访问的模型。留空时，子代理在当前模型上运行 |
| **文件上传** | 是否可以向消息附加文件。默认开启；关闭后，使用该模型的对话中会上传被拒绝，并且 **预加载文件** 会从此编辑器中消失，因为已没有可提取的内容 |
| **预加载文件** | 启用时，附加的文件会通过 RAG 处理并注入对话。禁用时不会注入任何内容，模型改用内置的 **文件** 工具读取附加文件。在原生函数调用下默认关闭，在旧版下默认开启；编辑器和 **模型默认值** 会显示实际生效的值 |
| **默认功能** | 紧接在 **能力** 下方的一行，列出 **网页搜索**、**图像生成** 和 **代码解释器**，且仅在相应能力开启时显示。在此开启的功能会在使用该模型的每个新对话中默认启用；用户仍可按对话将其关闭 |
| **默认终端** | 当 **终端** 开启时显示：与该模型的对话默认选用的[Open Terminal](/features/open-terminal)服务器 |
| **TTS 声音** | 位于 **语音** 一行：为该模型的回复指定特定语音 |

:::info 用量统计覆盖模型参与的所有对话
token 计数的请求是在服务端添加的，因此无论模型在哪里使用都会生效：对话界面、API，以及 Open WebUI 通过[自动化](/features/chat-conversations/chat-features/automations)、[定时器](/features/chat-conversations/chat-features/timers)、[子代理](/features/chat-conversations/chat-features/subagents)和[频道](/features/channels)代表你发起的对话。无需按请求做任何设置。只有流式请求会受影响，因此关闭了 **流式回复** 的模型不受影响。
:::

### 语音头像 {#voice-avatar}

**语音** 一行中有 **语音头像** 设置；当管理员把 **通话模式** 设为 **实时** 时，还会显示 **实时语音**。**语音头像** 会为模型分配一个用于语音通话的动画 3D 角色，在两种通话模式下都可用，并可选择动画和手势。有关设置和文件要求，请参阅 [语音头像](/features/chat-conversations/chat-features/voice-mode#voice-avatars)。

### 高级参数 {#advanced-parameters}

**高级参数** 这一行会显示该模型改动了多少个参数，例如 **已修改 2 项**，点击后可以展开完整列表。

- **停止序列**：在特定字符串处强制停止生成（例如 `<|end_of_text|>`、`User:`）。单个文本字段，以逗号分隔。
- **温度、Top P 等**：调整创造力和确定性。
- **上下文压缩阈值**：设置该模型自己的[上下文压缩](/troubleshooting/context-window#the-built-in-option-context-compaction)阈值。仅在开启上下文压缩时显示。

在此处设置的参数会应用于所有未自行设置同名参数的聊天。如果用户在聊天的**模型控制 > 控制项**中、或在自己的**设置 > 通用**中设置了某个参数，以及 API 调用者在请求中传入了某个参数，则以他们自己的值为准。参见[聊天参数](/features/chat-conversations/chat-features/chat-params)。

### 模型控件 {#model-controls}

模型控件为用户在对话中提供几个简单的选择，例如模型思考的力度或回答的长度，而你则决定每个选项具体发送哪些参数。名为 **思考** 的控件包含最低、低、中、高四个选项，分别把 `reasoning_effort` 设为对应值，让任何人都能在不了解该参数的情况下调整推理强度。

任何拥有模型写入权限的人都可以定义它的控件，位置在 **工作区 > 模型** 或 **设置 > 模型**（管理员区域）。请使用 **高级参数** 下方的 **模型控件** 这一行：**+** 添加控件，**编辑** 修改控件，**×** 删除控件，左侧的拖动手柄用于调整顺序。每行会显示该控件的默认选项。

控件与模型一同保存，并对所有能使用该模型的人生效。能编辑模型的人可以在编辑器、JSON 预览和导出结果中看到每个选项背后的参数。只能使用模型的人看到的是名称、描述和选项名称，这些内容可以被翻译（参见 [翻译](#translations)）。

![思考控件的编辑对话框，以滑块形式展示，包含最低、低、中、高四个选项，每个都设置 reasoning_effort](/images/features/models/model-controls-edit.webp)

| 字段 | 作用 |
| :--- | :--- |
| **名称** | 用户在对话中看到的标签，例如 **思考** |
| **默认选项** | 在用户尚未选择任何选项时生效的选项。若为 **无**，则在用户选择某个选项之前该控件不会发送任何内容 |
| **描述** | 可选的帮助文本，会显示在对话中 |
| **显示方式** | **菜单** 以列表形式显示选项。**滑块** 按此处列出的顺序把选项显示为滑块档位，至少需要两个选项 |
| **选项** | 每个选项包含一个名称以及一组或多组 **参数** 和 **值**，通过 **添加参数** 新增。拖动手柄可调整选项顺序 |

选项中的参数与 **高级参数** 中通过 **添加自定义参数** 添加的用法相同：参数名会原样传给服务商，能读作 JSON 的值（数字、`true`、对象）会按对应类型发送，其余按文本发送。当一个选项包含多个参数时，它们会一起发送。对于 Ollama 模型，这些参数会进入 Ollama 的 `options`，但 `think`、`format` 和 `keep_alive` 除外，这三个会放在请求的顶层。模型自身设置的 `think`、`format` 或 `keep_alive` 仍然优先于控件；如果希望由控件驱动，请在模型上把这三项留空。

控件需要模型由实例的某个连接提供服务，例如兼容 OpenAI 的连接或 Ollama 连接。在由管道函数支撑的模型、竞技场模型或来自直连的模型上保存控件会失败，并提示 **模型控件需要由服务端管理的提供商模型。**

#### 在对话中使用模型控件 {#using-model-controls-in-chat}

当已选模型带有控件时，消息输入框旁的模型选择器旁会出现一个旋钮图标（**模型控件**）。点击它会打开一个面板，列出每个控件及其当前选择。**滑块** 型控件通过拖动滑块调整，下方显示 **默认 · 中**（默认选项的名称）以便恢复默认，描述则位于 **?** 图标之后。**菜单** 型控件会展开一个列表，其中包含描述、**默认 · 中** 以及所有选项。

![对话中的模型控件，思考滑块设为高，详略滑块保持默认的均衡](/images/features/models/model-controls-slider.webp)

![对话中的模型控件以菜单形式展示，思考子菜单展开显示默认 · 中，位于低、中、高之上](/images/features/models/model-controls-menu.webp)

只要已选模型带有控件，该图标就会出现，且对所有被允许使用 [控件](/features/chat-conversations/chat-features/chat-params) 的人可见。任何有权访问该模型的人都可以选择其选项，无论其 [权限](/features/authentication-access/rbac/permissions#3-chat-permissions) 中的 **允许对话控件** 和 **允许对话参数** 如何设置。这样管理员可以通过模型控件提供诸如思考级别这样的策展选项，同时对用户隐藏 **控件** 和原始参数。当同时选中两个模型时，每个模型的控件会显示在各自的名称下，并各自保存自己的选择。

- **选择会按模型保存到账户中。** 选择某个选项会立即保存，并适用于使用该模型的所有对话（无论新旧）、所有设备，直到用户改选其他选项为止。
- **默认跟随模型。** 只要勾选 **默认**，每条消息都会发送默认选项的参数；若默认选项为 **无**，则不发送该控件的任何内容。若之后有人修改了默认选项，所有保持 **默认** 的用户都会随之变化。
- **选定的选项会在其他所有位置取代同一参数。** 它的值优先于模型的 **高级参数**、[全局模型默认值](#global-model-defaults-admin)、用户的 **设置 > 通用** 以及对话中的 **控件**。如果两个控件设置了同一参数，则以列表中靠下者为准。
- **删除选项会阻塞模型，直到重新选择。** 如果编辑者删除了某人已选中的选项，该用户发往该模型的消息将失败并提示 `Model control <key>: the selected option is no longer available.`，直到他改选其他选项或 **默认**。针对已删除控件的选择会被跳过。
- **自动化使用默认值。** 由 [自动化](/features/chat-conversations/chat-features/automations) 启动的对话始终发送各控件的默认选项。

API 调用方也能获得同样的控件。请求如何选择某个选项，请参阅 [Chat Completions](/reference/api-endpoints#chat-completions)。

### 提示词建议 {#prompt-suggestions}

用户使用该模型开启全新对话时出现的可点击起始提示。你可以添加诸如“逐步解释这段代码”或“总结这份文档”之类的短语来引导用户。它们可以按语言分别翻译，参见下文。

它们位于 **提示词** 一行。设为 **默认** 时，模型显示来自[全局模型默认值](#global-model-defaults-admin)的实例级建议；**自定义** 会为它提供自己的列表，显示为带有建议数量的 **自定义**；**使用默认** 则回到实例级的建议。
### 翻译 {#translations}

名称、描述、提示词建议以及[模型控件](#model-controls)的名称都可以为每种语言分别设置一个版本，因此使用德语界面的 Open WebUI 用户会看到德语的模型名称和德语的起始提示词，而其他用户仍保留原文。

在编辑器右上角选择语言后，编辑器会切换为编辑该语言，并以原文作为占位文本显示。此时 **模型控件** 一行会列出每个控件的名称、描述和选项名称以便翻译。用户会看到与其界面语言匹配的版本，未翻译的部分则保留原文。

同样的机制也适用于工具、技能、函数、横幅和竞技场模型。完整说明（包括如何翻译阀门标签）请参阅 [翻译](/features/administration/translations)。

### 版本历史 {#version-history}

每一次改变模型配置的 **保存并更新** 都会作为一个版本保留下来，同时保留按钮旁 **描述此次变更** 中填写的内容。模型编辑器顶部 **返回** 旁的版本选择器默认停在 **生产环境**，即对话实际使用的配置。展开它可查看已保存的版本，按时间倒序排列，每页 20 条，每条附带作者和描述（若描述为空则显示一个简短的版本 ID）。任何能编辑该模型的人都可以使用它，在 **工作区 > 模型** 以及 **设置 > 模型**（管理员区域） 中对已保存设置的模型均是如此。

![展开版本选择器的模型编辑器，列出生产环境版本以及按描述排列的较早版本](/images/features/models/model-version-history.webp)

- **打开版本**：选择某个版本即可，编辑器会以只读方式显示该版本。
- **设为生产环境**：将当前打开的版本设为实际生效的配置。如果编辑器中有未保存的改动，会先要求你确认，因为这些改动将被丢弃。
- **删除**：位于某个版本的 **⋯** 菜单中。生产环境版本无法删除。在被删除版本之上保存的版本会重新链接到其父版本，从而保持版本链完整。

一个版本包含名称、基础模型、系统提示词、参数以及编辑器的其他设置，例如描述、标签、能力、提示词建议，以及所绑定的知识库、工具、技能、过滤器、操作和终端。访问权限设置、**隐藏模型** 和 **启用** 开关属于实时模型，切换版本时它们会保持当前值。每个已有模型在升级时都会自动创建一个版本。

将某个版本设为生产环境时，会检查它所引用的一切，因为较早的版本可能指向此后已被删除或你无权访问的内容。出现下列情况时，实际配置保持原样，切换会被拒绝：

- 它的基础模型已不再可用。
- 它绑定的知识库、知识文件、笔记、技能、工具或终端缺失，或你无权访问。
- 它绑定的过滤器或操作函数缺失或已被关闭。
- 它的背景图或语音头像文件你已无法访问。

若要继续，请把缺失的条目恢复或获取其访问权限，或者改选其他版本。

同样的操作也可以通过 API 完成，每个接口都以 `?id=` 接收模型 ID：`GET /api/v1/models/model/history`（通过 `&page=` 分页）、`GET /api/v1/models/model/history/{history_id}`、`POST /api/v1/models/model/update/version` 搭配 `{"version_id": "..."}`，以及 `DELETE /api/v1/models/model/history/{history_id}`。通过 `POST /api/v1/models/model/update` 保存时，还可以附带可选的 `commit_message`。

### 启用与禁用 {#enabled-and-disabled}

可编辑的行还带有一个 **启用** 开关，在 **工作区 > 模型** 和 **设置 > 模型**（管理员区域） 中都有。关闭它会把该模型从所有人的模型列表中移除：它会从选择器中消失，指名它的请求会失败并提示 **“未找到模型”**。不会删除任何内容，其他模型保持原位，重新打开开关即可让模型恢复。

**隐藏** 是更轻量的选项。它保留模型在列表中，只是将其从选择器中移除，因此隐藏的基础模型仍可支撑基于它构建的预设。

### 导入和导出 {#import-and-export}

- **导入**：从 `.json` 文件或 Open WebUI 社区链接导入
- **导出**：将所有您有权编辑的自定义模型下载为单个 `.json`，无论搜索框或过滤器当前显示了什么。管理员在 `BYPASS_ADMIN_ACCESS_CONTROL` 开启时（这是默认设置）可获得全部自定义模型
- **发现**：在页面底部浏览社区预设

模型的背景图片会随模型一同迁移。导出时图片会嵌入文件内部，导入时会作为一次全新的上传保存在目标实例上，因此在实例之间迁移的模型无需您手动搬运文件即可保留背景图片。有关导出和导入的调用，请参阅 [API 端点参考](/reference/api-endpoints)。

如果某个模型的 ID 已被一个您无权编辑的模型占用，导入会以 **Uh-oh! This model id is already registered. Please choose another model id string.** 中止。文件中位于它之前的模型仍会被导入。

:::info 下载基础模型
要下载新的基础模型，请进入**设置 > 连接**（管理员区域），在某个 Ollama 连接上打开 **管理**，或在模型选择器中输入 `ollama run hf.co/{username}/{repository}:{quantization}`。
:::

## 全局模型默认值（管理员） {#global-model-defaults-admin}

管理员可以在**设置 > 模型**（管理员区域）中设置适用于所有模型的基础能力和参数。点击列表顶部的 **Model Defaults** 即可打开它，并使用页面上的 **保存** 按钮提交。它与模型编辑器使用相同的行：**模型能力**包含**能力**、**默认功能**和**内置工具**三行，**工具**选择器用于设置默认工具，**模型参数**包含高级参数，**提示建议**则是起始标签。

- **默认模型元数据**（`DEFAULT_MODEL_METADATA`）：基础能力（视觉、网络搜索、预加载文件、代码解释器、内置工具）。冲突时，按模型的覆盖始终优先。
- **默认模型参数**（`DEFAULT_MODEL_PARAMS`）：基础推理参数（温度、top_p、max_tokens、function_calling）。明确设置时，按模型值优先。此值作为 JSON 从环境变量加载；无效 JSON 会被忽略，回退到 `{}`。
- **工具**：对于没有自有工具列表的模型，在新聊天中默认启用的工具。拥有自有工具列表的模型会保留其列表。新建模型表单会默认选中这些工具。
- **提示建议**：当模型没有自己的提示建议时显示的起始标签。地球图标选择器会按语言翻译它们，与模型自身的建议翻译方式相同。参见 [Translations](#translations)。

以上设置作用于聊天补全。后台任务请求（标题、标签、追问、搜索查询、自动补全、上下文压缩摘要）不经过这些设置；它们的参数在[任务模型](/features/administration/task-models)中单独设置。

### 合并行为 {#merge-behavior}

| 设置类型 | 策略 | 示例 |
|---|---|---|
| **能力** | 深度合并 | 全局设置 `file_context: false`，模型设置 `vision: true` > 模型两者兼有 |
| **其他元数据** | 仅填充 | 全局设置了描述，模型没有 > 模型获得全局的值 |
| **参数** | 简单合并 | 全局设置 `temperature: 0.7`，模型设置 `0.3` > 模型得到 `0.3` |
| **自定义参数** | 逐键合并 | 全局添加 `service_tier`，模型添加 `tools` > 模型两者兼有，且同名时以模型的值为准 |

自定义参数是通过 **添加自定义参数** 添加的那些，存储在 `custom_params` 下。它们是唯一按条目逐个合并的分组，因此自行定义了某个自定义参数的模型会同时保留全局的参数。

**默认功能** 和 **内置工具** 是整行生效的。一旦模型在其中任一行保存了自己的选择，该选择就会取代全局的那一行。模型可以关闭 **模型默认值** 开启的任一默认功能；而 **模型默认值** 关闭的内置工具，对于开启了该工具的模型仍保持开启。

:::info 请求中已设置的参数会保留自身的值
两层配置只会填充请求中未指定的部分。在[聊天补全](/reference/api-endpoints#chat-completions)请求正文中发送的参数会被保留，因此自行发送 `temperature` 或 `max_tokens` 的集成拿到的是它所请求的值，而不是模型保存的值。唯一的例外是 **流式回复**，无论请求如何设置，它仍决定回复是否以流式返回。
:::

:::warning 知识库与函数调用的相互影响
在全局参数中设置 `function_calling: native` 会改变**所有**模型处理已附加知识库的方式。在原生模式下，模型附加的知识库不会自动注入，模型必须调用内置工具来获取知识。如果知识库突然失效，请先检查全局默认值。

参见[知识库排查](/troubleshooting/rag#13-knowledge-base-attached-to-model-not-working)。
:::
### 批量管理 {#bulk-management}

管理员模型列表默认打开 **可用** 视图：其中包含连接当前提供的全部基础模型，以及全部工作区模型。**不可用** 则列出已不再由任何连接提供、但仍保存着设置的基础模型，例如提供商下架了某个模型或某个连接被移除之后的情形。**全部** 同时显示两者。

每个模型的三点菜单（**...**）以两个操作之一开头，两者都会先要求确认：

- **重置**，用于连接仍在提供的基础模型，会把为该模型保存的设置恢复为默认值。该模型仍保留在列表中。
- **删除**，用于工作区模型和不可用的基础模型，会把该模型及其保存的设置从列表中移除。

按状态（启用、禁用、可见、隐藏、公开、私密、已选、置顶）过滤管理员模型列表，并使用**批量操作**一次性启用、禁用、显示或隐藏当前视图中的所有模型。当外部提供商暴露数百个模型时非常有用。在筛选后的视图中同样支持拖拽排序：你拖动的模型会落在你放置位置旁边那个可见模型的位置上，而被筛选隐藏的每个模型都会保留原有位置。

## 已选模型与置顶模型（管理员） {#selected-and-pinned-models-admin}

这是两个实例级设置，用于决定用户一开始使用哪个（或哪些）模型。它们此前被称为 **默认模型**；现在界面中称为 **已选** 和 **置顶** 模型。其背后的配置键没有变化，因此现有的环境配置仍然有效。

| 设置 | 菜单操作 | 作用 | 配置键 |
| :--- | :--- | :--- | :--- |
| **已选模型** | **设为已选模型** | 为那些既没有自己的模型偏好、也没有[用户组默认模型](/features/authentication-access/rbac/groups#default-models-per-group)的用户，在新对话中预先选中该模型 | [`DEFAULT_MODELS`](/reference/env-configuration#default_models) |
| **置顶模型** | **设为置顶模型** | 为那些尚未自行置顶任何模型的用户，预先填充侧边栏中的模型快捷方式 | [`DEFAULT_PINNED_MODELS`](/reference/env-configuration#default_pinned_models) |

两者都接受多个模型，因此你可以给用户提供一组起始模型，而不是单个模型。

:::info 与模型默认值不同
同一页面顶部的 **模型默认值** 面板是另一项功能：它为所有模型设置基础能力、参数和提示词建议。参见 [全局模型默认值](#global-model-defaults-admin)。
:::

### 设置已选或置顶模型 {#setting-a-selected-or-pinned-model}

1. 前往 **设置 > 模型**（管理员区域）。
2. 用 **搜索模型** 找到该模型，或用视图筛选器缩小列表范围。
3. 点击模型所在行末尾的省略号（**...**）。
4. 选择 **设为已选模型** 或 **设为置顶模型**。

![模型省略号菜单中的“设为已选模型”和“设为置顶模型”](/images/features/models/model-row-menu.png)

改动会立即保存，无需单独的保存步骤，模型名称旁会出现 **已选** 或 **置顶** 标签。你可以对任意数量的模型重复此操作。要取消，只需打开同一个菜单并选择 **移除已选模型** 或 **移除置顶模型**。

:::tip 更快的切换方式
按住 **Shift** 并保持模型列表打开，每一行都会显示相同操作的行内图标按钮：眼睛切换可见性，对勾切换已选，图钉切换置顶、地球或锁切换公开访问，铅笔打开模型。已置顶的模型会显示一个带斜杠的图钉，因为点击它会取消置顶。松开 **Shift** 后这些图标会再次隐藏。

![按住 Shift 出现的行内快捷操作图标](/images/features/models/model-quick-actions.png)
:::

### 查看当前配置 {#reviewing-what-is-configured}

打开视图筛选器（**操作** 旁、默认为 **可用** 的下拉框），选择 **已选** 或 **置顶**，即可只列出当前按此方式配置的模型。同一下拉框还可以按全部、可用、不可用、启用、禁用、可见、隐藏、公开和私密筛选，也可以按 **基础模型** 或 **工作区模型** 筛选，从而区分你的服务商所提供的模型与在此基础上构建的模型。

![带有“已选”和“置顶”选项的视图筛选器](/images/features/models/model-view-filter.png)

### 已选模型如何为用户解析 {#how-a-selected-model-resolves-for-a-user}

对于新对话，Open WebUI 会按以下顺序取第一个能得到用户实际可用模型的结果：

1. `model` 或 `models` [URL 参数](/features/chat-conversations/chat-features/url-params)。
2. 启动该对话所在文件夹所绑定的模型（如果有）。
3. 用户自己的默认模型，通过在对话中使用 **设为默认** 保存。
4. [用户所属组的默认模型](/features/authentication-access/rbac/groups#default-models-per-group)，取自组层级中设置了默认模型的最深一层（层级相同时以最早创建的组优先）。通过父组继承而来的组同样计入。
5. 实例的 **已选模型**。
6. 列表中第一个可用的模型。

第 3 至 5 步同样决定了笔记和 Playground 中的起始模型。

已被隐藏或删除的模型在每一步都会被剔除，因此当用户上次使用的模型消失时，他们会落到一个可用的模型上，而不是看到空的选择器。

**置顶模型**的机制不同：它们只在用户尚未自行置顶任何模型时，为其侧边栏快捷方式提供一次初始值。此后用户自己的置顶优先，指向已隐藏或已删除模型的置顶会被自动清理。

:::warning 已选只是起点，而非限制
将某个模型设为已选，并不会阻止任何人切换到他们有权限使用的其他模型。要控制用户可以使用哪些模型，请使用按模型的访问控制或 **隐藏**，详见[策展式界面部署](#curated-interface-deployments)。
:::

## 对话中切换模型 {#model-switching-in-chat}

在不丢失上下文的情况下切换模型。同时选择最多两个模型，并排比较响应，使用箭头按钮在它们之间导航。模型选择器**支持搜索**，在 **Search a model** 输入框中输入即可筛选较长的列表；自定义模型只有在其**基础模型**可用时才可选择。

![模型选择器，支持搜索并显示已固定的模型](/images/features/chat/model-selector.png)

您也可以在不打开选择器的情况下切换。发送 `/model` 加上模型 ID，例如 `/model gpt-5.1`，聊天就会切换到该模型；单独发送 `/model` 则会告知当前聊天使用的模型。ID 必须完全匹配，显示名称无效；无法访问的 ID 会提示 `Model not found`。从 `/` 菜单中选择 **Model** 则会打开选择器并聚焦其搜索框。其他内置斜杠命令参见[聊天功能](/features/chat-conversations/chat-features/)。

模型变更会立即随聊天一同保存，因此重新打开该聊天时仍是这个模型。切换会应用新模型的默认工具、技能、过滤器、功能和终端，同时保留您自己开启或关闭的内容。新模型无法使用的功能和过滤器会被关闭。使用 `@` 选择模型并发送消息时，聊天会切换到该模型。

创建一个带有 CRM 知识库、异议处理提示词和邮件起草工具的"销售助手"。与销售用户组共享。工程团队永远看不到它。

## 策展式界面部署 {#curated-interface-deployments}

一种常见的部署模式是向普通用户展示一个策展好的模型（一个带有特定名称、图标、系统提示词和工具的预配置智能体），同时将原始基础模型隐藏起来。

在选择方法之前，先了解支配这一切的一条规则。

### 规则：自定义模型始终需要访问其基础模型 {#the-rule-a-custom-model-always-requires-access-to-its-base-model}

你在**工作区 > 模型**下创建的每个模型都是一个*工作区模型*：它指向一个基础模型并存储对它的引用，而不是该基础的独立副本。创建它永远不会产生第二个独立的基础模型。它始终位于现有基础之上。

当用户运行工作区模型时，Open WebUI 会检查**工作区模型**和**其底层基础模型**的访问权限。如果用户无法访问基础模型，请求将失败并显示**"未找到模型"**，即使工作区模型本身已公开与他们共享。

这是设计使然。没有它，任何人都可以通过在受限制的基础上构建工作区模型并公开共享该包装器来绕过基础模型的访问控制。共享包装器永远不能授予基础模型拒绝的访问权限。

:::warning
如果你以前依赖工作区模型向用户提供他们无法直接看到的基础模型访问权限，那依赖的是一个已被修补的访问控制漏洞。它不再有效，而且从来就不安全。
:::

实际后果：任何应该使用你的策展模型的人也必须有权访问其基础模型。你**隐藏**基础模型不让这些用户看到，而不是限制他们的访问。

### 推荐：带有策展模型在上层的隐藏公开基础模型 {#recommended-a-hidden-public-base-model-with-a-curated-model-on-top}

这是为每个人提供统一策展体验的可靠方法：

1. 将基础模型（例如"GPT-5.6"）设置为**公开**，以便每个目标用户都能通过基础访问检查。
2. **隐藏**基础模型（省略号 **...** > **隐藏**），使其不出现在模型选择器中。
3. 在该基础之上创建一个策展工作区模型。赋予其自己的名称、头像、系统提示词、知识和工具，然后与你的用户共享（或保持公开）。

普通用户现在在选择器中只看到策展模型。基础模型在底层仍然可访问，这是策展模型运行的条件，但它在列表中不可见。管理员仍然可以通过其直接 URL 打开隐藏的基础模型。

:::tip 升级上游模型
当你迁移到更新的 LLM 时，更新策展工作区模型上的基础模型选择，并重新指向基于旧基础构建的其他任何内容。**导出**和**导入**可帮助你跨条目携带设置。
:::

### 如果有些用户还需要看到原始基础模型 {#if-some-users-must-also-see-the-raw-base-model}

**隐藏**是全局的：隐藏的基础模型对所有人都隐藏，因此你不能用它来向高级用户显示原始模型，同时不让普通用户看到。工作区模型也不能做到这一点，因为它如上所述继承基础访问权限。

要给一个组在其选择器中提供原始模型，而其他所有人只获得策展模型，相同的上游 LLM 必须作为**两个独立的基础模型**出现，每个都有自己的访问控制。这是一个连接级别的设置（例如，通过第二个连接添加模型），不是你能从**工作区 > 模型**创建的东西。将一个基础条目限制给你的高级用户，并使策展模型公开。因为两者都是基础模型，所以不会继承对方的访问权限。

## 局限性 {#limitations}

### 预设而非微调 {#preset-not-fine-tune}

模型预设通过系统提示词和工具绑定配置行为。它们不修改底层模型权重。对于深层行为更改，您需要实际的微调。

### 回退需要配置 {#fallback-requires-configuration}

如果基础模型不可用，预设将会失败，除非将 `ENABLE_CUSTOM_MODEL_FALLBACK` 设置为 `True` 并在 **设置 > 模型**（管理员区域）中配置了至少一个[已选模型](#selected-and-pinned-models-admin)。

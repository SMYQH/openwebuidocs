网页搜索失败时，先区分是搜索请求失败，还是无法读取搜索结果中的网页。本指南涵盖代理设置、搜索服务错误、内容为空、超时，以及模型未调用搜索工具等问题。

## 常见 Web Search 问题 {#common-web-search-issues}

### 1. Web Search 在 HTTP 代理后失效 {#1-web-search-fails-behind-http-proxy}

如果你把 Open WebUI 部署在 HTTP 代理后，可能会发现搜索查询本身可以成功（例如 SearXNG 能返回结果），但后续内容抓取会失败，并出现类似错误：

- `[Errno -3] Temporary failure in name resolution`
- `Connection timeout to host`
- `None of the web search results could be loaded`

默认是信任代理的（`WEB_SEARCH_TRUST_ENV`），因此在默认安装下，这通常意味着 **信任代理环境** 已在 **设置 > Web Search**（管理员区域）中关闭并保存——在那里保存的值优先于环境变量。每个结果 URL 在抓取前也会在本地解析。只有代理才能解析域名时，日志中会显示 `Could not resolve host`，你还需要设置 `ENABLE_LOCAL_WEB_FETCH=True`，它同时允许抓取内网地址。

✅ **解决方法：**

1. 前往：**设置 > Web Search**（管理员区域）
2. 启用 **信任代理环境**
3. 保存修改

或者设置环境变量 [`WEB_SEARCH_TRUST_ENV`](/reference/env-configuration#web_search_trust_env)：

```bash
WEB_SEARCH_TRUST_ENV=True
```

:::info
这是一个 **ConfigVar** 变量，意味着它既可以在启动时通过环境变量设置，也可以通过管理面板 UI 配置。一旦你在 UI 中设置了它，数据库中的值就会优先生效。

这个设置会让 Open WebUI 的网页内容加载器遵循环境变量中的代理设置（`http_proxy`、`https_proxy`）。如果不开启，即使你的搜索引擎本身能通过代理工作，从返回 URL 抓取内容时仍然会失败。
:::

### 2. 来自 SearXNG 的 403 Forbidden 错误 {#2-403-forbidden-errors-from-searxng}

如果你使用的是 SearXNG，并在日志中看到 `403 Client Error: Forbidden`，通常说明没有启用 JSON 格式。

✅ **解决方法：**

编辑你的 SearXNG `settings.yml`，并在 formats 列表中加入 `json`：

```yaml
search:
  formats:
    - html
    - json
```

修改后重启 SearXNG。

### 3. 内容为空或结果质量差 {#3-empty-content-or-poor-results}

如果 Web Search 返回空内容或结果质量很差，问题通常与上下文窗口大小或内容提取有关。

✅ **解决方法：**

- **增加上下文长度**：网页通常包含 4,000 到 8,000 个 token 或更多。在显存小于 24 GiB 的 GPU 上，Ollama 默认使用 4096 个 token，模型会丢失大部分内容。在管理后台的 **设置 > 模型 > 编辑** 中打开模型的 **高级参数**，将上下文长度增加到至少 16384 个 token。低于这个值不适合处理网页内容。

- **检查结果数量**：通过调整 `WEB_SEARCH_RESULT_COUNT` 控制抓取的结果数。

  在 Native/Agentic 工具调用模式下，如果模型在 `search_web` 中省略了 `count`，Open WebUI 会默认使用 `WEB_SEARCH_RESULT_COUNT`。如果模型提供了 `count`，也会被限制在管理员配置的同一最大值以内。

- **搜索使提示词超出上下文限制。** 在原生模式下，请检查对话是否调用了 `fetch_url`。该工具返回提取出的页面文本，可能在一条结果中发送很长的页面。在管理员区域的**设置 > Web 搜索**中，将**获取 URL 内容长度限制**设为大于零的字符数，然后在新对话中重试。为对话、其他工具结果和回答预留空间。该限制适用于每条 `fetch_url` 结果。

  在旧版模式下，请检查**设置 > Web 搜索**中的**跳过嵌入和检索**。启用它后，加载的页面文本会直接进入提示词。关闭它可以检索相关文本块，也可启用**跳过 Web 加载器**以使用搜索摘要。参见 [Web 搜索配置参考](/reference/env-configuration#bypass_web_search_embedding_and_retrieval)。

- **尝试不同 loader**：把 `WEB_LOADER_ENGINE` 改为 `playwright` 以处理 JavaScript 较重的网站，或使用 `firecrawl`/`tavily` 获得更好的提取效果。

- **设置真实的 User-Agent**：如果来自维基百科、受 Cloudflare 保护的网站或其他大型发布商的结果为空（或日志中出现 403），说明网站的机器人检测机制过滤了 Python `requests`/`aiohttp` 的默认用户代理。请将 [`USER_AGENT`](/reference/env-configuration#user_agent) 设置为类似真实浏览器的字符串（例如 `Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0 Safari/537.36`）。此设置影响网页搜索结果的抓取、`fetch_url` 工具和通过 `#` 附加的网页，包括检查链接是否指向 PDF 等文件。

- **你自己网络上的结果会被跳过**：解析到私有地址、回环地址或其他非全局可路由地址的结果 URL 会在抓取前被丢弃，日志中会显示 `Blocked non-global address:` 及该地址。要搜索内网，请设置 [`ENABLE_LOCAL_WEB_FETCH=True`](/reference/env-configuration#enable_local_web_fetch)，这样每个能发起对话的用户都可以通过服务器访问内部地址。

- **压缩响应会被拒绝**：Open WebUI 会请求未压缩的页面和文件，并以 `The server answered with a compressed response, which is not accepted.` 拒绝压缩响应。如果主机总是以压缩方式发送文件（例如上传时带有 `Content-Encoding` 说明头的 S3 或 MinIO 对象），就无法读取。请在不带该说明头的情况下重新上传文件。

关于上下文窗口问题的更多细节，请参阅 [RAG 故障排查指南](./rag)。

### 4. Web Search 已启用但模型没有调用 `search_web` {#4-web-search-is-enabled-but-the-model-does-not-call-search\_web}

如果网页搜索引擎已经配置好（例如以 DuckDuckGo 为后端的 DDGS）、模型也启用了 Web Search、当前对话的 Web Search 开关也已打开，但助手仍然不搜索就作答，那么问题通常出在模型能力而不是搜索提供商。

在 Native/Agentic 模式下，Open WebUI 会把网页搜索暴露为 `search_web` 工具。模型必须自行决定调用该工具并返回有效的结构化工具调用。较旧、较小或较弱的本地模型可能会漏掉这个工具、无视它，或者即使 Open WebUI 的所有设置都正确也产出格式错误的工具调用。

**解决方法：**

- **为网页搜索工作流使用现代的高质量工具调用模型。** 前沿模型或近期的大型开放权重模型，在判断何时该搜索以及正确组织工具调用方面，都比老旧或较小的模型可靠得多。有关模型要求与建议，请参阅[工具调用模式：原生与旧版](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)。
- **确认原生函数调用已启用**：在管理后台的 **设置 > 模型 > 编辑** 中打开模型的 **高级参数 > 函数调用**。内置的网页搜索工具属于原生模式工具。
- **如果模型一直不搜索就作答**，例如回答“我没有实时访问能力”，请把模型切换到旧版。在模型的 **高级参数** 中把 **函数调用** 设为 **旧版**。在旧版模式下，只要对话的网页搜索开关是打开的，Open WebUI 就会在模型作答前自行执行搜索，查询由任务模型撰写，因此模型不必自行决定是否搜索。如果任务模型返回空的查询列表，则会跳过搜索，对话中显示状态 `No search query generated`。如果 **设置 > 界面**（管理员区域）中的 **网页搜索查询生成** 处于关闭状态，或者查询生成失败，Open WebUI 会用你原样发送的消息进行搜索。旧版模式不受支持，也没有内置工具，因此 `fetch_url` 和其他原生工具都不可用。请参阅[工具调用模式](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)。
- **检查五道网页搜索开关**：全局已启用网页搜索、模型上已启用网页搜索、模型的内置工具中包含网页搜索类别、对话中已打开网页搜索开关，以及用户所在用户组拥有 `features.web_search` 权限。
- **对于 DDGS / DuckDuckGo 配置**，请参照 [DDGS 提供商指南](/features/chat-conversations/web-search/providers/ddgs)单独确认提供商配置；但如果 DDGS 在日志中返回了结果而助手却从不调用 `search_web`，请更换模型。

### 5. 连接超时 {#5-connection-timeouts}

如果 Web Search 经常超时：

✅ **解决方法：**

- **降低并发请求数**：设置 `WEB_SEARCH_CONCURRENT_REQUESTS=1`，按顺序执行（推荐用于 Brave 免费层；Brave 客户端在收到 429 后已经会自动重试一次）。

- **调整 loader 并发**：如果同时抓取很多页面，请降低 `WEB_LOADER_CONCURRENT_REQUESTS`。

- **检查网络连通性**：确认 Open WebUI 能访问搜索引擎以及搜索结果对应的 URL。

### 6. SearXNG 没有报错，但返回空结果 {#6-searxng-returns-no-results-without-an-error}

SearXNG 可能用一份空的结果列表来回应一次搜索，例如它查询的上游搜索引擎用验证码或速率限制拦住了这个实例。Open WebUI 只读取 SearXNG 响应中的 `results` 列表，因此它把这当成一次什么都没搜到的搜索，而不是一次 SearXNG 故障。

你看到什么取决于模型的 **函数调用** 设置：

- **旧版**：回复下方的网页搜索状态显示 `No results found from web search`，模型在没有网页内容的情况下作答。
- **原生**或**默认**：`search_web` 工具给模型返回一份空列表。对话中不会出现错误，模型可能会说自己什么都没找到。

✅ **解决方法：**

- **查看 SearXNG 日志**，寻找验证码、超时或访问被拒之类的引擎错误。
- **在 SearXNG 的 Web 界面中运行同一个查询**，看看是否有引擎返回了结果。
- **在 SearXNG 的 `settings.yml` 中关闭出问题的引擎或启用其他引擎**，然后重启 SearXNG。

## 环境变量参考 {#environment-variables-reference}

完整的 Web Search 环境变量列表，请参阅 [环境变量配置文档](/reference/env-configuration#web-search)。

常用变量：

| 变量 | 说明 |
|----------|-------------|
| `WEB_SEARCH_TRUST_ENV` | 为内容抓取启用代理支持 |
| `WEB_SEARCH_RESULT_COUNT` | 要抓取的搜索结果数量 |
| `WEB_SEARCH_CONCURRENT_REQUESTS` | 向搜索引擎发起的并发请求数（位于“搜索结果数量”旁的“并发请求数”字段；`0` 表示不限制） |
| `WEB_LOADER_CONCURRENT_REQUESTS` | 页面抓取并发数（位于 Loader 部分的“并发请求数”字段；默认为 10） |
| `WEB_LOADER_ENGINE` | 内容提取引擎 |


以上都是持久化设置，当前生效的值以管理后台的 **设置 > Web Search** 为准。页面抓取器每次搜索时都会从已保存的配置中读取代理信任、加载器并发数和 SSL 校验设置。因此，保存的更改会在下次搜索时生效，无需重启。这与这些设置在其他位置的行为一致。如果管理面板中的更改似乎没有生效，请回到面板核对。环境变量只用于设定初始值，之后以已保存的设置为准。

**Web Search Engine** 只在 **Web Search** 开启期间才是必需的，因此 **Loader** 设置可以在没有它的情况下保存。

当 **Web Search** 关闭时，页面会隐藏那些仅对搜索生效的设置，但它们已保存的值会被保留。

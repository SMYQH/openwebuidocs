# 聊天数据隐私与加密 {#chat-data-privacy--encryption}

Open WebUI 是自托管软件。您的组织控制服务器、数据库、存储、模型连接、日志、备份和网络部署。

Open WebUI 可以通过数据库加密、HTTPS/TLS、SSO/RBAC、管理员访问控制、临时聊天、私有模型以及为敏感组提供独立部署来减少聊天数据暴露。

Open WebUI 的标准体验旨在提供自托管控制、可审计性、历史记录、搜索、RAG、工具和管理治理。以下控制帮助组织决定聊天数据存储的位置、谁可以通过产品访问、哪些模型端点接收提示以及数据保留多长时间。

## 按关注领域划分的控制 {#controls-by-concern}

| 关注领域 | 最佳可用措施 |
| :--- | :--- |
| 在界面中向管理员隐藏用户聊天 | 设置 `ENABLE_ADMIN_CHAT_ACCESS=false` |
| 控制管理员通过产品界面导出内容 | 设置 `ENABLE_ADMIN_EXPORT=false` |
| 限定管理员工作区列表/选择器可见性 | 设置 `BYPASS_ADMIN_ACCESS_CONTROL=false` |
| 生产数据库存储暴露 | 使用 PostgreSQL，配合加密卷、提供商加密、TDE（如可用）、TLS 和加密备份 |
| 仅 SQLite 部署 | 将数据目录放在加密文件系统上（LUKS、BitLocker、FileVault） |
| 员工提出敏感或个人问题 | 使用临时聊天，或通过 `USER_PERMISSIONS_CHAT_TEMPORARY_ENFORCED=true` 强制非管理员用户使用临时聊天 |
| 用户互相讨论敏感话题 | 在私聊和私密群组中使用[加密聊天](/features/channels/encrypted-chats)：在浏览器中端到端加密，且从不存储在服务器上 |
| 将提示保留在基础设施内部 | 使用本地或私有模型端点，并按组限制批准的模型 |
| 敏感文档上传或索引 | 关闭文件上传权限（它默认开启），并保持知识库权限关闭；仅按组授予 |
| 控制服务器端代码执行 | 将工具和函数限制为受信任的管理员 |
| 聊天内容出现在日志中 | 除非明确批准记录正文，否则将审计日志保持在元数据级别 |
| 共享控制 | 关闭社区共享（它默认开启），并审查聊天共享权限 |
| 不同团队需要不同的信任边界 | 使用独立的 Open WebUI 实例，配备独立的数据库、备份、凭证、操作员和模型提供商 |

## 推荐基线 {#recommended-baseline}

### 使用 PostgreSQL 配合加密存储 {#use-postgresql-with-encrypted-storage}

对于生产部署，请使用 PostgreSQL 并在 PostgreSQL 或存储层配置加密。使用加密卷、提供商管理的加密、TDE（如可用）、TLS 用于数据库连接、加密备份和网络隔离。

```bash
DATABASE_URL=postgresql://user:password@db-host:5432/openwebui
```

数据库加密保护静态数据。运行中的 Open WebUI 应用程序使用数据库密钥为经过身份验证的用户提供服务并执行正常产品工作流。

对于仅部署 SQLite 的情况，请将数据目录放置在加密文件系统上（Linux 上的 LUKS、Windows 上的 BitLocker、macOS 上的 FileVault）。不支持 SQLCipher。

### 限制管理员访问聊天和导出内容的途径 {#limit-admin-chat-and-export-surfaces}

```bash
ENABLE_ADMIN_CHAT_ACCESS=false
ENABLE_ADMIN_EXPORT=false
BYPASS_ADMIN_ACCESS_CONTROL=false
```

这些功能会在界面中隐藏其他用户的聊天记录和导出内容，使其不被管理员看到。但这并不会阻止管理员访问这些数据；请参阅 [管理员用户](#admin-users)。

### 使用 SSO 并限制账户 {#use-sso-and-restrict-accounts}

```bash
ENABLE_LOGIN_FORM=false
ENABLE_PASSWORD_AUTH=false
ENABLE_PASSWORD_CHANGE_FORM=false
DEFAULT_USER_ROLE=pending
```

使用您的身份提供商进行 MFA、条件访问、设备状态、组成员资格和用户生命周期管理。尽可能使用 SCIM。对于仍然直接登录 Open WebUI 的账号，请开启内置的[双因素登录](/features/authentication-access/mfa)。

### 在不需要历史记录时使用临时聊天 {#use-temporary-chat-where-history-is-not-needed}

临时聊天可以减少保存的聊天记录。启用强制临时聊天后，用户必须使用此模式。

要使临时聊天默认可用：

```bash
USER_PERMISSIONS_CHAT_TEMPORARY=true
```

要强制非管理员用户使用临时聊天：

```bash
USER_PERMISSIONS_CHAT_TEMPORARY_ENFORCED=true
```

相关权限：

- **聊天 > 临时聊天**
- **聊天 > 强制临时**

对于同时拥有这两项权限的用户，服务器将拒绝在所有路径下保存聊天记录，包括直接调用 API、导入聊天、克隆和分叉操作。用户仍可打开已有的聊天记录。此限制不适用于管理员。

临时聊天减少保存的聊天历史。当前活动的提示仍由 Open WebUI 和配置好的模型端点处理。您保持启用的工具仍会在临时聊天中运行，并可能存储自己的数据，因此请在需要时在相关模型上禁用这些工具。

### 将敏感提示保留在私有模型上 {#keep-sensitive-prompts-on-private-models}

对于敏感数据，优先选择由您的组织控制的本地或私有模型端点。按组限制外部模型，并按数据类别批准提供商。

### 限制高级功能 {#restrict-advanced-capabilities}

```bash
USER_PERMISSIONS_WORKSPACE_TOOLS_ACCESS=false
USER_PERMISSIONS_WORKSPACE_KNOWLEDGE_ACCESS=false
USER_PERMISSIONS_CHAT_FILE_UPLOAD=false
ENABLE_COMMUNITY_SHARING=false
ENABLE_API_KEYS=false
```

仅向批准的组授予高级功能。

### 默认保持日志仅为元数据 {#keep-logs-metadata-only-by-default}

```bash
AUDIT_LOG_LEVEL=METADATA
ENABLE_AUDIT_STDOUT=true
LOG_FORMAT=json
```

仅在您的日志平台获批用于聊天内容时，使用 `REQUEST` 或 `REQUEST_RESPONSE` 审计日志记录。

审计日志默认关闭（`AUDIT_LOG_LEVEL=NONE`）。默认情况下，`/api/v1/chats/*`、`/api/v1/folders/*` 和 `/api/chat/*`（包括 `/api/chat/completions`）路由在任何级别都被排除，除非修改 `AUDIT_EXCLUDED_PATHS` 或设置 `AUDIT_INCLUDED_PATHS`；但 `/openai/chat/completions` 和 `/ollama/api/chat` 代理路由不在排除范围内。请求体默认截断为 2048 字节（`MAX_BODY_LOG_SIZE`），文件输出默认写入数据卷内的 `DATA_DIR/audit.log`，除非设置了 `AUDIT_LOGS_FILE_PATH`。

## 谁可以阅读聊天数据？ {#who-can-read-chat-data}

### 普通用户 {#regular-users}

普通用户可以阅读自己的聊天记录以及明确与他们共享的聊天记录。访问权限由角色、组、权限和资源级访问授予控制。

### 管理员用户 {#admin-users}

管理员控制着该实例，因此请将每位管理员视为能够阅读所有聊天记录。`ENABLE_ADMIN_CHAT_ACCESS=false` 和 `ENABLE_ADMIN_EXPORT=false` 仅在界面中隐藏其他用户的聊天记录和导出内容。 管理员仍可通过其他方式访问数据，例如安装在服务器上运行代码的功能或工具，以及通过内部聊天（如子代理聊天），这些聊天内容可通过 ID 读取。请将管理员角色以及数据库、主机和备份的访问权限，仅授予您信任且能够妥善保管数据的人员。

### 数据库、主机和备份操作员 {#database-host-and-backup-operators}

有权访问数据库、主机、持久卷、应用密钥或未加密备份的操作员属于聊天数据信任边界的一部分。

对于需要独立操作员信任边界的组，请使用具有独立基础设施和操作员的独立 Open WebUI 实例。

### 模型提供商 {#model-providers}

如果配置了外部模型提供商，发送用于推理的提示和上下文可能对该提供商可见。对于应保留在您基础设施内部的数据，请使用私有/本地模型。

## 加密保护什么 {#what-encryption-protects}

Open WebUI 把聊天标题以明文存储，把聊天内容以明文 JSON 存储在数据库中，把上传的文件未加密地存放在 `DATA_DIR/uploads`（或配置的对象存储）中，并把文档分块以明文存放在向量存储中，因此静态保护来自数据库、卷或存储层（pgvector 可以用 `PGVECTOR_PGCRYPTO=true` 加密分块文本）。

静态加密有助于防止以下情况：

- 磁盘丢失或被盗。
- 数据库文件被复制。
- 卷快照放错位置。
- 备份泄露（当备份单独加密时）。
- 部分未波及运行中应用密钥的基础设施入侵。

将这些路径保留在您的运营信任边界内：

- 运行中的 Open WebUI 应用程序、其数据库密钥，以及 `WEBUI_SECRET_KEY`——后者用于签署会话，并默认加密已存储的 OAuth 令牌、OAuth 客户端密钥和其他已存储的机密（它不加密聊天数据）。
- 具有实时查询访问权限的数据库管理员。
- 有权访问环境变量或挂载密钥的主机操作员。
- 包含聊天数据的导出、日志、跟踪和备份。
- 接收提示进行推理的模型提供商。

## 实际部署模式 {#practical-deployment-patterns}

对于一般内部用途：

- 使用 SSO/MFA。
- 加密数据库和备份。
- 限制管理员聊天访问和导出。
- 保持日志仅为元数据。
- 按组限制外部模型和文件上传。

对于敏感部门（如人力资源、法务或受监管工作负载）：

- 运行独立的 Open WebUI 实例。
- 使用独立的数据库和备份。
- 使用独立操作员和凭证。
- 使用私有/本地模型。
- 考虑对非管理员用户强制临时聊天，通过 `USER_PERMISSIONS_CHAT_TEMPORARY_ENFORCED=true` 设置。

对于个人或高度敏感的员工问题：

- 发布清晰的使用指南。
- 提供临时聊天，或要求非管理员用户使用。
- 仅将那些提示路由到批准的模型提供商。
- 明确说明谁管理系统以及保留什么内容。

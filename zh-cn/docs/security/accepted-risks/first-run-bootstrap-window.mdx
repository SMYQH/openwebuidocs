# 首次运行的管理员提升 {#first-run-admin-promotion}

|  |  |
| :--- | :--- |
| **类别** | CWE-362，竞争条件 |
| **状态** | 可利用的问题已在 0.9.0 修复；剩余风险已接受，因为失败时不会授予管理员权限 |
| **追踪为** | [GHSA-h3ww-q6xx-w7x3](https://github.com/open-webui/open-webui/security/advisories/GHSA-h3ww-q6xx-w7x3) / [CVE-2026-45675](https://www.cve.org/CVERecord?id=CVE-2026-45675) |

---

## 概述 {#summary}

新建的 Open WebUI 实例在创建第一个账户之前没有管理员。该首个账户会被自动提升为管理员，随后注册功能关闭。

最初的实现会先检查是否已存在用户，根据该结果决定角色，然后才插入账户。如果两个注册请求同时到达，它们可能都读到空表，并都被插入为管理员。该问题被报告给我们、得到修复，并以 [CVE-2026-45675](https://www.cve.org/CVERecord?id=CVE-2026-45675) 发布。

## 我们修复的内容 {#what-we-fixed}

执行顺序被颠倒了。现在账户会先以默认角色插入，只有在事后发现它是唯一存在的账户时才会被提升：

```python
# before: decide the role from a check that another request can invalidate
has_users = Users.has_users(db=db)
role = "admin" if not has_users else DEFAULT_USER_ROLE
user = Auths.insert_new_auth(..., role=role)
```

```python
# after: insert first, promote only if this account is the only one
user = Auths.insert_new_auth(..., role=DEFAULT_USER_ROLE)
if Users.get_num_users(db=db) == 1:
    Users.update_user_role_by_id(user.id, "admin", db=db)
    ENABLE_SIGNUP = False
```

注册路径在 **0.8.4** 中改为这种方式，LDAP 与 OAuth 注册路径则在 **0.9.0** 中改为这种方式，后者也是上述公告的修复版本。

## 剩余部分 {#what-remains}

插入操作与随后的计数并未共享同一个数据库事务。因此在使用 PostgreSQL 的部署上，两个在同一瞬间到达的注册请求可能各自都看到对方已经存在，于是双方的计数都返回 2，两个账户都不会被提升。实例上会留下账户，却没有管理员。

修复后的设计刻意让失败表现为拒绝授权。旧实现会给每个参与竞争的注册请求授予管理员角色；修复后，发生这种情况时，两个账户都不会获得管理员角色。这只会发生在空数据库刚开始接收注册请求时，因此实例上没有聊天、设置或其他账户可被窃取。遇到这种状态时，运维人员可以删除空数据库并重新开始，不会丢失数据。

使用默认 SQLite 后端的部署不受影响，因为它的写锁可以防止两次注册以这种方式重叠。

## 为何接受 {#why-it-is-accepted}

对没有存量数据的实例而言，失败时拒绝授权比旧行为更可取。要完全消除剩余问题，必须重写提升逻辑，使其与插入操作在同一个事务中执行。但当前行为在失败时已经不会向任何人授予管理员角色，因此重写不会带来额外的安全收益。

这个窗口的另一半根本不是残余问题，而是一个部署决策。第一个注册的人会成为管理员，而在尚未完成配置就已被暴露的实例上，这个人未必是运维人员。**Open WebUI 面向的是私有的、可信的网络；我们在任何情况下都不建议把未配置的实例暴露到公共网络。** 请先在私有网络、VPN 或本地端口上完成配置。参见加固指南中的[网络部署位置](/getting-started/advanced-topics/hardening#network-placement)。

如果实例必须立即可访问，请在首次启动前设置 `WEBUI_ADMIN_EMAIL` 与 `WEBUI_ADMIN_PASSWORD`，通过启动流程而非界面来创建管理员账户。该账户会在启动过程中被创建，注册会自动关闭，任何其他注册尝试都会被拒绝。参见[通过环境变量设置管理员账户](/getting-started/advanced-topics/hardening#admin-account-from-environment-variables)。

# LLM 输出不可预测性 {#llm-output-unpredictability}

|  |  |
| :--- | :--- |
| **类别** | 模型固有问题（提示注入、越狱、不安全或幻觉输出）— OWASP LLM Top 10 |
| **状态** | LLM 固有风险，不是可修复的应用缺陷；单独出现时不属于漏洞报告范围，除非证实它与实际的 Open WebUI 漏洞构成攻击链（参见[安全政策](../security-policy)） |

---

## 概述 {#summary}

Open WebUI 认可 [OWASP LLM 应用 Top 10](https://owasp.org/www-project-top-10-for-large-language-model-applications/) 的价值：它为分析 AI 系统如何失效提供了框架。不过，其中许多行为并非传统的安全漏洞，而是大型语言模型本身的风险。任何基于这类模型的应用都会面临这些风险，并非某个供应商的代码缺陷所致。当模型可以使用工具并自主执行任务时，同样的风险也会延伸到智能体行为；参见[智能体应用风险](./agentic-application-risks)。

大型语言模型是非确定性的，且可被其输入操纵。模型可能通过精心设计的提示、获取的网页或上传文档中的注入内容，或对抗性对话，被说服产生不安全、误导性或攻击者期望的输出：越狱、提示注入、幻觉事实、不安全建议，或尝试以用户未预期的方式使用可用工具。

这种不可预测性源于语言模型本身的工作方式。它**不是 Open WebUI 代码的缺陷**。

## 我们如何缓解风险 {#what-we-mitigate}

Open WebUI 控制模型*周围*的系统，并在这一层采取加固措施：

- **访问控制和隔离**限制模型及其工具的访问范围：按用户隔离数据、应用[工具和函数权限模型](/features/extensibility/plugin/)，并在容器中隔离执行代码。
- **模型不能超越调用用户自身的权限。** 代表用户行动时，它受该用户权限约束；它不能读取或执行用户无法做到的事情。
- **运维侧防护措施**（[过滤器](/features/extensibility/plugin/functions/filter)、内容检查、确认提示）让部署方可以添加自己的策略层。

这些措施减轻不良模型输出造成的*后果*，却无法保证模型输出始终可预测或安全。

## 剩余部分及为何不被视为漏洞 {#what-remains-and-why-it-is-not-treated-as-a-vulnerability}

其全部影响为**模型的输出**的安全问题——模型被说服说了什么、推荐了什么或尝试了它已被允许尝试的行动——是**LLM 固有的，且单独而言不是 Open WebUI 漏洞**。它受限于模型对齐的技术现状，而非 Open WebUI 代码可修补的内容，且"使模型永不产生有害输出"不是可实现的应用级修复。

因此，**当全部影响仅为模型产生不期望的内容，或被说服误用其已被允许使用的能力时，我们不接受作为漏洞的报告。** 该行为是运行 LLM 的已接受固有属性，不会作为缺陷处理。

**这是关于模型行为的范围声明，而非全面豁免。** 一旦精心设计的输入从"模型说了什么"跨越到 Open WebUI 自身代码或控制中的具体缺陷，报告**就属于范围**内，并被视作真实漏洞处理，例如：

- 提示注入**通过 Open WebUI 代码路径升级为代码执行、数据访问或权限提升**；
- **绕过访问控制、权限或隔离检查**；或
- 模型仅为底层应用错误的**触发**因素的任何缺陷。

这些是 Open WebUI 的缺陷，并会作为缺陷进行修复。完整报告范围请参见[安全政策](../security-policy)。

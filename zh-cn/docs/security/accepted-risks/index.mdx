# 已知与已接受风险 {#known--accepted-risks}

**Open WebUI 已评估这些残余风险，在技术可行或运维合理的范围内尽力缓解，并正式接受这些风险。**

某些弱点无法在应用代码中完全消除。它们受限于编程语言、运行时、编译器和解释器优化、操作系统、CPU 或网络，而非 Open WebUI 可以修补的缺陷。对于这些，我们将可利用部分缩小到应用级代码允许的范围，然后将剩余部分记录在此，作为已知的已接受风险。

少数风险可以通过修改代码消除，但会影响确实依赖现有行为的部署。因此，我们改用可配置的控制措施。

每条记录说明风险是什么、采取了哪些缓解措施、为什么无法修复剩余风险或修复会影响正常运行的部署，以及如何在我们的[威胁模型](#threat-model)中评估该风险。

---

## 为何接受这些风险 {#why-we-accept-these}

接受残余风险是有意的工程决策，而非疏忽。仅当以下所有条件都成立时，弱点才会被列入此处：

- **可利用部分已尽可能缓解**，在应用级代码允许的范围内，或通过运维人员可以施加的控制手段。
- **残余风险有明确的边界**：在实践中难以可靠利用，或仅在运维人员主动启用受影响的功能时存在，默认部署不受影响。
- **消除该残余部分是不值得的**，原因至少符合以下之一：
  - 它**在技术上无法由我们修复**，源于语言、运行时、操作系统、CPU 或网络，而非 Open WebUI 自身逻辑；或
  - 进一步修复会带来**真实且不成比例的成本**，降低或移除用户合法依赖的功能，或损害性能或正确性，以换取边际或虚幻的安全收益；或
  - 进一步修复**不会带来任何安全收益**，因为当前控制会在失败时拒绝访问，不会给任何人授予权限。

无论出现哪种情况，我们都会明确记录残余及其限制，而不是暗示无法或不应做出的保证。

## 威胁模型 {#threat-model}

Open WebUI 是一个**自托管、单租户、经过身份验证、基于角色**的应用程序。此处的风险在此模型内评估：

- **用户必须先通过身份验证**，然后才能接触任何用户数据或产品功能。浏览器在登录之前需要的端点（登录、注册，以及登录页面读取的公共配置）按设计无需账户即可访问。
- **管理员**是受信任的行为者，拥有完整的系统控制权。
- 报告根据**默认或更严格**的配置进行评估。

如果残余的实际影响主要由网络和调度噪声主导，或仅在威胁模型已排除的条件下可观察，则该残余被视为已接受而非可修补的缺陷。有关完整模型，请参阅[安全政策](../security-policy.mdx)。

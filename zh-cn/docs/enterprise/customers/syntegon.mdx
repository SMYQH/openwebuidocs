# 全球科技公司 Syntegon 借助 Open WebUI 让 500 多个 RAG 智能体投入工作 {#global-technology-company-syntegon-puts-500-rag-agents-to-work-with-open-webui}

![Syntegon](/images/enterprise/customers/syntegon/hero.png)

## 概述 {#overview}

:::info
Syntegon 基于 Open WebUI 构建了 Syntia（Syntegon Intelligence Assistance），并将其托管在 AWS 上。它为工程、运营、合规等各个部门的员工提供了一个受 SSO 保护、可完整审计的统一平台，支持 8 个以上的 AI 模型和 RAG 智能体。
:::

### 概览 {#at-a-glance}

- **行业**：全球科技公司
- **公司规模**：7,300 名员工，分布于 20 多个国家的 49 个地点；总部位于德国斯图加特
- **上线时间**：2025 年 12 月
- **活跃用户**：报告时最近 14 天内有 2,000–2,500 名
- **访问方式**：面向 Syntegon 全球所有员工授权，但在合规要求与当地法规限制访问的地区除外
- **部署方式**：欧盟境内的 AWS Fargate 上的 Amazon EKS，配备 Kubernetes 自动扩缩容；数据仅驻留在欧盟境内
- **模型**：横跨 Azure OpenAI 与 AWS Bedrock 的 8 个以上模型，包括 OpenAI GPT 与 Anthropic Claude；默认使用 GPT-5-mini
- **集成**：SharePoint、Confluence、Jira 与 Web 搜索
- **关键成果**：500 多个活跃 RAG 智能体；Syntia 是 Syntegon 唯一在其数据治理与劳资委员会（Works Council）框架下获得批准的 AI 平台

## 关于 Syntegon {#about-syntegon}

[Syntegon](https://www.syntegon.com/) 是领先的全球科技公司，也是制药、生物技术与食品行业的战略性全生命周期合作伙伴。总部位于德国斯图加特，在 20 多个国家的 49 个地点雇用 7,300 名员工。凭借 160 余年的行业经验，Syntegon 提供帮助人们生活得更好、更健康，并信赖他们每天所依赖产品的解决方案。

## 挑战：负责任地扩展 AI {#the-challenge-scaling-ai-responsibly}

Syntegon 需要在保持严格的数据治理、合规以及对 AI 模型和数据源完全控制的前提下，在全球多地点的工程组织中扩展 AI 的可及性。其领导层设定了一个目标：让每位员工都能获得企业级的 AI 能力，同时不牺牲安全性与合规性。

Syntegon 发现公共 SaaS AI 工具在数据驻留与知识产权暴露方面带来了不可接受的风险。该公司还发现商业 SaaS 工具存在以下问题：

- 对数据驻留的控制太少，
- 无法安全地集成专有内部数据源，
- 模型选择有限，以及
- 没有与 Syntegon 身份管理体系对齐的企业级基于角色的访问。

鉴于 AI 对公司未来的战略重要性，厂商锁定也是一个重大顾虑。

Syntegon 不可让步的要求包括：

- 部署在 Syntegon 自主掌控的云基础设施上（AWS，欧盟区域）
- 与 Microsoft Entra ID 的 SSO，以及通过 IAM 实现的基于角色的访问
- 通过统一网关（LiteLLM）支持多个 LLM 提供方（Azure OpenAI 与 AWS Bedrock）
- 一条符合当地法规的、包含劳资委员会与数据保护官（DPO）审批的流程
- 一套每位员工都必须完成的结构化 AI 素养培训计划，涵盖 AI 的战略价值以及负责任使用的边界

## 解决方案：部署在 AWS 上的 Syntia {#the-solution-syntia-on-aws}

Open WebUI 开放的架构、宽松的许可证以及面向企业的功能，让 Syntegon 无需定制代码库就能快速部署一个完全自托管、面向企业加固的 AI 平台。这些功能包括 RAG、Model Context Protocol（MCP）、SSO、多模型支持以及可扩展的插件框架。

LiteLLM 起了决定性作用。作为统一且成本可控的网关接入后，它在 Azure OpenAI、AWS Bedrock 以及未来的 AI 模型之间路由流量。Open WebUI 的可配置性也让 Syntegon 的安全团队能够实施严格的治理策略，包括禁用代码执行和拦截未授权的 webhook。

- **计算与编排**：AWS Fargate 上的 Amazon EKS（托管 Kubernetes）
- **存储与数据库**：Amazon Aurora（兼容 PostgreSQL），并启用 pgvector 扩展用于 RAG 嵌入；AWS EFS 为各 Pod 提供持久共享存储；每日 AWS RDS 快照
- **网络**：所有应用工作负载运行在 AWS VPC 的私有子网中，Pod 不接受来自互联网的直连入站流量
- **密钥管理**：所有敏感凭据保存在 AWS Secrets Manager 中，静态加密使用 AWS KMS
- **CI/CD**：基于 GitOps 的部署，使用 Terraform 管理基础设施即代码，Kubernetes 清单在 Git 中管理。计划中的更新会先在预发布环境测试，并配有成文的回滚方案。
- **日志与监控**：使用 OpenTelemetry Collector 收集链路与指标，Prometheus 存储指标，Grafana 仪表板用于可视化与告警，AWS SNS 发送邮件告警，LiteLLM 仪表板展示各模型的使用量与成本
- **安全控制**：通过身份提供方实现 MFA、设备合规、按群组划分的基于角色的访问、强制的数据驻留、内容审核与护栏、向 SIEM 导出审计记录以及出口限制

### 模型与数据处理 {#models-and-data-handling}

所有模型路由都经由部署在 Syntegon Kubernetes 集群内的 LiteLLM 网关完成。

- **Azure OpenAI**：GPT-5 用于高质量任务；GPT-5-mini 作为兼顾成本与大批量任务的默认模型；GPT-4.1 用于复杂推理；GPT-5.4 与 GPT-5.1；以及 GPT 1.5 用于图像生成
- **AWS Bedrock**：Claude Sonnet 4.5 与 4.6 用于高级推理与长上下文；Pixtral Large 25.02 用于视觉与文本；以及开源的 gpt-oss-120b

GPT-5-mini 是每位用户的默认模型，用户也可以从完整目录中选择其他模型。对成本敏感或大批量的任务会路由到 GPT-5-mini 或 gpt-oss-120b；高敏感度或复杂推理任务则可使用 Claude Sonnet 或 GPT-5。

RAG 使用 Azure OpenAI 的 text-embedding-3-large 配合 Aurora 上的 pgvector，Syntegon 看重它在多 Pod 环境下的可靠性。来源包括：

- 上传到 Syntia Workspace 的内部知识库，
- 通过 Microsoft Graph API 接入的 SharePoint 文档库，
- 通过 Atlassian 集成接入的 Confluence 页面。

Syntia 可处理 PDF、Office 文件、CSV、Markdown、HTML、JSON、图片和音频。OCR 与 Azure Document Intelligence 可从复杂文档中提取内容。

敏感数据通过四种方式加以保护：

- Azure AI Content Safety 会过滤所有 Azure 模型的输入与输出，AWS Bedrock Guardrails 则对 AWS 模型施加等效的过滤。
- 管理员聊天访问与管理员导出被禁用，以保护用户隐私。
- 直接注册被禁用。用户只能通过 Entra ID SSO 登录，并通过 Syntegon Identity Manager 完成开通。
- 每日备份均经过静态加密。

## 推广与赋能 {#adoption-and-enablement}

![Syntia 模型选择器，显示 GPT、Claude 以及其他可用模型。](/images/enterprise/customers/syntegon/open-webui.png)

Syntia 于 2025 年 12 月在生产环境上线，访问权限通过 Azure Service Group 开通，此后一直迭代更新。符合条件地区的员工可以通过 Syntegon Identity Manager 自行完成开通。

Syntegon 通过以下方式推动采用：

- **培训与文档**：提供专门的 Syntia 培训材料与在线学习模块，并以 Confluence 和 SharePoint 作为 Syntia 文档的唯一事实来源，涵盖架构、配置、安全与推广指南。
- **AI Hub & Spoke 研讨会**：由一个中心枢纽团队负责共享的 AI 基础设施、治理、经批准的工具和可复用组件，各部门则作为辐条把这一基础应用到自己的问题上。
- **产品委员会会议**：用于收集反馈、确定功能优先级并同步进展。由 AI Innovation Hub 统筹这些会议、场景创意以及跨部门的路线图治理。
- **支持与社区**：办公时间（office hours）、各职能团队的赋能活动，以及专门的 AI Hub 社群。

Syntia 的使用范围涵盖工程与研发、运营与制造、项目管理、销售、市场与客户体验、财务与人力资源，以及数字化转型。它通过 Azure Speech 多语言神经模型支持德语、英语等多种语言。LiteLLM 虚拟 API key 让工程团队可以在 Syntia 的模型基础设施上构建自己的 AI 应用。

## 成果 {#results}

> “我们从 AI 试验走到了实实在在的生产力提升——上线最初几周就有超过 1,000 名用户，而不是几个季度之后。Open WebUI 让我们得以规模化地落地用例，同时对成本与合规保持完全可见。”
>
> —— Syntegon 数字技术应用总监 Matti Maier

Syntegon 报告了以下成果：

- **安全与合规**：Syntia 是 Syntegon 唯一在其数据治理与劳资委员会框架下获得批准的 AI 平台。它具备两层内容过滤（Azure AI Content Safety 与 AWS Bedrock Guardrails）、通过 OpenTelemetry 与 Grafana 实现的完整审计轨迹，以及满足其备份与恢复 SLA 的每日快照。
- **企业知识**：500 多个活跃 RAG 智能体基于 Syntegon 产品文档、SharePoint 与 Confluence 给出具备上下文的答案。
- **生态集成**：Syntia 是 Syntegon 唯一在一个界面中原生集成 SharePoint、Confluence、Jira、Web 搜索、图像生成与文档 RAG 的企业 AI 平台，从而免去了使用多个彼此割裂的工具。
- **模型广度与成本效率**：单一界面中提供横跨 Azure 与 AWS Bedrock 的 8 个以上模型，日常任务走 GPT-5-mini，高端模型则留给复杂工作。
- **平台可靠性**：Syntia 运行在生产级、可自动扩缩容的 Kubernetes 集群上，可用性目标为 99.9% 以上。计划内维护均有完整的回滚方案，且没有记录到非计划内的停机事件。

> “使用 Open WebUI 最大的收获是让每一个 LLM 都集中在一处。我们的团队可以随时在模型之间切换，用于推理、编码或基于 RAG 的检索——一个界面、充分的灵活性，不必在多套工具和账号之间来回切换。”
>
> —— Syntegon 数字技术应用总监 Matti Maier

## 主要使用场景 {#top-use-cases}

Syntegon 强调的这些使用场景与收益：

- **触手可及的企业知识**：500 多个 RAG 智能体直接从产品文档、SharePoint 和 Confluence 中回答问题，无需手动检索
- **开发者生产力**：集成式代码辅助与评审加快了交付周期并提升了代码质量
- **客户与现场服务**：AI 辅助的简报撰写让服务沟通更快、更一致
- **视觉内容生成**：按需生成与编辑技术插图和营销素材的图像，减少对外依赖并缩短周转时间
- **规模化敏捷**：Confluence 集成支持迭代计划、文档编写与项目跟踪

## Syntegon 为何选择 Open WebUI {#why-syntegon-chose-open-webui}

- **开放且自托管**：开放的架构与宽松的许可证，完全自托管部署且无需定制代码库
- **面向企业的功能**：RAG、MCP、SSO、多模型支持以及可扩展的插件框架
- **统一模型网关**：LiteLLM 集成，在 Azure OpenAI、AWS Bedrock 与未来模型之间路由，Syntegon 称其具有决定性意义
- **可配置的治理**：安全团队可以实施严格策略，例如禁用代码执行和拦截未授权的 webhook

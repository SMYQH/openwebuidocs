# Public Storage 使用 Open WebUI 搭建安全 AI 平台，由内部推广负责人带动各部门使用 {#public-storage-scales-a-secure-champion-driven-ai-platform-across-every-corporate-function-with-open-webui}

## 概述 {#overview}

:::info
Public Storage 在 GCP 上使用 **Open WebUI** 部署了安全、私有的生成式 AI 平台，由**内部推广负责人带头推广**。平台在 **30 天内达到约 50% 的活跃使用率**，一项关键运营流程的耗时缩短了**超过 80%**。

### 一览 {#at-a-glance}

- **用户数**：5,000-10,000 名员工
- **地区**：美国（强制执行数据驻留）
- **行业**：房地产
- **部署**：GCP（容器化、私有网络）
- **模型**：Anthropic Claude（主要）、OpenAI GPT（高用量）、Llama、Gemma（开放权重）

- **采用率**：第一个月约 50% 活跃使用率

## 关于 Public Storage {#about-public-storage}

[Public Storage](https://www.publicstorage.com/) 是一家财富 500 强自助仓储房地产投资信托基金，在美国运营 3,000 多处设施。公司拥有数百万客户，数千名员工分布在办公室、呼叫中心和现场运营团队，并管理着全球规模最大的房地产资产组合之一。以这样的运营规模，统一提供受管控的 AI 访问是一项竞争优势。

## 挑战：在企业范围内安全地扩展 AI {#the-challenge-scaling-ai-safely-across-the-enterprise}

随着生成式 AI 工具普及，Public Storage 看到了机遇和风险。各团队开始自行尝试 AI，零散地订阅和使用服务，缺少统一管理。

领导层的目标是提供**安全的集中式 AI 平台**，提高全公司的 AI 素养，发掘有价值的业务场景，并让提效成果可以复用，同时保证数据安全和合规。

**关键需求**

- **私有部署**：在企业 GCP 环境内
- **访问限制**：仅限于企业防火墙后的已认证员工
- **SSO 集成**：与现有身份提供商 **Okta** 集成
- **模型灵活性**：无供应商或单一 LLM 锁定
- **完整审计跟踪**、DLP 政策和 PII 脱敏
- **基于角色的访问控制**：按群组划分

基于 SaaS 的 AI 工具提供了便利性，但缺乏 Public Storage 所需的隐私控制、网络限制和模型灵活性。

## 解决方案：GCP 上的 Open WebUI {#the-solution-open-webui-on-gcp}

选择 Open WebUI 是因为其**可扩展的基础**：开放的架构允许 Public Storage 从基本的聊天界面演变为安全的多模型内部 AI 平台。它支持快速迭代、广泛的模型选择和企业治理，同时保持完全私有。

**架构亮点**

- **计算/编排**：GCP 上的容器化工作负载，根据内部需求自动扩展
- **存储/数据库**：托管 PostgreSQL 和安全对象存储（GCP 原生）
- **网络**：采用私有网络，仅允许企业防火墙内已通过身份验证的员工访问；为开放权重 LLM 的 API 提供私有端点
- **CI/CD**：用于受控 Open WebUI 升级的自动化管道
- **日志/监控**：通过 GCP 原生工具和 **Langfuse** 集中记录日志并展示用量，以观测 LLM 的运行情况
- **安全控制**：通过 IdP 实施 MFA，按群组实施 RBAC，强制执行数据驻留要求；检测到 PII 时进行脱敏、中断处理并通知用户；实施内容审核、向 SIEM 导出审计记录、执行 DLP 策略并限制出站流量

> "我们的目标不仅是部署 AI，而是负责任地扩展它。Open WebUI 允许我们从业务中众包高价值的使用案例，同时保持所需的治理。" — Public Storage 首席技术官

## 模型和数据处理 {#models--data-handling}

Public Storage 采用**多模型策略**以平衡能力、隐私和成本：

- **主要**：Anthropic Claude（零数据保留）
- **高用量**：OpenAI GPT 模型（零数据保留）
- **开放权重**：在自有基础设施上使用 Llama 和 Gemma 处理私有工作负载
- **RAG**：默认 Sentence Transformers 用于嵌入，持续优化检索性能
- **PII 处理**：自定义过滤器在任何敏感数据到达模型前，**移除 PII、停止处理并通知用户**。它不只是静默脱敏，还会主动中断处理

## 推广与培训 {#adoption--enablement}

Public Storage 按计划由内部推广负责人带头推广。公司先指定推广负责人开展**为期两周的试点**，随后扩大覆盖范围，在 30 天内向全公司开放。

培训侧重**各岗位的实际使用场景**，而非抽象的 AI 知识。团队为早期用户举办了 1.5 小时的“PS.AI 入门培训”，向各部门分享适合其职责的实例和最佳实践。

在第一个月内：

- 完成入门流程的用户中，**约 50%** 活跃使用该平台
- 随着团队**与同行分享成功的工作流**，使用量继续增长
- 用户覆盖**所有企业职能部门**，包括 HR、市场营销、财务、法律、呼叫中心、运营、销售/收购、IT 和风险管理

> “不仅 IT 部门，业务部门也提出了实际应用场景，确实节省了运营时间。这加快了推广，也带来了实实在在的成果。” — Public Storage 数字技术副总裁

## 成果：生产力、采用和治理 {#results-productivity-adoption-and-governance}

![Public Storage 内部 AI 平台的手机截图，该平台由 Open WebUI 提供支持。](/images/enterprise/customers/public-storage/open-webui.png)

### 01. 操作时间节省 {#01-operational-time-savings}

整个组织的团队报告了显著的生产力提升。一个例子：区域经理**将四小时的周预订审查流程减少到约 40 分钟**，减少了超过 80%。

### 02. 跨职能部门采用 {#02-cross-functional-adoption}

**第一个月约 50% 的活跃使用率**，采用由员工构建自定义模型和角色、跨部门共享业务案例机会而自发推动。

### 03. 企业治理 {#03-enterprise-governance}

- **完全私有部署**，数据必须留在 GCP 环境内
- 内置 PII 脱敏、内容审核措施、DLP 策略和审计导出，**减少合规操作负担**
- RBAC、MFA 和出站限制在整个平台提供**分层安全**

## 主要使用案例 {#top-use-cases}

- **预订分析**：总结报告和预订详情
- **现场沟通**：起草指导、跟进和内部沟通
- **政策检索**：知识检索覆盖内部政策、程序和方案
- **跨部门代理**：试验工具特定的 AI 代理并在部门间共享工作流（HR、法律、呼叫中心、财务等）

## 为什么 Public Storage 选择 Open WebUI {#why-public-storage-chose-open-webui}

Open WebUI 能随 Public Storage 的需求扩展，因此脱颖而出：

- **可扩展的基础**：从聊天演变为完整的内部 AI 平台
- **多模型选择**：支持商业模型和开放权重模型，不受供应商锁定
- **企业级治理**：PII 脱敏、审计跟踪、RBAC、DLP
- **快速部署**：IT 开销最少
- **开放架构**：支持迭代，无供应商依赖

该平台使每个企业职能部门能够安全、大规模地发现和共享 AI 驱动的生产力提升。

# Open WebUI 与 Onyx {#open-webui--onyx}

*最后更新时间：2026 年 8 月*

[Onyx](https://onyx.app/)（前身为 Danswer）专注于让 AI 检索组织在 Slack、Google Drive、Confluence、Jira、GitHub 等数十种工具中的内部知识，同时遵守来源系统的访问权限。这尤其适合知识分散在不同工具、又需要在搜索中保持访问控制的团队。

发现错误或过时的信息？[请告诉我们](https://github.com/open-webui/docs/issues)。

[GitHub](https://github.com/onyx-dot-app/onyx) · [源码可用](https://github.com/onyx-dot-app/onyx/blob/main/LICENSE)（MIT 核心 + Onyx 企业许可证用于 `ee/` 目录） · [自托管条款](https://onyx.app/legal/self-host)

---

## Onyx 的优势 {#what-onyx-does-well}

- **企业连接器**，[按 Onyx 的统计有 40 多个](https://docs.onyx.app/admins/connectors/overview)，为 Slack、Google Drive、Confluence、Jira、GitHub、Notion 等提供原生集成
- **自动同步**，无需手动重新导入即可更新已连接的数据源
- **权限感知检索**，在返回搜索结果时尊重源系统访问控制
- **企业搜索**，为跨组织内部知识搜索而专门设计
- **多种访问方式**，包括 Web 应用、Slack 机器人、Discord 机器人、Chrome 扩展和 CLI
- **托管云选项**，适合不想自托管的团队
- **带有操作的自定义智能体**，用于构建可以跨连接的工具采取行动的 AI 助手
- **活跃开发**，版本发布频繁，社区反应迅速

---

## Open WebUI 的优势 {#what-open-webui-does-well}

- **完整的 Agentic 平台**，模型可自行调用[内置工具](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)、[MCP](/features/extensibility/mcp) 服务器、[子智能体](/features/chat-conversations/chat-features/subagents)、[定时器](/features/chat-conversations/chat-features/timers) 和 [自动化](/features/chat-conversations/chat-features/automations)，用于委派和定时任务
- **几乎可自定义一切**，从按模型的提示词、工具、知识和参数，到可在管道任何位置改变行为的[过滤器、管道、动作和事件函数](/features/extensibility/plugin/functions)，再加上主题、横幅和按组权限
- **完整 AI 平台**，包括聊天、笔记、频道、自动化、Open Terminal、语音/视频通话和图像生成
- **聊天中的云存储**，支持 Google Drive、OneDrive（个人版和企业版）和 SharePoint 文件选择器
- **在任何地方部署**，在您自己的基础设施上，如果需要可完全隔离
- **免费社区版**，包含无限用户、OIDC/OAuth SSO、LDAP、RBAC 和 SCIM 2.0
- **任何模型、任何提供商**，包括 Ollama、OpenAI、Anthropic、Google、Azure、Bedrock 以及任何 OpenAI 兼容 API
- **知识库与 RAG**，拥有 13 个向量数据库、8 个内容提取引擎以及混合 BM25 + 向量搜索和交叉编码器重排序

## 许可证与付费层级 {#licensing-and-paid-tiers}

两个项目都可以免费自托管，也都销售付费层级。它们把不同能力放在不同层级中，所以实际问题在于：哪一套功能与您计划中的部署相符。

**Open WebUI** 以 [Open WebUI 许可证](https://github.com/open-webui/open-webui/blob/main/LICENSE) 源码形式提供。这是一个 BSD-3 条款许可证，外加一条补充条款：一旦某个部署在滚动 30 天内超过 50 个用户，您不得移除或替换 Open WebUI 品牌标识，除非您持有企业许可证。

**Onyx** 以 MIT 许可证授权其社区版核心，涵盖聊天、RAG、智能体和操作。该授权并非覆盖整个仓库：Onyx 自己的 [LICENSE](https://github.com/onyx-dot-app/onyx/blob/main/LICENSE) 将 `ee` 目录下的所有内容排除在外，改为适用 Onyx 企业许可证。单就这一点而言，MIT 比我们的许可证更宽松，如果您打算重新分发或 fork 核心代码，这一点就很重要。

### 各免费自托管版本包含的内容 {#what-each-free-self-hosted-edition-includes}

这是 Open WebUI 免费版与 Onyx 社区版（即承载 MIT 许可证的那一部分）的对比。Onyx 一列依据其 [Enterprise Edition](https://docs.onyx.app/deployment/miscellaneous/enterprise_edition) 与[访问控制](https://docs.onyx.app/security/architecture/access_controls)文档，以及其自身 `license_enforcement_config.py` 中的分层门控。Onyx 的付费层级既可自托管也可用于其云服务，因此下文的 “Business” 和 “Enterprise” 仍然可以指自托管。

| 能力 | Open WebUI（免费版） | Onyx 社区版（免费版） |
| :--- | :--- | :--- |
| OIDC / OAuth 单点登录 | 包含 | 可启用一个 SSO 提供商；多个需要 Business 或 Enterprise |
| SAML 单点登录 | 由[受信任请求头代理](/features/authentication-access/auth/sso#trusted-header)处理 SAML | 可启用一个 SAML 提供商；与其他 SSO 提供商同时使用需 Business 或 Enterprise |
| LDAP / Active Directory | 包含 | 未记录 |
| 用户组和基于角色的访问控制 | 包含 | Business 层级及以上 |
| 按资源授权（用户和组） | 包含 | Business 层级及以上 |
| SCIM 2.0 用户预配 | 包含 | Enterprise 层级 |
| 审计日志 | 包含 | 记录结构化安全事件；导出日志包需要 Enterprise |
| 付费前的用户数量上限 | 无 | 无 |
| 让不同团队访问不同文档 | 创建独立知识库，分别授权给指定的用户或组 | 按组限制访问需 Business 或 Enterprise |
| 对**同一个**知识库中的不同文件设置不同权限 | 访问权限以整个知识库为单位生效 | 按源文档的权限检索需 Business 或 Enterprise |
| 自动同步 Slack、Drive 或 Confluence 中的权限 | 目前不是 Open WebUI 的功能 | Business 或 Enterprise |
| 移除产品品牌标识 | 50 个用户以内；超过后需企业许可证 | Business 可自定义标志和名称；Enterprise 支持完整白标 |
| 专属支持和 SLA | [企业许可证](/enterprise/support) | Enterprise Edition |
| 功能请求的优先级 | 企业许可证 | Enterprise Edition |

Open WebUI 一列中所有标为“包含”的项目都不需要许可证密钥、席位数或付费计划。它们都是可配置项。

有两行值得留意，因为其中的区别很容易被混为一谈。Open WebUI 通过把不同文档集放入不同知识库、并将每个知识库授权给相应的组，来让不同团队访问不同的文档集。Onyx 的付费版本在企业搜索上走得更深：它们可以从 Slack、Drive 和 Confluence 等工具镜像源系统权限，并在检索过程中强制执行。如果您这些文档在源系统中已经具有复杂权限，这确实是 Onyx 的强项。

专属支持和路线图优先级在两边都是付费的，这也是两个项目的资金来源，双方都不加掩饰。

英文原文记录了 2026 年 7 月的报价：[Onyx Cloud](https://onyx.app/pricing) 的 Business 套餐为每位用户每月 20 美元，包含基于角色的访问控制和权限继承；Enterprise 套餐需要询价。云端套餐页面将 Google OAuth 列入 Business，将 OIDC/SAML 单点登录列入 Enterprise，和上面的自托管功能对照不同。SCIM 和出站 webhook 的云端可用性请向 Onyx 确认。

因此结论如下。如果您在自托管并需要在免费版中获得托管身份管理，Open WebUI 会为任意数量的用户提供它。如果您需要从 Slack 或 Drive 镜像单个文档的权限，那么 Onyx 的付费版本正是为此设计的。如果您打算 fork 或重新分发，Onyx 的核心采用的是更宽松的许可证。

:::note 决定之前请两者都核对

定价和套餐会变化。历史报价来自对应时间的条款；功能对照按当前 Onyx 文档核对。做决定前请查阅 [Onyx 的定价](https://onyx.app/pricing)和我们的[许可证](https://github.com/open-webui/open-webui/blob/main/LICENSE)，不要只依赖任一方的摘要。

:::

## 一览表 {#at-a-glance}

| | Open WebUI | Onyx |
| :--- | :--- | :--- |
| **主要焦点** | 通用 AI 平台 | 企业搜索和知识发现 |
| **知识方法** | 文档上传、知识库、13 个向量数据库、8 个提取引擎 | 40 多个企业连接器，自动同步 |
| **权限处理** | 组、角色和按资源访问授权，均在免费版中提供 | 付费层级上从源系统镜像的权限感知检索 |
| **多提供商** | 任何 OpenAI 兼容 API + Ollama | 多个 LLM 提供商支持 |

| **许可证** | Open WebUI 许可证（BSD-3，另加一条超过 50 用户的品牌标识条款） | 社区版核心采用 MIT；企业功能适用单独条款，参见[自托管条款](https://onyx.app/legal/self-host) |

## 何时选择各个平台 {#when-to-use-each}

**选择 Onyx**：如果你希望让 AI 使用组织已有工具中的知识。团队知识分散在 Slack、Confluence、Jira、Google Drive 或 GitHub 时，可以使用 Onyx 的 40 多个连接器；支持同步源权限的连接器可以按权限检索。

其中两个方面值得说得更精确，因为这些正是 Onyx 有专门设计的领域：

- **持续同步到知识库。** Open WebUI 支持在聊天时从云存储选取文件：用户可以直接添加 [Google Drive](/features/chat-conversations/rag#google-drive-integration)、OneDrive 和 SharePoint 中的文件。知识库可以通过上传、目录同步或 API 更新；[oikb](/ecosystem/knowledge-base-sync) 还可以按计划同步代码仓库、对象存储桶和 wiki。Onyx 把持续的连接器同步内置在产品中。
- **从源系统继承权限。** Open WebUI 按知识库授权，需要将不同团队可读的内容分别放进不同的知识库。Onyx 的 Business 和 Enterprise 可同步源系统的访问控制列表，并在检索时按列表授权。若要索引权限复杂的大型共享 Drive，这项区别很重要。

如果其中一项是硬性要求，可以重点考虑 Onyx。连接器的索引更新可以定期运行；同步源权限则是 [Business 和 Enterprise 的功能](https://docs.onyx.app/deployment/miscellaneous/enterprise_edition)，不能用免费社区版的权限功能来作对照。

**选择 Open WebUI**：如果你需要通用 AI 平台，支持聊天、知识库、团队协作、Python 扩展和接入不同模型提供商。Open WebUI 免费社区版包含 SSO、LDAP、RBAC、SCIM 2.0 和审计日志，且不限制用户数量，适合需要集中管理身份、不想按席位付费的组织。

**两者解决的问题不同。** Onyx 擅长企业搜索和连接已有工具；Open WebUI 更适合作为通用 AI 平台。组织也可以搭配使用两者。

## 常见问题 {#frequently-asked-questions}

**Onyx 和 Open WebUI 有什么区别？**
Onyx 侧重企业搜索，提供 40 多个连接器，并可按源系统权限检索。Open WebUI 更通用，提供聊天、知识库、团队协作和扩展功能。

**Onyx 是开源的吗？**
部分开源。Onyx 的社区版核心采用 MIT 许可证，`ee` 目录里的内容适用单独的企业条款。其他[自托管条款](https://onyx.app/legal/self-host)也可能适用。许可证与功能套餐是两回事：MIT 覆盖核心，而多个单点登录提供商、按组授权及源权限同步需要 Onyx 付费套餐。就再分发而言，核心代码的 MIT 许可比 Open WebUI 许可证宽松。

**SSO 和 RBAC 如何比较？**
Open WebUI 免费版包含 OIDC 和 OAuth 单点登录、LDAP、RBAC、SCIM 2.0 用户预配和审计日志，用户数量不限，且不需要许可证密钥。Onyx 自托管社区版可启用一个 SSO 提供商；[自定义用户组、按组授权和同时使用多个 SSO 提供商](https://docs.onyx.app/deployment/miscellaneous/enterprise_edition)需要 Business 或 Enterprise。Onyx Cloud 的功能以其现行套餐为准。

**Onyx 是免费的吗？**
社区版可免费自托管。其他[自托管条款](https://onyx.app/legal/self-host)可能适用。需要托管服务或额外功能的团队可考虑 Onyx Cloud 和企业套餐。

**我可以同时使用 Onyx 和 Open WebUI 吗？**
是的。它们解决不同的问题。Onyx 将 AI 连接到您现有的企业工具。Open WebUI 还内置了知识管理、团队功能和扩展性。

**哪个更适合企业 AI 部署？**
这取决于您的需求。如果您的优先级是使用权限感知检索跨内部工具搜索，Onyx 就是为此而设计的。如果您需要更多的通用 AI 平台，可以在您自己的基础设施上部署，并在免费版本中包含 SSO、RBAC 和 SCIM，那就是 Open WebUI 更适合的地方。

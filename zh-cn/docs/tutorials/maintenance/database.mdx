如果您需要将 **Open WebUI** 的数据（例如聊天历史记录、配置等）从一台服务器迁移到另一台，或者备份以供将来使用，可以通过导出和导入数据库来实现。本指南假设您使用 Open WebUI 内置的 SQLite 数据库（而非 PostgreSQL）。复制 `webui.db` 只会迁移存储在数据库中的全部内容（账号、聊天、设置、文件和知识库记录），但不包括文件本身：位于 `/app/backend/data/uploads` 下的上传文件和位于 `/app/backend/data/vector_db` 下的向量库会留在原处，因此引用了这些文件的聊天会指向不存在的对象。要完成完整迁移，请复制整个 `/app/backend/data` 目录（参见[备份指南](/tutorials/maintenance/backups)）并保持相同的 `WEBUI_SECRET_KEY`；Docker 镜像会把自动生成的密钥写入 `/app/backend/.webui_secret_key`，位于该目录之外。如果使用 PGVector 等外部向量数据库，向量则存放在那里，而不是存放在 `vector_db` 中。

按照以下步骤导出和导入 `webui.db` 文件，该文件包含您的数据库。

---

### 导出数据库 {#exporting-database}

:::note

请按下文说明自行复制数据库文件。**管理设置 > 数据库**中的 **数据库** 下载不会包含 `webui.db-wal`，因此可能缺少最近的数据。

:::

从当前 Open WebUI 实例中导出数据库：

1. **复制数据库前先停止 Open WebUI**：
   Open WebUI 默认以预写日志（WAL）模式运行 SQLite，因此最近已提交的更改保存在 `webui.db` 旁边的 `webui.db-wal` 中。请先停止容器，这样导出期间就不会有写入操作：
   ``` bash
   docker stop open-webui
   ```

2. **把待处理的更改写入 `webui.db`**：
   停止容器后，这些更改仍留在 `webui.db-wal` 中，因此单独复制 `webui.db` 可能会丢失它们。在容器停止的状态下，使用同一个镜像执行一次 checkpoint：
   ``` bash
   docker run --rm --volumes-from open-webui --entrypoint python3 "$(docker inspect -f '{{.Config.Image}}' open-webui)" -c "import sqlite3; db = sqlite3.connect('/app/backend/data/webui.db'); db.execute('PRAGMA wal_checkpoint(TRUNCATE)'); db.close()"
   ```

3. **使用 `docker cp` 复制数据库文件**：
   `webui.db` 文件位于容器内的 `/app/backend/data` 目录中。运行以下命令将其复制到本地机器：
   ``` bash
   docker cp open-webui:/app/backend/data/webui.db ./webui.db
   ```

4. **在源服务器上重新启动 Open WebUI**：
   ``` bash
   docker start open-webui
   ```

5. **将导出的文件传输到新服务器**：
   您可以使用 **FileZilla** 或任何其他文件传输工具将 `webui.db` 文件移动到新服务器。

   :::info
   推荐使用 FileZilla，它在将文件传输到新服务器时操作简便。
   :::

---

### 导入数据库 {#importing-database}

将 `webui.db` 文件移动到新服务器后，按照以下步骤操作：

1. **在新服务器上安装并运行 Open WebUI**：
   使用 Docker 容器安装并运行 Open WebUI。请按照[🚀 入门指南](/getting-started)中的说明安装和启动 Open WebUI 容器。容器启动后，在执行导入步骤之前先停止它。
   ``` bash
   docker stop open-webui
   ```

2. **删除目标端的 SQLite 附属文件**：
   如果目标容器已经生成了 `webui.db-wal` 或 `webui.db-shm`，请在替换 `webui.db` 之前删除它们。它们属于目标端原有的数据库状态，不能与导入的数据库混用。
   ``` bash
   docker run --rm --volumes-from open-webui --entrypoint rm "$(docker inspect -f '{{.Config.Image}}' open-webui)" -f /app/backend/data/webui.db-wal /app/backend/data/webui.db-shm
   ```

3. **使用 `docker cp` 将数据库文件复制到容器中**：
   假设导出的 `webui.db` 文件在当前工作目录中，将其复制到容器：
   ``` bash
   docker cp ./webui.db open-webui:/app/backend/data/webui.db
   ```

4. **启动 Open WebUI 容器**：
   再次启动容器以使用导入的数据库。
   ``` bash
   docker start open-webui
   ```

   新服务器现在应该运行着带有您导入数据库的 Open WebUI。

---

### 注意事项 {#notes}

- 此导出/导入过程**仅适用于使用内置 SQLite 数据库（`webui.db`）的情况**。
- 如果您使用的是外部 PostgreSQL 数据库，此方法不适用，因为数据库是在容器外部管理的。对于 PostgreSQL，需要使用 PostgreSQL 专用工具和流程来备份和恢复数据库。
- 不要混用来自其它数据库副本的 `webui.db-wal` 或 `webui.db-shm` 文件。在目标端替换 `webui.db` 时，请先删除已有的附属文件，然后再启动 Open WebUI。
---

### 为什么这很重要 {#why-its-important}

以下情况特别适合使用此方法：

- 将 Open WebUI 数据迁移到新服务器或新机器。
- 在更新或修改之前创建数据备份。
- 在多台服务器上使用相同配置测试 Open WebUI。


通过以上步骤，您可以轻松管理 Open WebUI 的迁移或备份流程。请注意您使用的数据库格式，以确保兼容性。

---

``` bash

# Quick commands summary for export and import

# Export:
docker stop open-webui
docker run --rm --volumes-from open-webui --entrypoint python3 "$(docker inspect -f '{{.Config.Image}}' open-webui)" -c "import sqlite3; db = sqlite3.connect('/app/backend/data/webui.db'); db.execute('PRAGMA wal_checkpoint(TRUNCATE)'); db.close()"
docker cp open-webui:/app/backend/data/webui.db ./webui.db
docker start open-webui

# Stop container on the new server:
docker stop open-webui

# Import:
docker run --rm --volumes-from open-webui --entrypoint rm "$(docker inspect -f '{{.Config.Image}}' open-webui)" -f /app/backend/data/webui.db-wal /app/backend/data/webui.db-shm
docker cp ./webui.db open-webui:/app/backend/data/webui.db

# Start container:
docker start open-webui
```
